# AGENTS.md: yavs-clift

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-clift`.
The Cranelift tier of #481, on main behind the `clift` feature (not a default feature) and the compiled
tier of the release archives (user, 2026-10-28: one archive per platform); tuning rounds are paused. Measurements in
`docs/STATUS.md` "clift", decisions in `docs/decisions.md` "Cranelift tier" and its rounds.

## 1. Purpose and boundaries

- A second code generator for the compiled-code contract of `yavs-llvm`: the same function
  signature (`fn(env, regs, mem, pc) -> u32` on the interpreter frame's registers), the same
  frame view (`yavs_llvm::rt::Mem`, `TierFrame`), the same callbacks (`yavs_rt_step`,
  `yavs_rt_signal`, `yavs_rt_host`), the same side exits. Cranelift is a Cargo dependency, so a
  release binary gets a compiled tier without an LLVM install.
- `compile` (`yavs run --tier=clift`) translates every non-elaboration function before time 0.
- `First` is the Cranelift `yavs_llvm::Generator` of `yavs-llvm`'s `AutoTier` (the policy of `--tier=auto`: budget, payback, bands, trials): the only generator of `--tier=clift-auto` (a yavs built with the `clift` feature alone), the first level of `--tier=auto3` (both features: Cranelift for warm functions, LLVM O2 for those that stay hot).
- Everything is behind the `clift` feature (off by default); `yavs --features clift`.
- Depends on `yavs-llvm` (without its `llvm` feature) for `rt.rs`, which holds everything the two
  code generators share, `yavs-interp`, `yavs-ir`.

## 2. Map

| File | Responsibility |
|---|---|
| `src/lower.rs` | `Jit` (a Cranelift JIT module with the runtime callbacks as symbols), `gen_func` (IR to Cranelift IR per function: register cache per block, side exits, slow paths emitted after the body), `compile`; native-frame variants (`Jit::native_of`, `try_native`, `build`, `Gen::native_call`, `record_frame`) and the `Inl` inliner |
| `src/lib.rs` | `ClifTier`, `First` (the `Generator`) |
| `src/cache.rs` | The compiled-code cache: `set_cache`, `cache_stats`, `Kv` (the objects store of the work library as Cranelift's `CacheKvStore`), the list of compiled functions the policy probes |
| `tests/tier.rs` | The LLVM tier's tier-against-interpreter tests, run against this tier |

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| Registers stay in the frame's register array; a per-block cache of SSA values avoids reloads, and is dropped at every block start, join and callback, except as the next row says | Callbacks and the interpreter read and write the array | `src/lower.rs` |
| Frame mode, processes (round 7): the definitions of `quiet` instructions are deferred (`Gen::pend`, `fresh`, `settle`) and stored only where the interpreter or a callback can look at the frame: at a non-quiet instruction (`spill`), an exit (`leave_at`: the deferred registers live at its pc, `regs::Live`), the block of a slow path (`snaps`, stored before the step), a block start a jump leads to; registers the interpreter preloads are never stored, registers live over more than `MAX_SPAN` instructions are stored at the definition. A slow path's join takes the fast path's definitions as block parameters (`join_with`; the slow path loads them after the step), so do the result of a direct native and of an in-place `ieee` native. A block start no jump leads to (the entry after a call) takes the live values in hand as block parameters; the switch over the entries is made at the end (`dispatch`) and its stub loads them from the frame. In every frame-mode function the facts of `known` carry over such a block start (its only way in is the instruction before it) | LLVM's deferred stores (decisions "Tight compute loops"); a callback's result was stored and loaded again right after it, and every definition was a store | docs/decisions.md "Cranelift tier, round 7" |
| Copies of a process (`Program::copy_of`) whose Cranelift body and referenced functions and data are equal are one definition (`Jit::bodies`, key `compute_cache_key` plus the external names) | `--tier=clift-auto` defined 36 copies of the adder processes of `poc_arith_addw` where LLVM's twins share 4: 10 percent of the cycles | docs/decisions.md "Cranelift tier, round 7" |
| Slow paths (step the instruction in the interpreter) are emitted after the body and rejoin the fast path | Keeps the hot path straight; a stepped instruction may write any register | `src/lower.rs` |
| The kernel-facing instructions are lowered as the LLVM generator does (2026-10-24): `Inst::Edge` and the `rising_edge`/`falling_edge` natives (the kernel's resume key in `Mem::known`, else the event stamp, the codes and the last-value planes of the `TierSig` entry), `SigReadScalar` (codes, planes, or the bytes of an integer, enumeration or real signal), `SigRead` (up to 64 elements through `yavs_rt_codes`, more through `yavs_rt_planes`), `SigAttr` `'event`, the scalar logic assignment the interpreter fuses (`scalar_drives`: the fused `Alloc`/`Store`/`Index`/`LSet` are skipped, `Drive` calls `yavs_rt_drive_bit`), other single-element `Drive`s (`yavs_rt_drive`), `WaitOn` plus `Suspend` (`yavs_rt_wait`), a `WaitOn` that is not the last (`yavs_rt_wait_on`), the wait that names the same signals (`static_wait`, `yavs_rt_wait_same` at the `Stmt`), frame-mode `CallNative` of the natives `direct_native` allows (`yavs_rt_native` with `NATIVE_FRAME_MODE`); `TempRoot`, `NewFrame`, `Stmt`, `Deref`, `MemEq` and `Cat` go to `TierHost::signal` instead of the generic step. An access through the result of a `Deref` (known to be on the heap) tries the entry of `Mem::objs` (one load and compare) before `yavs_rt_host`; any other address of unknown space calls `yavs_rt_host` (next rows). None of this is in a native-frame variant except `SigReadScalar`, the table read, `SigRead`, and `Drive`/`DriveSlot` of one waveform element (`yavs_rt_drive_nat`: no frame view, the kernel's answer or nothing; where the view or the kernel has no answer the native frame is materialised, as the LLVM tier does since #730); another signal operation or a callback that needs a step makes the function frame-mode only | Without them a clocked process made 4800 signal callbacks and 960 steps per 1000 activations against 4 and 8 under LLVM, and ran twice as many instructions as the interpreter | `src/lower.rs` `impl Gen` "kernel-facing instructions" |
| Not lowered inline (stepped): calls (except to a function with a native variant), natives other than the `std_ulogic` tables, edges, the light `numeric_std` natives (`native::ieee_fast`; inline on their small path, `ieee_native`) and the `direct_native` ones, `New`, reports, `**`, `LEq`, `NewFill`, `PkgAlloc`, `SigLastValue`, `LogicOp` of `Resolve` and `to_x01z`, and signal operations other than those above | Same list as the LLVM tier minus `LayoutOf` (fused, row below) | `src/lower.rs` |
| Frame-mode code reaches an address whose space it does not know through `yavs_rt_host` (`Mem::find`: the object table, the temporary area, instance data, the frame, then the interpreter), as the reference lowering does (#634); the inline chain of tests (the frame, temporary area and instance data by the high half of the address, then the object table) stays in native-frame variants only. Spaces the generator knows (`Known`: the frame, the temporary area, instance data, constants, held objects, a heap object by its table entry) are inline in both; a guess (`Known::LikelyTemp`: a call's result and the words loaded from it; `LikelyHeap`: a pointer loaded from a variable's slot) is tested inline first in frame-mode code, the temporary area by its address tag and length, the heap guess by the object table, and the runtime is asked when it was wrong (#711) | The chain was 38 instructions and about 60 Cranelift instructions per access: 29 percent of the Cranelift instructions of fletcher's frame-mode code, 18 percent of the compile time, 20 percent of the instructions of poc_arith_addw's two hot processes; with the call the whole run is 1 to 2 percent below the inline chain on the clocked designs and 10 percent on `xor_types` (counters in the same instructions) | `src/lower.rs` `Gen::host`, docs/decisions.md "Cranelift tier, round 3" |
| `Generator::tree` (called by the policy before it compiles a root with the callees it chose) limits the variants a native build makes as dependencies to those functions (`Jit::allow`); other callees are called through `Mem::ntab` (a null entry materialises the frame) until they compile themselves. Without it `peek` of a verification library compiled 26 variants (`log`, `alert`, `check_value`...) in 112 ms of the 120 ms of its compile, none of them seen running | The policy leaves out callees that were never seen running (`left_out`); the Cranelift build did not know | `src/lib.rs` `First::tree`, `src/lower.rs` `Jit::native_of` |
| A `Call` of a function with a memo signature (`Program::memo_sig`, pure, cells equal to the arguments; not `CallProt`) from frame-mode code or a native frame calls `yavs_rt_memo` before the call (`TierHost::memo_probe`: a hit is the result in `out[0]`, a miss returns the report count in `out[1]`) and, on the normal return, `yavs_rt_memo_keep`; the argument cells go to a stack buffer of the caller (`Gen::native_call`). Same protocol as the LLVM lowering | Compiled callers did not ask the memo, so a design that calls pure functions with repeating arguments ran them again in compiled code (`pure_memo`: 0 hits against 435; the window generator 8 percent more instructions) | `src/lower.rs` `Gen::native_call`, `tests/pmemo.rs`, `perf.rs` `clift::pure_memo` |
| A Cranelift error (`define_function`: the verifier, on in debug builds) is a bug of the lowering: debug builds panic with the function's Cranelift IR (the compile thread's panic is re-raised when the tier stops), release builds leave the function interpreted with a note. `tests/verifier.rs` breaks every function on purpose (`BREAK`, debug builds only) | A function silently left interpreted hid a dominance bug in a release build until the verifier was switched on by hand | `src/lower.rs` `build`, `define_adapter` |
| `AutoTier` calls `NativeFlags::set` (`Runtime::native_flags`) after publishing an entry | The interpreter's fast loop asks only those flags; without it translated code is never entered | `src/auto.rs`, `yavs-interp` |
| `ClifTier` keeps `lean` per function (`yavs_llvm::regs::no_table`) and passes it to `rt::enter`; under `AutoTier` the shared `Entry` carries it. A lean process activation skips the object table's tags (`Mem::begin_lean`) | The host layers of a small clocked process, the same for both generators (#766) | docs/decisions.md "Compiled clocked RTL processes, round 11" |
| A function in `native_set` (`yavs_llvm::native`, the rule the LLVM generator uses) gets a second body `n<id>` (native-frame variant: registers and slots on the native stack, `(env, mem, depth, [up1, up2], cells...) -> i64`, the LLVM tier's calling convention); callers call it directly when it is in their module (Cranelift inlines the small ones) and through `Mem::ntab` otherwise (a cycle, a callee another generator compiled), a null entry being a materialised frame (`Call`, and `CallProt` with the shared-state flags of `Machine::call_prot`), so a call costs no interpreter frame. Anything that cannot finish (a failing check, a slow path, `Unreachable`) records the frame (`yavs_rt_deopt`: registers, slots, pc, temporary base, static link; it sets `Mem::ndeopt`, which every caller tests after the call, as the LLVM callers do) and every caller on the way records itself; the frame-mode root pushes them all (`yavs_rt_deopt_end` = `TierHost::materialise`) and returns `TIER_UNWIND`, so errors, call chains and the rest of the run are the interpreter's. An instruction without inline code runs through `yavs_rt_xstep` on a frame of the host's own (`xstep_wide`: heap, vector fills and compares, layouts, reports, `Cat`, `NewFrame`, `Fill`, `SlicePos`, `MemEq`), a typed or heap-pointing `TempRoot` through `yavs_rt_troot`, the end of a statement with recorded temporaries through `yavs_rt_endstmt` (the frame's `temp_base` is a cell a `NewFrame` raises), a `direct_native` native through `yavs_rt_native`, a `Deref` as in frame mode; a cold native or `Unreachable` leaves the frame (`deopt_here`). Every native frame registers its slots in `Mem::nslots[depth]` at entry, so a callee, a helper or an inline access reaches an address in a caller's frame (`Gen::host`: the own frame, the frames above the interpreter's top frame and below this one, then the object table) | The call protocol of the interpreter (frame push, two view refreshes, lookup, return) was 80% of the time of call-heavy code; the machinery is the LLVM tier's "compiled frames". Without the helpers a variant needed a function with no heap access, so the verification-library queue and pointer-table code (`CallProt` into `Deref`) stayed in frame mode: 139 million `CallProt` steps in a 35 s testbench run | `docs/decisions.md` "Compiled frames", `src/lower.rs` |
| Variants are published (`First::compile` reports `Compiled::native` and `call`, the variants built on the way as `extra`; `ClifTier` keeps its own tables) in `Mem::ntab`, so LLVM- and Cranelift-compiled callers call each other's variants, and a `c<id>` adapter (the LLVM tier's `CallFn`) serves the interpreter's calls (`Tier::call`). Nested functions take the static links as parameters (`AddrOf Up` reads them), a signal parameter takes two cells. `YAVS_CLIFT_NTAB=1` makes every call go through the table and `YAVS_MIXED=1` (`--tier=auto3`) has LLVM compile the functions of even id and Cranelift the others: the `yavs-mixed` difftest candidate and `tests/compiled_mixed.rs` | One convention for both generators was the gap list's first item; the hybrid was slower than Cranelift alone because LLVM callers could not call Cranelift variants | `src/lower.rs`, `crates/yavs/src/elab.rs` |
| Not in the variants: the LLVM generator's closed frames and held objects (`ObjRef`); a native frame's access to an address of a caller's frame goes through `yavs_rt_host`, where LLVM's inline code finds `Mem::nslots` itself. A function the Cranelift lowering cannot finish (`Gen::bad`: an instruction it can neither inline nor `xstep`) has no variant and its callers in `native_set` are not built as variants either | Each costs a lowering of its own (STATUS.md "clift" gap list) | `src/lower.rs` |
| Cranelift's `Inline` (`Context::inline`) inlines the small bodies (up to 150 Cranelift instructions, 2000 in all per caller) into their callers before compilation, except a body with a symbol (`symbol_value`: the inliner keeps the callee's name reference, #765); the alias regions of guest memory are shared between caller and callee (ids 2, 3), the registers of a native variant have their own (4) | The inliner merges regions by id; sharing the guest-memory region keeps stores and loads of caller and callee ordered | `src/lower.rs` `Inl` |
| Registers the interpreter starts a frame with (`rt::preloads`: defined once by a `Const`, `ConstF` or a non-`Up` `AddrOf`) are treated as known addresses at every block start (`base_known`); a frame-mode entry after them may find the register of a parameter's slot address unset (`Pre::lean`), so a load or store through it goes by the known frame offset, never by the register | Without it a recursive function read the caller's parameter after a merge with main (the interpreter leaves those registers zero) | `src/lower.rs` `gen_func` |
| The registers of a native-frame variant are Cranelift variables (`Gen::vars`, `ld`/`st`); the register array on the native stack is written only when the frame is recorded: `leave_at(pc)` stores the registers live there (`regs::Live`), the exit block stores the preloaded ones (`fixed`, `pre`). The interpreter's preloads (a constant defined once, a frame address) are made where they are used (`var_ld`), never read from a variable, and `Known` facts of them are restored after each instruction (`track` forgets a register after the definition of its neighbour). A closed frame (`native::closed_frame`) is not registered in `Mem::nslots` (length 0), zeroes and hands over only the bytes in use, and keeps slots read and written at one width as variables (`slot_vars`); held objects (`Known::Heap(Some(ObjRef))`) after a `Deref` carry across `Index`/`Move` and across blocks with a single way in (`ways`, `inherit`) | Without them `get` of the test runner's pointer tables spent its instructions on a frame prologue, a store per definition and a lookup per access; the window generator under `--tier=clift` went from 389.5 G to 275.1 G instructions | `docs/decisions.md` "Cranelift code quality, round 1" |
| Measurement knobs `YAVS_CLIFT_NATIVE` (`0` turns the variants off), `YAVS_CLIFT_NATIVE_MAX` (most variants made), `YAVS_CLIFT_INLINE` (largest inlined body, `0` for none), `YAVS_CLIFT_DUMP` (IR of each function and why a variant was or was not made), `YAVS_CLIFT_CLIF=<id|all>` (the Cranelift IR), `YAVS_CLIFT_ASM=<id>` (the machine code), `YAVS_CLIFT_PERFMAP=1` (`/tmp/perf-<pid>.map` for `perf report`) with `YAVS_CLIFT_CODEDIR=<dir>` (the machine code of each function as `<name>.bin` and `<name>.srcmap`, the IR pc of every stretch of it: `perf script` addresses minus the function's start give the executed instructions per IR instruction, with `objdump -D -b binary -mi386:x86-64`), `YAVS_CLIFT_TRACE` (a line per materialised frame), `YAVS_CLIFT_NO_SCAN` (search loops without `yavs_rt_scan`); plus `YAVS_CLIFT_OPT` (`speed` default, `none`), `YAVS_CLIFT_VERIFY` (on in debug builds, off in release), `YAVS_CLIFT_RA` (`backtracking` default, `single_pass`) | Spike measurement only | `src/lower.rs` |

| The machine code of every function goes through `Jit::define_code`: with a store (`set_cache`, the work library of `--tier=clift`, `clift-auto`, `auto3`; not `--no-cache`) Cranelift's `compile_with_cache` under its own key of the body and the target (`incremental-cache`; the names of the functions and data the body refers to are relocations, not part of the key) plus the yavs build and `yavs_ir::opt::fingerprint`, then `define_function_bytes` with the relocations of the body. `Generator::cached_only` (the policy's probe) compiles nothing the store lacks (`NOT_CACHED`; `missed`), and a variant that failed so is not remembered as "none" (`native_of`); a frame-mode body is defined once (`frames`). The callees' references are declared in id order so a body, and its key, is the same every run | A warm run spent 2 to 19 s translating again (eager neorv32: 4 079 ms compiled, 536 ms linked); hand-written keys over the CLIF text would have to rename the module's function and data ids | `src/cache.rs`, `src/lower.rs` `define_code`, docs/decisions.md "Cranelift tier, round 5" |
| A process that never suspends (`FuncFlags::MAY_SUSPEND` clear) counts its retreating `Br`s (`yavs_interp::retreating_brs`) in a Cranelift variable loaded from `TierFrame::spin` at the entry and stored back by the exit block (`Gen::spin_poll`); it leaves at the `Br` at a stop request and at every `SPIN_CHECK`th jump, before counting it; `Inst::Zero` (frame temporaries, #668) is zeroed in place through `host` | As the LLVM lowering (#737, #583, user 2026-10-26): such a process stays compiled under the 10^9 bound, the interpreter's step of the `Br` trims and reports it | `src/lower.rs` `gen_func` |
| Ported from the LLVM lowering of main (2026-10-26): the element loops of a variant whose frame is registered ask `yavs_rt_eloop` for all iterations but the last at the loop head (#757, `Gen::eloop`; the program is an 8-byte aligned data object); a `LayoutOf` whose one word is read right after it is one `yavs_rt_layout_word` call (`rt::fuse_layout`, `Gen::layout_word`; with no inline layout cache in this lowering, frame-mode `LayoutOf`s with a cache are fused too); the zero-delay scalar drives of a process are kept in a stack batch (`Batch`, `rt::batched_drives`, `rt::batch_pure`) and handed over by `yavs_rt_drive_flush` before any other instruction and in the exit block | The same callbacks as LLVM's code makes; without the batch every scalar drive was a kernel call (918 against 153 in `llvm_drive_batch`) | `src/lower.rs`, `perf.rs` `clift::{eloop,layout_field,drive_batch,nowait}` |
| Frame-mode code: a register's guess of its space (`Known::LikelyTemp`, `LikelyHeap`) survives a block start reached by falling through (an entry after a call); dope reads of `DopeLen`/`SubtypeCheck` use the register's facts (`dim_len`); a `Copy` of a known size of up to 64 bytes is words (all loads before the stores; pairs stored as 16 bytes, round 7, so the 16-byte loads of `rt::plane_block` are forwarded); a temporary of 32 bytes of run-time size at an aligned end is zeroed by stores; a multiplication by a constant that only feeds the `Index` after it is one test of its operand (`rt::index_muls`); a `Pos` in a descriptor of the constant pool reads the dimension when the code is made (`Gen::const_dim`: one unsigned compare and a subtraction) and a range check with constant bounds is one unsigned compare (`range_exit`, round 8) | A guess is tested where it is used; the rest are the `yavs_rt_host`, `memmove`, `memset` and `smul_overflow` costs seen in the adder processes of `poc_arith_addw` (a `memset` then 8-byte reads of its bytes stalled on store forwarding) | `docs/decisions.md` "Cranelift tier, round 6" |

## 4. Invariants and pitfalls

- A value cached for a register is valid only while the generator is in a block dominated by the
  block that defined it: clear the cache at every point that joins paths or calls out. A deferred
  value (`pend`) survives `clear` (it dominates every block up to the next block start, which
  stores it or takes it as a parameter); a definition of the instruction being generated
  (`fresh`) must reach a join as a parameter (`join_with`): a `clear` with one pending is a bug
  (`broken`, a debug assertion).
- Compiled code never reports an error itself: an inline instruction that fails returns its own
  pc and the interpreter re-executes it (rule 5).
