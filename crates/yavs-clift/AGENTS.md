# AGENTS.md: yavs-clift

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-clift`.
The Cranelift tier of #481, on main behind the `clift` feature (not a default feature) and the compiled
tier of the release archives (user, 2026-10-28: one archive per platform); tuning rounds are paused. Measurements in
`docs/STATUS.md` "clift", decisions in `docs/decisions.md` "Cranelift tier" and its rounds.

## 1. Purpose and boundaries

- A second code generator for the compiled-code contract of `yavs-llvm`: the same function
  signature (`fn(env, regs, mem, pc) -> u32` on the interpreter frame's registers), the same
  frame view (`yavs_llvm::rt::Mem`, `TierFrame`), the same callbacks (`yavs_rt_step`,
  `yavs_rt_signal`, `yavs_rt_host`), the same side exits. Cranelift is a Cargo dependency, so a
  release binary gets a compiled tier without an LLVM install.
- `compile` (`yavs run --tier=clift`) translates every non-elaboration function before time 0.
- `First` is the Cranelift `yavs_llvm::Generator` of `yavs-llvm`'s `AutoTier` (the policy of `--tier=auto`: budget, payback, bands, trials): the only generator of `--tier=clift-auto` (a yavs built with the `clift` feature alone), the first level of `--tier=auto3` (both features: Cranelift for warm functions, LLVM O2 for those that stay hot).
- Everything is behind the `clift` feature (off by default); `yavs --features clift`.
- Depends on `yavs-llvm` (without its `llvm` feature) for `rt.rs`, which holds everything the two
  code generators share, `yavs-interp`, `yavs-ir`.

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| Registers stay in the frame's register array; a per-block cache of SSA values avoids reloads, and is dropped at every block start, join and callback, except as the next row says | Callbacks and the interpreter read and write the array | `src/lower.rs` |
| Frame mode, processes (round 7): the definitions of `quiet` instructions are deferred (`Gen::pend`, `fresh`, `settle`) and stored only where the interpreter or a callback can look at the frame: at a non-quiet instruction (`spill`), an exit (`leave_at`: the deferred registers live at its pc, `regs::Live`), the block of a slow path (`snaps`, stored before the step), a block start a jump leads to; registers the interpreter preloads are never stored, registers live over more than `MAX_SPAN` instructions are stored at the definition. A slow path's join takes the fast path's definitions as block parameters (`join_with`; the slow path loads them after the step), so do the result of a direct native and of an in-place `ieee` native. A block start no jump leads to (the entry after a call) takes the live values in hand as block parameters; the switch over the entries is made at the end (`dispatch`) and its stub loads them from the frame. In every frame-mode function the facts of `known` carry over such a block start (its only way in is the instruction before it) | LLVM's deferred stores (decisions "Tight compute loops"); a callback's result was stored and loaded again right after it, and every definition was a store | docs/decisions.md "Cranelift tier, round 7" |
| Copies of a process (`Program::copy_of`) whose Cranelift body and referenced functions and data are equal are one definition (`Jit::bodies`, key `compute_cache_key` plus the external names) | `--tier=clift-auto` defined 36 copies of the adder processes of `poc_arith_addw` where LLVM's twins share 4: 10 percent of the cycles | docs/decisions.md "Cranelift tier, round 7" |
| Slow paths (step the instruction in the interpreter) are emitted after the body and rejoin the fast path | Keeps the hot path straight; a stepped instruction may write any register | `src/lower.rs` |
| `cold::propagate` runs before the cache key and `Jit::define_code`, so the key sees the layout (`Layout`'s hash covers the cold flag). A generator marks only the block it knows is cold; the continuation after a callback there follows by itself. It changes flags and adds jump-only blocks, no operation. Cranelift lays blocks out in reverse postorder with the cold ones last, so of a branch whose two ways meet again one way is always a taken jump unless the other is cold: writing the branch the other way round only turns a taken conditional into a taken `jmp`. So a rare way is marked cold where it is made (the codes of a short `SigRead` after the plane-word test, `sig_read_word`; the native call of an in-place `ieee` op, `ieee_native`). Builds that count (debug, `op-census`) call `yavs_rt_rare` at the start of each, so `cb_rare_codes` and `cb_rare_native` show how often a rare way ran (`Gen::rare`) | A continuation that stayed hot made hot code jump over it with an always-taken forward branch; the two rare ways and the branch over the statement end's store were about 700 (GRLIB) and 1 130 (Microwatt) of the distinct taken branch sites of a kernel cycle window (docs/decisions.md "Cranelift: rare ways cold where they are made") | docs/decisions.md "Cranelift: cold continuations" |
| An address parameter of a native variant used three times (`rt::hold_addrs`) has its region resolved at the entry (`Gen::hold_resolve`: inline for a composite variable of the root frame, a native caller's slots, an object of the table, nothing for what is not held, else `yavs_rt_region`), `[pointer, length]` in a stack slot (`Held`): `Known::Param(k)` is `pres[k]`, and an access is one compare of its end against that length, the chain of `host` when it fails. Held over calls: a native caller's slots, the root frame, instance data, packages, constants, heap objects; after an instruction outside `rt::holds_over`, and at the end of a slow path that comes back, `hold_recheck` compares `TierFrame::heap_gen` (the sum of the heaps' epochs, refreshed with the temporary area by every host call, which `Mem::forget` relies on too) and asks `yavs_rt_region` again when a heap changed. The temporary area and the interpreter's other frames move and are held only in a `stable_activation`; the root frame by its own address (a copy a process made in its frame, passed to a function) is `TierFrame::root_slots` inline when the view has them (#1122), else `yavs_rt_region`. A new instruction that frees or edits a heap object on its hot path must stay out of `holds_over`, and a new way for the root frame's slots or instance data to move ends this design. `YAVS_CLIFT_HOLD_CHECK` (always in debug builds) checks every held access against the lookup (`yavs_rt_hold_check`, aborts), and the difftest candidate `yavs-clift-check` turns it on; `YAVS_CLIFT_HOLD_DROP` (debug builds) leaves the recheck out: the mutation test of `crates/yavs/tests/clift_hold.rs` | `unsafe_pop` of the test runner's queues ran the chain of `host` five times per call, 18 to 30 instructions each; a process-level hold across calls was unsound over `sstack` resizes (`docs/decisions.md` "Held regions of address parameters") | `src/lower.rs` `hold_resolve`, `hold_recheck`; `rt.rs` `Mem::region` |
| `yavs_rt_host` and the `Deref` of `yavs_rt_fast` in a native variant go through stubs that clobber no register (`cold_stub`, `CallConv::PreserveAll`), the result in `Mem::cold_ret`; so does the re-resolve of a held region. Frame-mode code calls the plain callbacks | Those cold blocks come back to the hot path, so the allocator kept what the hot path holds over them: spills and reloads in code that never calls. A native frame rarely misses; frame-mode code often does, and the stub's saves cost more than the spills (Microwatt eager +4 %) | `src/lower.rs` `cold_stub`, `host_call` |
| A native variant finds the view in the pinned register (`pin_mem(.., adopt)`): every Cranelift caller has it there, the `c<id>` adapter sets it for the interpreter. A build with the `llvm` feature keeps the save and set in the variant, since an LLVM-compiled caller knows nothing of the register | 5 instructions per call | `src/lower.rs` `pin_mem`, `define_adapter` |
| An access of a constant size is one compare of its end (`in_range`: `off + n <= len`, no wrap since `off` is below 2^63 + 2^32); only `yavs_rt_host`'s answer to a lookup can be null (`host_call`, `nonnull`); arithmetic with an interval proof has no overflow test (`Gen::iv`, `iv_track`, `yavs_ir::opt::iv_after`, the transfer function of the optimiser's interval analysis; `YAVS_CLIFT_NO_PROOFS=1` keeps them); a `Deref` hit compares the tag as 32 bits; `Pos` and `DopeLen` have one arm per direction with the tests of the interpreter; a case arm of one value is one compare; a `Stmt` stores the length cut back to the base with no branch (`umin`: a branch over the store was a taken site per statement); a call tests the frame index against `TierFrame::max_depth` alone (`TIER_MAX_DEPTH`) | Bounds and range tests all stay: these are the same tests in fewer instructions. Window generator eager 53.90 to 46.06 G with the rows above, bytes 12.08 to 11.48 MB | `docs/decisions.md` "VUnit-style library code in Cranelift" |
| The kernel-facing instructions are lowered as the LLVM generator does (2026-10-24): `Inst::Edge` and the `rising_edge`/`falling_edge` natives (the kernel's resume key in `Mem::known`, else the event stamp, the codes and the last-value planes of the `TierSig` entry), `SigReadScalar` (codes, planes, or the bytes of an integer, enumeration or real signal), `SigRead` (up to 64 elements through `yavs_rt_codes`, more through `yavs_rt_planes`; a reference that a `SigSlice` of a constant length of up to 64 made in the same block has that length as a guess, `Gen::slices`, which `sig_entry` tests, so the read is the in-place word read, #1121), `SigAttr` `'event`, the scalar logic assignment the interpreter fuses (`scalar_drives`: the fused `Alloc`/`Store`/`Index`/`LSet` are skipped, `Drive` calls `yavs_rt_drive_bit`), other single-element `Drive`s (`yavs_rt_drive`), `WaitOn` plus `Suspend` (`yavs_rt_wait`), a `WaitOn` that is not the last (`yavs_rt_wait_on`), the wait that names the same signals (`static_wait`, `yavs_rt_wait_same` at the `Stmt`), frame-mode `CallNative` of the natives `direct_native` allows (`yavs_rt_native` with `NATIVE_FRAME_MODE`); `TempRoot`, `NewFrame`, `Stmt`, `Deref`, `MemEq`, `Cat` and (frame mode only) `SigGather` and `SigScatter` go to `TierHost::signal` instead of the generic step. An access through the result of a `Deref` (known to be on the heap) tries the entry of `Mem::objs` (one load and compare) before `yavs_rt_host`; any other address of unknown space calls `yavs_rt_host` (next rows). None of this is in a native-frame variant except `SigReadScalar`, the table read, `SigRead`, `SigSlice` (inline in both modes for a reference of one range: the element or slice of a signal parameter; a reference of several parts or a range out of bounds is stepped, #1121), and `Drive`/`DriveSlot` of one waveform element (`yavs_rt_drive_nat`: no frame view, a zero-delay drive on `TierFrame::kctx` as frame mode's, else the host's answer or nothing; where the view or the kernel has no answer the native frame is materialised, as the LLVM tier does since #730); another signal operation or a callback that needs a step makes the function frame-mode only | Without them a clocked process made 4800 signal callbacks and 960 steps per 1000 activations against 4 and 8 under LLVM, and ran twice as many instructions as the interpreter | `src/lower.rs` `impl Gen` "kernel-facing instructions" |
| Where a copy has no facts for the target, a `Drive` of one waveform element (`n` 1) at a constant reference of 1 to 64 elements covered by the function entry's signal-table test (`sig_ok`, `sig_max`), with the waveform in the frame (16 bytes at least inside it or its composite variable) or in the temporary area, calls `yavs_rt_drive_f(mem, pc, driver, lo, wave, len \| inertial << 32 \| readable bytes << 33)` (`Gen::drive_thin`): no table test, element-size load or size select at the call site; the callee finds the form in `TierSig` and sends a waveform not all in reach to the interpreter. Any other `Drive` keeps `yavs_rt_drive`; `sig_entry` also skips its table test for a constant reference the entry's test covers | The general call site was about 57 instructions of generated code per integer drive, 31 now; a skipped drive costs 150 to 260 more in the host | `src/lower.rs` `drive_thin`, `sig_entry`; `rt.rs` `yavs_rt_drive_f`; decisions.md "Drive from compiled code" |
| In a process copy, a zero-delay drive with a constant driver below 64 at a reference the facts know compares inline before the call: `Gen::gate_test` (the word at `TierFrame::gate`), `cur_is_code` (one element: the codes, else the planes), `cur_differs` (the waveform's delay and first block against the planes in one plane word, or one byte element); a hit is one store to `Mem::skipped`, and `rt::gate_skipped` tells the kernel when the code is left. `drive_kept` closes the whole gate before it keeps a drive whose bit is open or that has no bit (driver 64 and up): the kernel does not see the entry yet, and two of the machine's drivers can name one kernel driver. A closed bit needs nothing, since all the bits of a kernel driver close together, so a kept drive of a driver that is not direct leaves the gate open for the others. Shared code, native frames, a run-time reference and a `DriveSlot` keep the call. `YAVS_INLCMP=off` generates no compare; `check` (always in debug builds) calls `yavs_rt_gate_check` at every skip, which aborts when the kernel's full test disagrees | A skip cost 150 to 260 host instructions; see the kernel's row on `ProcState::gate` | `src/lower.rs`; docs/decisions.md "Drive compare in compiled code" |
| A whole `SigScatter` at delay 0 and a whole `SigGather` in frame-mode code use the machine's `ImageCell` (`Gen::cell_of`): with an image, a scatter compares with it (`yavs_rt_memeq`) under the plan gate and on a hit stores `Mem::skipped`, a gather copies it; with no image, a gather of a record of at most 8 logic vectors of up to 64 elements with no descriptor reads each leaf in place from its signal's planes (`Gen::static_leaves`, `read_leaves`); with no image but a plan the cell names (`ImageCell::direct`), `yavs_rt_scatter` and `yavs_rt_gather` drive and read it on the kernel itself (`Gen::call_stored`: the deferred registers are stored for the call but stay deferred, so a compare hit stores nothing); any test that fails takes `yavs_rt_signal`, which keeps the cell. `yavs_rt_image_check` at every hit in check mode (`image_mode`, part of the key) | A held record drive went through the host and the kernel's clean test before its compare; a gather through the host before its copy; a record that changes at every clock went through the host and the plan lookup at every drive and read (#1110) | `docs/decisions.md` "Record images in compiled code", "Record drives in compiled code" |
| Not lowered inline (stepped): calls (except to a function with a native variant), natives other than the `std_ulogic` tables, edges, `math_real.uniform` of three variables (`uniform_fast`, in place, the native as its slow path), the light `numeric_std` natives (`native::ieee_fast`; inline on their small path, `ieee_native`) and the `direct_native` ones, `New`, reports, `**`, `LEq`, `NewFill`, `PkgAlloc`, `SigLastValue`, `LogicOp` of `Resolve` and `to_x01z`, and signal operations other than those above | Same list as the LLVM tier minus `LayoutOf` (fused, row below) | `src/lower.rs` |
| Frame-mode code reaches an address whose space it does not know through the object table inline (`Gen::obj_try`, keyed by the address's own space: heap objects and constants found before, nearly all of what the runtime found), then `yavs_rt_host` in a cold block (`Mem::find`: the temporary area, instance data, the frame, then the interpreter) (perf/inv-lower prototype, 2026-11-02, replaces the plain call of #634); a pointer loaded from a frame slot that every 8-byte `Store` fills with the address of one frame offset (`slot_targets`, a descriptor of a variable sized by a generic in shared code) is compared once with that address at its use and then reached as the frame's own bytes (`Gen::fguess`, a guess: a mismatch takes the lookup); the inline chain of tests (the frame, temporary area and instance data by the high half of the address, then the object table) stays in native-frame variants only. ## 4. Invariants and pitfalls

- A value cached for a register is valid only while the generator is in a block dominated by the
  block that defined it: clear the cache at every point that joins paths or calls out. A deferred
  value (`pend`) survives `clear` (it dominates every block up to the next block start, which
  stores it or takes it as a parameter); a definition of the instruction being generated
  (`fresh`) must reach a join as a parameter (`join_with`): a `clear` with one pending is a bug
  (`broken`, a debug assertion).
- Compiled code never reports an error itself: an inline instruction that fails returns its own
  pc and the interpreter re-executes it (rule 5).
- A pre-key hit skips `lower`: a new input of the lowering (an environment variable, a process-wide
  setting, something of the run, anything of `Program` that `Program::identity` does not name) must go into
  `cache::pre_key` or its `KEYED` or `NO_PRE`. `every_switch_of_the_lowering_is_accounted_for` fails on a
  new variable; the check (debug builds, `yavs-auto-warm`) fails on the rest. A body may refer to a new kind of symbol
  only with a `Name` for it (`Jit::names_of`).
- Slow paths, entry stubs and the exit block are generated after the body, so they have no pc of
  their own in `known`: `gen_func` resets it to `base_known` first (#1089). State that depends on
  the pc is taken when the slow path is made (`snaps`, `jparams`, the fields of `Slow`), or read
  through the Cranelift variables.
