# AGENTS.md: yavs-cycle

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-cycle`.
Cycle mode lives on the side branch `Lukas-mode` only, milestone by milestone; this is milestone
4a: two-state values, the types, expressions and statements of RTL (`numeric_std`, `case`, nested
arrays, enumerations, concurrent assignments, `wait until` processes, asynchronous resets, unrolled
loops), and the bench RTL designs of `tools/bench/designs` inside the region.
Milestone 3 (in parallel) added the subset checker (`check.rs`), which is also the selector, and
the element-level dependence graph (`dep.rs`).
Milestone 8 added several clocks (one edge class per clock and edge, edges in one delta run
together on the values before the edge) and asynchronous resets made inside the region (reset
branches in the settle).

## 1. Purpose and boundaries

- `yavs run --cycle` (or `--cycle-strict`, its strict form, given instead): the processes the mode
  can take join one region, run by one kernel process on a static schedule (clocked bodies, commit,
  combinational bodies in dependency order) over a flat image of two-state words, compiled with
  Cranelift.
  Every other process stays in the event kernel and is listed in the region report with its reason.
- The region reads from the kernel the inputs its members read, at a wake only those that changed
  since its last one (the kernel counts the changes of each input chunk of up to 64 elements in an
  image of `ImageKind::Count` items), and drives with zero delay, through the member processes' own drivers, every member-driven signal anything outside may
  read, only where it changed. At the boundary a kernel value becomes two-state (`'1'` and `'H'`
  are 1, every other value 0, a metavalue counted) and outputs go back as `'0'` and `'1'`. An exported kernel signal nothing outside waits on is quiet
  (`yavs_kernel::Builder::quiet`, no byte codes): the kernel makes its change without an event
  while nothing waits on it at run time.
- Selection is automatic and never an error under `--cycle`. A process stays out for one of three
  kinds of reason, kept apart in the code (`region::Why`) and the report: outside the subset (a
  code `E4110` to `E4127`, the construct's position), behavioural (the testbench kind: timed or
  several waits, `wait;`, a procedure that waits, files, text I/O, access values, protected
  objects, simulator procedures), or in the subset but not implemented yet (the lowering's reason).
  Under `--cycle-strict` every reason of a process below the top-level design unit that is not
  behavioural is an error with its code (`E4101` for not implemented yet), all of them listed.
- Does not: change the normal mode (without the option no code of this crate runs; the only hook is
  `yavs_elab::Elaborated::region`), use `yavs-lower`, the IR or the interpreter for region code (it
  lowers the elaborated HIR itself), or keep anything between runs but its analysis and the machine code of its functions (the compilation cache, below).
- Depends on: `yavs-sem` (HIR, `reads_deep`, `stmt_exprs`, `edge_shape`),
  `yavs-elab` (net graph, `NetGraph::select` also on layouts of variables and of ports collapsed into parts, process instances, `var_shapes`, `value`, `range`, the `Region` hook), `yavs-kernel`
  (`Process`, `Ctx`, `publish_planes`, `Builder::quiet`), `yavs-ir` (`ieee::parse`: which `ieee`
  subprogram a call is), `yavs-rt` (`perfmap`), `yavs-diag`, `yavs-syntax` (identifiers of layout objects), `yavs-cache` (the cycle store of the work library), `yavs-interp` (`outside_calls`), `yavs-lib` (`fold` of generic names), `serde` and `postcard` (the analysis cache's entries), the Cranelift crates at the version
  `yavs-clift` pins (unconditional dependencies: the default test suite runs cycle mode). Called by:
  `yavs` (`run`).

## 4. Invariants and pitfalls

- Every reason a process is left out is a plain sentence a user reads in the report (rule 35); no
  selection path may panic. A failure to compile what was selected is `E9999`.
- The bits above a logic value's length are zero in every word: every op keeps it, and
  `Gen::bits` relies on it to leave masks out.
- `Op` operands are read before the result is written; the peephole in `Lx::assign` retargets the
  operation that made a fresh temporary.
- A word the code addresses at run time (`IndexRead`, `IndexWrite`) must be in memory: the cache
  spills it first and forgets it after a write (an element may reach into the word after the
  value, which the image always has). A branch stores what it changed before its join, and every
  word it forgot is stale after the join too (milestone 2's code kept the old value: a run-time
  write or a nested branch inside a branch was lost).
- `codegen::reads` names every word an operation's code reads, from registers or memory (the array a
  run-time index addresses, the word after it): a word missing there is taken for dead before its last read,
  and a scratch word is then lost. The numeric, cut and share tests run with `YAVS_CYCLE_REGS` so that a debug
  build sees it (`read_memory`). A new operation needs its row there.
- Scratch words never cross members: a piece starts from memory and from the state words the piece before it in its function left in registers (clean). They do cross the parts of a member
  cut by `cut`: such a part stores every changed word (`spill_all`). `codegen::span` must name, for
  every operation, how far it can write from its destination, or a cut `if` could test a condition
  its own branch changed.
- Integers export their low 4 or 8 bytes: correct because every assignment to a signal is range
  checked (with `YAVS_CYCLE_CHECKS=off` a value out of the subtype is exported truncated).

## 5. How to work here

```sh
cargo test -p yavs --test cycle
yavs run --cycle --work=work:W top          # the region report on stderr
YAVS_CLIFT_PERFMAP=1 perf record ... yavs run --cycle ...   # region functions named cycle_*
YAVS_CYCLE_DISASM=1 yavs run --cycle ...                     # machine code of the region on stderr
YAVS_CYCLE_CHECKS=off yavs run --cycle ...                   # without range and overflow checks
YAVS_CYCLE_CHECKS=all yavs run --cycle ...                   # also a pass after each loop group's runs that must change nothing
YAVS_CYCLE_STATS=1 yavs run --cycle ...                      # per function: operations, Cranelift instructions, bytes, compile time; shapes; selection timing; after the run wakes, inputs read without an edge, guard runs and skips
YAVS_CYCLE_SKIP_CHECK=1 yavs run --cycle ...                  # every skipped settle step run anyway: an internal error when it changes what it drives
YAVS_CYCLE_SKIP_CHECK=full yavs run --cycle ...               # also every run against one of every step on a copy, and every output the export skipped (the tests' default)
YAVS_CYCLE_GUARD=all yavs run --cycle ...                     # every settle step behind a guard (the tests run with this and the skip check)
YAVS_CYCLE_EXCLUDE=dcache_slow yavs run --cycle ...         # processes whose names hold one of the texts stay out (bisecting a difference)
YAVS_CYCLE_CHECKS=on yavs run --cycle ...                     # checks without the confirming pass of loop groups, also in a debug build
YAVS_CYCLE_FLAGS=opt_level=none yavs run --cycle ...         # more Cranelift settings, to measure them
YAVS_CYCLE_CHUNK=5 YAVS_BIN=... python3 -I tools/difftest/cyclegate.py   # every member cut into parts of a few operations
YAVS_CYCLE_REGS=2 YAVS_BIN=... python3 -I tools/difftest/cyclegate.py   # two words in registers at a time: the flushes and the dead-word drops everywhere
YAVS_BIN=<release yavs> python3 -I tools/difftest/cyclegate.py   # the correctness gate
YAVS_CYCLE_CACHE_CHECK=1 YAVS_BIN=... python3 -I tools/difftest/cyclegate.py --warm   # each cycle run again with the code from the cache, every hit compiled again and compared
```

- Run `tools/difftest/cyclegate.py` before every push of cycle code (30 seconds): it runs the difftest corpus,
  `tests/cycle` and the bench designs in normal and cycle mode with one binary and fails on any difference the
  documented losses (A6) or the reviewed list `tools/difftest/cyclegate.expected` do not explain; a new entry in that list is a decision to accept the loss, not a way to silence the gate. It also shows how many
  processes joined per test, so a pass is not vacuous: read the summary's count of tests with a member.
- Run the fixed-seed fuzz run before every push of cycle code too (about 3 minutes, README "Cycle mode fuzzer"):
  `python3 -I tools/difftest/cyclefuzz.py run --seeds 0:400 --warm --checks 5 --bin <release yavs>` (exit 1 on a
  difference, a seed that does not compare, or membership under 60 percent). Random designs in the subset found two wrong results that every gate before it passed (`q <= q`
  after an earlier write, a right shift by 64 or more); `shrink SEED` reduces a failing seed, and its summary
  shows how many of the designs' processes joined. A longer run (`--seeds A:B` with new seeds) after a lowering change.
- When a recorded command file of the user's test runs exists, run `tools/difftest/cyclereplay.py` on it before every push
  of cycle code too (README "Cycle mode gate"): it replays those runs normal and `--cycle` and compares the exit status, the
  end time, the console and the files written. It runs on private copies of the recorded libraries (made per replay,
  removed at its end), so a shared command file's libraries stay as they were. A warm pass: the first replay with
  `--libs DIR` (copies kept), the same again (the warm runs as users run them), then with `--libs DIR --warm` (with
  `YAVS_CYCLE_STATS`: every cycle run with members takes its region or all its functions from the cache, or the test
  differs; the summary counts the hits). Five wrong results passed `cyclegate.py` and `cyclebig.py` and were found
  on such runs (one test of a bench stopped one clock early: same verdict, same last message, another STOP time).
- `crates/yavs/tests/cycle/recreset.vhd` (arrays of records under synchronous and asynchronous reset, one reset by a literal aggregate), `cmpcount.vhd` (a counter with an enable feeding comparators), `fsmrec.vhd` (a state machine whose state is a
  record, in the two-process style) and `handshake.vhd` (a request and acknowledge handshake between clocks of 10 ns and 7 ns) are run by
  `cyclegate.py` only, not by `cargo test`: each has a monitor that stays outside the region and prints the registers at every
  rising edge and 1 ns after it, so a one-clock difference is a difference of the console.
- The gate has no large design: `tools/difftest/cyclebig.py <yavs>` (realbench worlds prepared) runs NEORV32
  dual_full and Microwatt CoreMark short in both modes and compares exit status, console, the files written (the
  CPU's instruction traces) and the region's member count with the one its `GATE` table holds (about a minute: 6 s
  NEORV32, 56 s Microwatt, 2026-11-16). It is required before every push that changes membership (user decision
  A22), and a missing world fails it. Microwatt runs to 1369 us in both modes, past "Execution completed.": the
  normal mode ends there with its RTL's `end of test` failure (exit 1), which cycle mode drops (A12, exit 0). A new
  member count is updated in `GATE` in the commit that changes it, with the reason. NEORV32's normal mode prints
  about 80 000 library metavalue warnings and configuration notes, all from member processes; `--cycle` prints
  none of them by design, and no UART text in either mode (its built-in program does not print).

- `E4102` (`yavs` `RunArgs::not_with_cycle`) refuses what records, shows, counts or changes region signals: a debug
  session, `--wave`, `--surfer` (named before the `--wave` it implies), `--cov`, `--vhpi`, `--activity`. Allowed
  (user-visible reasons in `docs/cycle-mode.rst`): `--profile` (samples the interpreter; the region is one kernel
  entry), `--assert-summary` (counts the asserts that run), `--shuffle`, `--hang-report`, `--time-report`. A new
  option that observes signals goes into that one function, and into the vunit-yavs check if the package can set it.
- Codes owned: `E4100`-`E4199`, `W4100`-`W4199` (in use: `E4101` to `E4104`, `E4110` to `E4127`, `lib.rs` `codes`).
- `yavs run --cycle-report[=FILE] ...` (user decision 2026-11-15, amendment A11) analyses the design,
  prints the full region report and exits 0 before compiling or simulating: the checker's verdicts on
  any design, whatever the lowering supports. It is a third mode, exclusive with `--cycle` and
  `--cycle-strict`. Plain `--cycle` (and `--cycle-strict` when it passes) prints one summary line;
  the report is the only place the rows are. Report layout (`plan` in `lib.rs`): summary, the
  processes left out grouped by code (behavioural and E4101 are a group each), most common first, the
  asserts and reports not evaluated with their holders and the fixed note that members give no ieee library warnings, the subset and loop-group lines, the boundary, the
  cycle-based processes. An unwritable FILE is E4103 before any work. The developer switch
  `YAVS_CYCLE_VERDICTS` is gone: the tests and `tools/difftest/cyclegate.py` read `--cycle-report`
  (the test helpers `run` and `run_text` append it to the standard error of a cycle run).
