# AGENTS.md: yavs-interp

Read the root `AGENTS.md` first. This file is for an agent about to change
`crates/yavs-interp`. The design is `docs/design/ir.md` section 3 (dispatch, kernel `Process`,
diagnostics and stack traces, debug hooks, thread safety, elaboration-time evaluation) and
section 9; the interpreter API and the Requests log are in `crates/yavs-ir/README.md`.

## 1. Purpose and boundaries

- Executes `yavs-ir` programs: `InterpProcess` implements `yavs_kernel::Process` (heap frame
  stack, waits inside procedures), `call`/`call_shared` run code without a kernel (elaboration
  time), natives (std.standard, textio, files, env, implicit operations, `'image`/`'value`,
  `std.reflection`), VHPIDIRECT foreign calls with marshalling, generational heaps with
  precise-root GC, protected objects, and debug hooks in the style of commercial simulators.
- **The interpreter is the semantic reference** (rule 5): the JIT tier must match it exactly.
- Does not: lower HIR, build the hierarchy, schedule processes (kernel), or format values itself
  where `yavs-std` has the function (it marshals and calls `yavs-std`).
- Depends on: `yavs-ir`, `yavs-kernel`, `yavs-logic`, `yavs-std`, `yavs-ffi`, `yavs-diag`.
  Called by: `yavs-elab` (builds processes, elaboration-time calls), `yavs-lower` (tests).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| Interpreter is the semantic reference; `--threads 1`/`N` identical | Rules 3 and 5 | `docs/plan.md` rule 5; root `AGENTS.md` rule 3 |
| A signal reference of several parts is mapped part by part onto `Ctx` in one step: reads concatenate, `'event`/`'active` any part, `'last_event` the most recent, drives split each waveform value and use each part's own driver slot; the parts' table lives in temporary memory | #71, LRM 16.2.4; no kernel change, same delta | ir.md 1.8 |
| `Bindings::revision` must be set by whoever builds the runtime (elab does, from `Db::rev`): FILE_OPEN_KIND positions differ per revision (2019 has READ_WRITE_MODE second), as do INTEGER bounds and `vhdl_version` | #297 | `yavs_std::file::FileOpenKind::from_pos` |
| Memory model: untyped u64 registers, 8 address spaces, every data-dependent access bounds-checked; out-of-object is an ICE, freed object a runtime error | Fail early, no UB | `docs/decisions.md` "IR and interpreter (M2)" |
| Temporaries live until the next statement of their frame | Unconstrained results survive return without copy | same |
| Natives by NATIVE.md symbol; undefined symbol fails `Runtime::new`, defined but unimplemented is a runtime error naming it; the table is parsed only for a symbol with no implementation (a debug build also checks that an implemented one is documented) | Fail early; parsing it in every run cost 4% of a tiny one (#426) | same; `lib/NATIVE.md` |
| An all-zero `NewFill` is a zeroed allocation (`vec![0; n]`), not a `resize`: untouched pages of a huge sparse array cost nothing (#486) | A 2^29 element `std_logic` list peaked at 567 MB | `docs/STATUS.md` "Zeroed large arrays" |
| Heap: generational handles, precise roots (`Func::roots`), mark and sweep at suspensions; skip collection rather than be unsound | Rule 6 | `docs/plan.md` rule 6, ir.md 1.6 |
| `Heap` has no flat per-slot view for compiled code (#655: built, correct, and slower than the object table); a future one must keep: generation compared on every access, freed and being-edited slots shown empty (`edit` hides, `reissue` shows), no `Clone`/serde of addresses (hand-written `Clone`, rebuild in `restore_state`), empty while `TIER_STAMPS`, refreshed wherever `TierFrame::heap_epoch` is, and a cross-check against the handle path in debug and `gc-stress` builds | A missed update point is a host use-after-free | `docs/decisions.md` "A flat view of the heap slots for compiled `Deref`" |
| Allocations in elaboration code run with the shared state, in methods of shared protected objects, and in everything they call go to the shared heap (`Frame::shared_alloc`, `Machine::alloc_heap`, the one allocation path) | Their objects outlive the elaboration call's private heap (#184, #246) | `docs/decisions.md` "Allocators of shared objects" |
| Serial processes allocate in the shared heap; it is sealed at the start of the simulation and collected at `Phase::NextCycle` by `SharedGc` and, once the simulation has started, inside a long activation (`Machine::gc_inline`, before a `new`, a `deallocate` or a native call, never in elaboration code, #409) from `Program::shared_roots`, the sealed objects and the roots each serial process publishes at its suspensions (`Machine::publish_shared`) | Values reached through non-protected shared variables, bounded growth, never during a cycle (user, 2026-10-19, #303) | `docs/decisions.md` "Shared heap collection" |
| Roots are precise (`Machine::refs`, #422, user 2026-10-19): the frames' root maps, the temporaries `Inst::TempRoot` recorded (`Machine::troots`, dropped by the `Stmt` that ends their statement), and between instructions the `Handle` registers live where each frame is (`roots::live_refs`); live `Ptr` registers, `RootKind::Addr` slots and recorded fat pairs pin the heap objects they point into. No conservative scan anywhere | Plan rule 6 | `docs/decisions.md` "Shared heap collection" |
| Package initialisation records whether it did more than compute (`Machine::tainted` into `SharedState::tainted`): foreign calls and every native not listed in `native::pure`; its reports are recorded (`init_reports`) and printed again when the state is restored. A new native that reads or changes anything outside its arguments and the heap (files, environment, clocks, assert state) must stay off that list; a new field of `Heap` or `Slot` is stored with the package state by the derive, so it must be serde-serialisable and mean the same after a restore | The cache restores the state instead of running the initialisers (#407): an effect that is skipped is a different run | `docs/decisions.md` "Compilation cache", `src/state.rs` |
| Deallocated heap slots are quarantined until a suspension finds no address to them among the precise roots (`Addr` slots, recorded temporaries); such addresses also keep objects alive in a collection. A long activation also recycles between instructions (`Machine::reclaim`, before a native call, `new` or `deallocate`, once `Heap::reclaim_due`), counting the live `Ptr` registers too | Addresses have no generation (#81); a loop without a wait kept every freed slot (#355) | `docs/decisions.md` "IR and interpreter" |
| A suspended process owns no registers or temporaries, except a small one: at a suspension in the root frame they go to a per-thread scratch of four sets, each named by the function of the root frame (`Machine::release_scratch`, `SCRATCH_SLOTS`), and are taken back before the next run (`borrow_scratch`; a set of the same function needs no fill); a debugged process and a wait inside a procedure keep theirs, and so does a **resident** process (`Machine::resident`, set when the process starts: no debugger, at most `RESIDENT_REGS` = 2048 registers in its root frame (16 KB; it was 48, then 256: a process above the limit copied its register file template at every activation, 14% of neorv32's L1 misses), within `RESIDENT_BUDGET`; it gives its vectors to the scratch for good at the first suspension where its temporary area has grown past `RESIDENT_TEMP` = 1 KiB): no swap, no thread-local access, no key check per activation (`fan` -240 instructions of 1460). `InterpProcess::run` goes straight to `Machine::run_quick` once a process is `hot` (started, running, no shared state, no debugger); `borrow_scratch`, `release_scratch`, `after_suspend` and the root frame's `suspend` are inline fast checks with the cold parts out of line (`*_slow`, `suspend_checks`); the scratch remembers whose root frame its registers are (`Scratch::key`: runtime and function), so the next process of the same function skips `Pre::fill` (a register defined once is never written, the others are written before they are read) | No register is live across a suspension (ir.md 1.2); a process of a small entity held 1.6 KB of dead registers, 20000 instances 45 MB (#409) | `docs/decisions.md` "IR and interpreter" |
| A process switches to its specialised copy (`Machine::specialise`, `Program::copy_of`) at activation `spec_after()` (1024; `YAVS_SPEC_AFTER=n` sets it and forces the switch whatever the tier compiled, 2 is the earliest), checked by one compare in `InterpProcess::run`'s hot path (`execs == spec_at`, `usize::MAX` when the process cannot have a copy). The first stop of that compare is activation 2, not `spec_after()`: `Machine::specialise` then sets `NativeFlags::resumed` for the process function (the tier read it for its wait for the switch, #749; the wait is gone, #754, and the flag is unused) and moves `spec_at` on to `spec_after()`; no cost on the activation path. It happens between two activations, the process waiting at its one wait statement in its root frame: the frame's function, `Machine::entry` and the resume pc (the copy's one `Suspend`) change; the variables stay where the lowered code put them (`Func::frame` of the lowered function), everything the shared optimised code kept behind them (memo flags and values, layout slots) is zeroed, the registers are filled for the copy (`Pre::fill`), a resident process stays resident if the copy's registers fit. Refused when the process is debugged, serial, in a procedure, or the shared code is compiled already (`NAT_CODE`, unless forced or the tier compiles copies: `Tier::compiles_copies`, `--tier=auto`, then the process switches from compiled shared code to its copy at once, #679: the compiled copy is a third smaller and runs 15 to 25 percent fewer cycles in heat mode); with a tier and shared code not compiled yet it switches at once (the 150 ms `SPEC_TIER_WAIT` after `set_tier` is gone, #675: the tier compiles the copy, and `sc5_fifo_repack` warm ran 7 to 10 percent slower with the wait); `AutoTier` no longer keeps the shared code of such a process from compiling for 400 ms (#673): since the shared code switches to its copy at its next activation, measured over the 42 designs of the real-world suite and the head-to-head designs the wait changed nothing (#754). A copy is a function like any, so compiled code and the tier see it by its own id; the tier's decisions about it are its process's (`AutoTier` counts time, instances and share by `Program::base_of`, #661) | The optimiser spends about 0.7 million instructions on a copy: initialisation, where every process runs once, must not pay it | `docs/decisions.md` "Specialised copies of processes" |

## 4. Invariants and pitfalls

- **Fusions stop at block starts that something jumps to** (`Code::new`, `block_start`), not at every block start: a block only a skipped `Br` reaches is run through. Code that must stop a fusion at a pc other than a branch target (a resume point is one) has to add it there. `YAVS_DUMPIR=1` prints the ops of each function (#534).

- **Determinism:** nothing may depend on thread scheduling; shared heap and shared variables are
  only touched by serial processes (kernel `ProcFlags::serial`, `proc_flags`, and
  `InterpProcess`'s `Process::serial`, which the kernel ORs in so no builder can drop it).
- **Checked i64 everywhere** through `yavs_std::arith`; never wrap, clamp or saturate.
- **Generational handles:** a stale access value is a clean runtime error. Heap *addresses*
  carry no generation: deallocated slots wait in quarantine until a suspension, or
  `Machine::reclaim` between instructions, finds no address to them (`Machine::refs`), so
  never hand out a freed slot any other way, and never recycle in the middle of an
  instruction or native (Rust locals may hold addresses there); the GC follows descriptors
  (`heap::handles_in`).
- A runtime error's `SimError::trace` is the VHDL stack as `StmtId`s, innermost first; keep it
  correct when adding call paths (natives calling back into IR).
- `reflect.rs` has a test that NATIVE.md reflection rows and the implementation agree: add both.
- A collection reads each frame's root map entry at the frame's `pc`, which must be the IR pc
  of its safepoint (`New`, `Free`, a native call, the call a caller waits in) with the
  frame's registers, slots and temporaries in the machine; anything else skips the
  collection. A dispatch that fuses or predecodes instructions, or compiled code that runs
  `New`, `Free` or calls natively, must keep that true (`docs/decisions.md` "Shared heap
  collection"). Check changes with a `gc-stress` build (section 5).
- A native that leaves handles in temporary memory records them (`Machine::temp_root`, as
  `implicit.rs` `write_arr` does for arrays of access values); a native result handle goes to
  a `Handle` register, so lowering must type it so (#422).
- `std.env.finish`/`stop` must end the calling process at once (#4).
- Tests build programs by hand (`tests/common/mod.rs`); keep them independent of `yavs-lower`.
- Code that only the watching loop (`W`) has can cost the whole loop: the register allocation of `run_ops::<false, true>` follows
  the block frequencies and calls of what is present, not its instruction count (a cold, out-of-line call behind one
  load of a `Pre` byte cost nothing; the same look with a call on the hot path cost 0.5 percent, spread over ops that have none of
  it, round 20, #750). Measure it as main-thread instructions of `--tier=auto --tier-heat=2000000000,0,16000 --threads 1`
  against `--tier=interp --threads 1` (`perf stat --no-inherit`, so the compile and sampler threads are out), and compare
  `tools/stepcount --ops --ops-fn 'run_ops::<false, true>'` with the plain loop per op. A change to `run_quick` moves the plain
  path as well: measure `--tier=interp` too.

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-interp
cargo test -p yavs-ir -p yavs-interp -p yavs-lower -p yavs-elab   # after IR or API changes
python3 tools/difftest/difftest.py --candidate yavs              # end to end against reference-simulator refs
cargo build --release -p yavs --features gc-stress                # collect at every safepoint (#422), then:
YAVS_BIN=target/release/yavs python3 tools/difftest/difftest.py --candidate yavs
```

- `gc-stress` (test builds only) collects at every `new`, `deallocate`, native call and
  suspension after an allocation, never reuses a heap slot (a wrongly freed object stays an access error) and
  panics when a process's roots cannot be located or a live register that is not a `Handle`
  holds a live handle. Run the corpus (both tiers: add `llvm`) and the library suites with it
  after changing roots, lowering of access values, the dispatch loop or compiled code; it is
  about 100 times slower, so two `synopsys/` tests exceed the harness timeout.
  Its unit tests run under it too (`cargo test -p yavs-interp --features gc-stress`, and
  `-p yavs-llvm --features llvm,gc-stress`; the CI `llvm` job does both on Linux, #500): a test that
  counts heap slots checks the live objects there instead, because no slot is reused.

- `op-census` (cargo feature, off by default, any profile) counts the ops the dispatch loop executes
  and the adjacent executed pairs, and `yavs run` prints the top 40 of each to stderr at the end
  (`op-census:` lines, `census::dump`). It is the tool for choosing fusions and superinstructions
  from data. Interpreted ops only (none that run as compiled code: use `--tier=interp`), by
  variant; a generic `Op::Step` is split by the IR instruction it runs (`Step:LEq`), which are the
  candidates for ops of their own. Pairs are consecutive in execution on one thread, jumps and
  calls included. A third table gives the time per op (`ns` from the end of one op's census work to the
  start of the next, the clock reads subtracted; `Suspend`, `Ret` of a process and the waits include the
  kernel; a hint for ranking, never a measurement); a table of the pairs where the second op follows the first in the code (`falls`: the ones a fusion can take; the pairs table also counts jumps); a table of the `Machine::load_slow` calls by running op and address space (`slow loads`: what to specialise); the ops by function (`functions`, `ops by function`; a function's code by its address, so a specialised copy is apart from its process) and by position (`ops by position`: function and op index as `YAVS_DUMPIR` numbers them, the hottest straight-line runs, #791); `YAVS_CENSUS_TOP=N` sets the length of the tables. It takes a mutex per op: about 5 times slower, so it is for choosing, never for
  timing, and use `--threads 1`. Without the feature the cost is zero in release builds.
  ```sh
  cargo build --release -p yavs --features op-census
  target/release/yavs run --tier=interp --threads 1 ... TOP 2>&1 >/dev/null | grep '^op-census'
  ```
  Sample (neorv32 single core, minimal, 30 us, 56.8 M ops): top ops `SigVal` 12.5 percent, `Stmt`
  8.8, `SigRead1` 7.6, `CmpBr` 4.4, `Drive` 3.8, `WaveBuf` 3.8; top pairs `SigVal -> SigVal` 5.3,
  `Stmt -> SigVal` 4.1, `SigRead1 -> CmpBr` 3.7, `Stmt -> SigRead1` 3.3, `SigVal -> AllocReadVec` 2.6.
- The `ops` counter (and `cb_*` of yavs-llvm) are what `crates/yavs/tests/perf.rs` bounds (root
  `AGENTS.md` section 4): when a pass or an op fusion lowers it, lower the bounds of the designs.

- A new native: row in `lib/NATIVE.md` (see `lib/AGENTS.md`), implementation in `native.rs` /
  `implicit.rs` / `textio.rs` / `env.rs` / `reflect.rs`, a test in `tests/`.
- No codes of its own: runtime errors are kernel `SimError`s with `ErrorKind::Runtime` (`E3009`)
  or `Internal` (`E9999`); the message text is what the user sees, so keep it reference-simulator-compatible.
