# AGENTS.md: yavs-interp

Read the root `AGENTS.md` first. This file is for an agent about to change
`crates/yavs-interp`. The design is `docs/design/ir.md` section 3 (dispatch, kernel `Process`,
diagnostics and stack traces, debug hooks, thread safety, elaboration-time evaluation) and
section 9; the interpreter API and the Requests log are in `crates/yavs-ir/README.md`.

## 1. Purpose and boundaries

- Executes `yavs-ir` programs: `InterpProcess` implements `yavs_kernel::Process` (heap frame
  stack, waits inside procedures), `call`/`call_shared` run code without a kernel (elaboration
  time), natives (std.standard, textio, files, env, implicit operations, `'image`/`'value`,
  `std.reflection`), VHPIDIRECT foreign calls with marshalling, generational heaps with
  precise-root GC, protected objects, and debug hooks in the style of commercial simulators.
- **The interpreter is the semantic reference** (rule 5): the JIT tier must match it exactly.
- Does not: lower HIR, build the hierarchy, schedule processes (kernel), or format values itself
  where `yavs-std` has the function (it marshals and calls `yavs-std`).
- Depends on: `yavs-ir`, `yavs-kernel`, `yavs-logic`, `yavs-std`, `yavs-ffi`, `yavs-diag`.
  Called by: `yavs-elab` (builds processes, elaboration-time calls), `yavs-lower` (tests).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| Interpreter is the semantic reference; `--threads 1`/`N` identical | Rules 3 and 5 | `docs/plan.md` rule 5; root `AGENTS.md` rule 3 |
| A signal reference of several parts is mapped part by part onto `Ctx` in one step: reads concatenate, `'event`/`'active` any part, `'last_event` the most recent, drives split each waveform value and use each part's own driver slot; the parts' table lives in temporary memory | #71, LRM 16.2.4; no kernel change, same delta | ir.md 1.8 |
| `Bindings::revision` must be set by whoever builds the runtime (elab does, from `Db::rev`): FILE_OPEN_KIND positions differ per revision (2019 has READ_WRITE_MODE second), as do INTEGER bounds and `vhdl_version` | #297 | `yavs_std::file::FileOpenKind::from_pos` |
| Memory model: untyped u64 registers, 8 address spaces, every data-dependent access bounds-checked; out-of-object is an ICE, freed object a runtime error | Fail early, no UB | `docs/decisions.md` "IR and interpreter (M2)" |
| Temporaries live until the next statement of their frame | Unconstrained results survive return without copy | same |
| Natives by NATIVE.md symbol; undefined symbol fails `Runtime::new`, defined but unimplemented is a runtime error naming it | Fail early | same; `lib/NATIVE.md` |
| An all-zero `NewFill` is a zeroed allocation (`vec![0; n]`), not a `resize`: untouched pages of a huge sparse array cost nothing (#486) | A 2^29 element `std_logic` list peaked at 567 MB | `STATUS.md` "Zeroed large arrays" |
| Heap: generational handles, precise roots (`Func::roots`), mark and sweep at suspensions; skip collection rather than be unsound | Rule 6 | `docs/plan.md` rule 6, ir.md 1.6 |
| Allocations in elaboration code run with the shared state, in methods of shared protected objects, and in everything they call go to the shared heap (`Frame::shared_alloc`, `Machine::alloc_heap`, the one allocation path) | Their objects outlive the elaboration call's private heap (#184, #246) | `docs/decisions.md` "Allocators of shared objects" |

| With a tier set, the fast loop runs in one of two forms (#432). For a function without compiled code (`NativeFlags::set`, kept by the tier; `set_tier` fills it from `Tier::ready`; `Machine::tiered` asks for the top frame's function when an activation starts) it is `exec_fast::<false>` with `watch`, also once other functions are compiled: it stores `runtime id << 32 | function` in the thread's sampling slot on entry and every `WATCH` (128) jumps, calls and returns, and hands over (`Flow::Retier`, the top frame's pc set) to `run_ops::<true>` at a call of a function with code (state 1 or 2) and at a tick when the running function has some (`look!`), so interpreted code pays about 1% for the tier (#480: sending every activation of an uncompiled function through the full loop once anything was compiled cost 6 to 10%). `run_ops::<true>` (monomorphised) on entering a function (also calls and returns inside the loop) stores the slot, and asks `NativeFlags` (one byte per function, no virtual call: 1 compiled, 2 `Runtime::set_eager` asks `Tier::hot` once) on entry and every `RECHECK` (256) jumps while there is none; time in compiled code counts for the interpreted caller (the sampler tells compiled from interpreted through the same flags). It finds other memory objects through `TierHost::object` (`Machine::obj`/`obj_mut`, the lookup `rd`/`wr` use) and returns at the rest, which `exec` executes | Rule 5 by construction; the debug loop never runs compiled code; frames always materialised | `docs/decisions.md` "LLVM tier: side exits", ir.md 5 |
| Without a debugger or a compiled tier the interpreter runs predecoded code (`pre::Code`, `Machine::run_ops`): the common instructions (`Load`, `Store`, `Index`, `Pos`, `Bin`, `BinRange`, `Cmp`, `Check`, `Move`, `Br`, `CondBr`, `Stmt`, `SigVal`, `DopeLen`, `Alloc`, `LayoutOf`, `Const`, `Deref`, `Field`, `LGet`, `LSet`, `Copy`, `CopyConst`, `MakeDope`, `SubtypeCheck`, `Call`, `CallProt`, `Ret`, `CallNative`, `SigReadScalar`, `WaitOn`, `Suspend`, `Drive`, and the scalar `std_logic_1164` natives `Gate` and `NotL`) are ops of the loop, sharing their bodies (value-level helpers, failure texts in cold `*_fail`) with `step`; common sequences are one op (#443: `Stmt` runs, `Stmt` + frame load, two frame loads, a frame load and the compare-branch on it, a frame store + `Stmt`, `Br` or `IndexImm`, `Move` + jump, `Pos` + `Index` + load or store, `Index` + load or store; `pre::Lin`, `pre::lin_run`), exact because the fast path takes atoms within 2^30 (no intermediate can overflow) and every other case (a big value, an index outside its range, a failing read) runs the run's IR instructions as they are (`Machine::aff_replay` from `Code::aff`, failures included, at their pcs); the `peephole` pass over the finished ops makes `WaveBuf` of `Alloc` + `Store` + `Index` by 8, `ReadPL`/`ReadPR` of an `AffPL`/`AffPR` and the `SigRead1` that alone reads it, and `LSetDrive` of the `LSet` of element 0 of such a waveform and the one-element `Drive` of it (a scalar logic assignment goes to the kernel without the waveform's planes; any other target runs the two instructions, `replay_lset_drive`), each only within a block and never entered in the middle (the optimiser's register sharing gives one register several short values, so `LSetDrive` does not ask a register to be used once in the whole function but that the waveform buffer is read by exactly its three instructions between its `Alloc` and the `Drive` and by none after it, `pre::waveform_is_private`, `pre::live_after`); a frame load of an element offset and the `SigRead1` of it is one op, `SigRead1Slot`; `BinRangeK` is a `BinRange` with constant 32-bit bounds; `Bool`, `LCopy`, `Cat` (a concatenation; the op reads its operands from the IR at its pc) and the one-range `SigRead` of a vector (`SigReadVec`) are ops, `Cmp` + `Not` + `CondBr` is a `CmpBr` with the opposite mask); | Fused ops are made by a pass over the resolved ops (`pre::superops`) that replaces the first op of a sequence and leaves the others in place; a fused op steps `k` over the ones it did (`k += n`) or jumps. Search loops (`pre::SCAN`) run in `Machine::scan_loop`, which hands the generic ops anything unusual. A new fusion must keep faults at the IR pc of the failing part and keep writing registers something else may read. | Frames live on stacks, not in vectors of their own (#438): `Machine::regs` is one register stack (`Regs`: `regs[r]` is register `r` of the top frame, `regs.v` the whole stack), `Machine::root` holds the slots of frame 0 (a process's variables, which outlive suspensions) and `Machine::sstack` those of the other frames; a `Frame` has `rbase`, `sbase`, `slen` into them. Only `push_frame(f, func, link, ret)` and `pop_frame` change `frames` and the stacks (never push or pop `frames` directly); `fslots(i)`/`fslots_mut(i)` give frame `i`'s slots (`run_ops` reads frame 0's straight from `root`: `fslots!`). A `FRAME` address is the frame index, so stacks may reallocate. A suspension in the root frame hands `regs.v` and `temp` to a per-thread scratch. `Inst::Call` of a function (`Machine::call_pre`; `call_regs` is the id-keyed form compiled code's `Call` uses) copies arguments from the caller's registers into the callee's slots and the fast loop enters the callee and leaves it without returning to `exec_fast` (without a tier it keeps the function, code and return op of the eight innermost callers it entered in locals, so a return looks nothing up; a call reads the callee's parameters, frame size and first op from its `Pre`, not from the function). The `TierFrame` carries the whole register stack and the whole slot stack of the top frame (`regs_at`, `slots_at`, `slots_len`; use `regs_mut`/`slots_mut`): a compiled function's access to a frame between 0 and the top goes through `step`. Also in `Machine`: the argument cells of the other calls (`cells`) and the last `LayoutOf` per type (`layouts`, reused while the descriptor bytes are equal) | Call and return cost (~77 ns to ~33 ns per call of a one-line function); no per-call allocation or vector moves; results unchanged (#386, #438) | `STATUS.md` "Interpreter run time", "Interpreter calls" |
| Memory the protected-object code lives in is read and written without the error paths: `mem_fast`, `load`, `store`, `put`, `store_idx` and `copy_fast` know the shared heap (`SHARED_HEAP`), the shared variables (`SHARED`) and, for reads, package data (`PKG`); `deref` looks at the heaps as they are (an absent shared heap goes to `deref_other`). ## 4. Invariants and pitfalls

- **Determinism:** nothing may depend on thread scheduling; shared heap and shared variables are
  only touched by serial processes (kernel `ProcFlags::serial`, `proc_flags`, and
  `InterpProcess`'s `Process::serial`, which the kernel ORs in so no builder can drop it).
- **Checked i64 everywhere** through `yavs_std::arith`; never wrap, clamp or saturate.
- **Generational handles:** a stale access value is a clean runtime error. Heap *addresses*
  carry no generation: deallocated slots wait in quarantine until a suspension, or
  `Machine::reclaim` between instructions, finds no address to them (`Machine::refs`), so
  never hand out a freed slot any other way, and never recycle in the middle of an
  instruction or native (Rust locals may hold addresses there); the GC follows descriptors
  (`heap::handles_in`).
- A runtime error's `SimError::trace` is the VHDL stack as `StmtId`s, innermost first; keep it
  correct when adding call paths (natives calling back into IR).
- `reflect.rs` has a test that NATIVE.md reflection rows and the implementation agree: add both.
- A collection reads each frame's root map entry at the frame's `pc`, which must be the IR pc
  of its safepoint (`New`, `Free`, a native call, the call a caller waits in) with the
  frame's registers, slots and temporaries in the machine; anything else skips the
  collection. A dispatch that fuses or predecodes instructions, or compiled code that runs
  `New`, `Free` or calls natively, must keep that true (`docs/decisions.md` "Shared heap
  collection"). Check changes with a `gc-stress` build (section 5).
- A native that leaves handles in temporary memory records them (`Machine::temp_root`, as
  `implicit.rs` `write_arr` does for arrays of access values); a native result handle goes to
  a `Handle` register, so lowering must type it so (#422).
- `std.env.finish`/`stop` must end the calling process at once (#4).
- Tests build programs by hand (`tests/common/mod.rs`); keep them independent of `yavs-lower`.

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-interp
cargo test -p yavs-ir -p yavs-interp -p yavs-lower -p yavs-elab   # after IR or API changes
python3 tools/difftest/difftest.py --candidate yavs              # end to end against reference-simulator refs
cargo build --release -p yavs --features gc-stress                # collect at every safepoint (#422), then:
YAVS_BIN=target/release/yavs python3 tools/difftest/difftest.py --candidate yavs
```

- `gc-stress` (test builds only) collects at every `new`, `deallocate`, native call and
  suspension after an allocation, never reuses a heap slot (a wrongly freed object stays an access error) and
  panics when a process's roots cannot be located or a live register that is not a `Handle`
  holds a live handle. Run the corpus (both tiers: add `llvm`) and the library suites with it
  after changing roots, lowering of access values, the dispatch loop or compiled code; it is
  about 100 times slower, so two `synopsys/` tests exceed the harness timeout.
  Its unit tests run under it too (`cargo test -p yavs-interp --features gc-stress`, and
  `-p yavs-llvm --features llvm,gc-stress`; the CI `llvm` job does both on Linux, #500): a test that
  counts heap slots checks the live objects there instead, because no slot is reused.

- A new native: row in `lib/NATIVE.md` (see `lib/AGENTS.md`), implementation in `native.rs` /
  `implicit.rs` / `textio.rs` / `env.rs` / `reflect.rs`, a test in `tests/`.
- No codes of its own: runtime errors are kernel `SimError`s with `ErrorKind::Runtime` (`E3009`)
  or `Internal` (`E9999`); the message text is what the user sees, so keep it reference-simulator-compatible.
