# AGENTS.md: yavs-ir

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-ir`.
The design is `docs/design/ir.md` section 1 (and 2, 9); what is stable vs still moving, the
calling and native conventions, and the Requests log are in `crates/yavs-ir/README.md`.

## 1. Purpose and boundaries

- The register IR: `Program` (functions: processes, subprograms, elaboration bodies, thunks),
  runtime type descriptions (`Ty`, descriptor-based layouts, bit-plane logic arrays), the compact
  constant pool, the global statement table (`StmtInfo`), natives by `lib/NATIVE.md` symbol,
  foreign references, check messages, case tables, coverage items, reflection descriptions.
  Built once by `ProgramBuilder`/`FuncBuilder`, verified, then immutable and `Send + Sync`.
- Does not: execute (`yavs-interp`), lower HIR (`yavs-lower`), elaborate (`yavs-elab`), or JIT
  (`yavs-llvm`, M6). It has no VHDL front-end knowledge.
- Depends on: `yavs-diag`, `yavs-kernel` (`StmtId`), `yavs-ffi` (foreign signatures). Called by:
  `yavs-lower` and `yavs-elab` (producers), `yavs-interp` (consumer); later `yavs-llvm`.

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| 32-bit ids, register reuse, linear-time passes; a unit too big for LLVM stays interpreted | Rule 5 | `docs/plan.md` rule 5, ir.md 1.1 to 1.2 |
| Every instruction carries a `StmtId` (span, statement id) | Stepping, coverage, DAP, stack traces | `docs/plan.md` "Designed for the GUI", ir.md 1.1 |
| Constraints are runtime descriptors on every composite; static ones are pool constants | Rule 1 | `docs/plan.md` rule 1, ir.md 1.3 |
| Registers are untyped u64 cells; addresses `[space:3 | index:29 | offset:32]` over eight spaces; out-of-object access is an ICE | Memory model | `docs/decisions.md` "IR and interpreter (M2)", ir.md 1.4 |
| A signal reference is two registers: one range of one instance signal, or (`SigParts`) a table of parts with a driver slot each; sliced only with `SigSlice` | Individually associated signal formals across signals (#71) without changing the calling convention | ir.md 1.8, `docs/decisions.md` "Multi-part signal references and port converters" |
| Logic arrays are bit-planes; BIT/BOOLEAN elements use the std_ulogic codes of '0'/'1' | Shared plane ops (orchestrator, 2026-10-18) | `docs/decisions.md` "Interpreter: BIT/BOOLEAN codes" |
| Constant aggregates are compact (`ConstData` run-length / `others`) | Rule 12 | `docs/plan.md` rule 12 |
| Natives named by `lib/NATIVE.md` symbol; `'image` is `yavs.attr.image` | One symbol table | `docs/decisions.md` "IR and interpreter", `lib/NATIVE.md` |
| Foreign calls without libffi through `yavs-ffi`; arrays as C-layout copies, records as aligned structs | ir.md 1.7 | `docs/decisions.md` "IR and interpreter" (Foreign arrays) |
| Verifier checks register liveness across suspension within a block only | Cross-block needs dataflow (JIT tier) | `docs/decisions.md` "IR and interpreter" |
| The optimiser runs lazily per function on the first `Program::func`; the unoptimised code stays in `Program::funcs`. A function's version is fixed at its first use, because frames find their function by id and a pc must keep its meaning. One exception: under `ElabRaw` (elaboration-time calls, `pkgcall::run_with`) a function or procedure that cannot suspend is handed out as lowered and counted; at 64 requests it is listed (`take_hot`) and optimised by `yavs_interp::Runtime::promote_hot` between two calls, when no frame runs the lowered code, and the runtime's `pre` and `live` for it are dropped. A lowered function also counts its jumps back (`Program::back_edge`, `BACK_BUDGET` 2048 over all calls): at the budget it is listed too, and a call that has only computed restarts with it optimised (`ElabRaw::restartable`, `no_restart`; the loop is `pkgcall::run_restarting`) | #427, #539, #695 |
| The optimiser never removes a store, a `Stmt` or a `Cover`, never lets a register live across a suspension, forgets memory facts at every `Stmt` (a debugger may write a named local) and drops a check only when it provably passes | Stepping, coverage, DAP, identical runtime errors | #427, ir.md 9 |
| A frame slot becomes a register (`Opt::promote`) only in a `Function` or `Procedure` that cannot suspend and has no nested subprogram, only if every access is a direct `Load` or `Store` of the same width and register class, its address never escapes (`escapes`), no root map covers it (except a handle or address root whose every access is exactly a `Handle` or `Ptr` register, which the collector finds as live registers) and no `Sig`-wide access overlaps it; a slot inside a named local only while `opt::keep_variables` was not called (the CLI calls it for `--dap`, `DebugSession::new` for library users, before any function is optimised). Registers that some path reads before writing get a zero (or the parameter's value) at the entry. Blocks no branch reaches (and every block of a function that may suspend counts as reached) do not count as definitions and are emptied at the end. Last: `Stmt` markers whose statement may not allocate temporary memory are dropped in subprograms and processes without a debugger (`may_allocate` lists the instructions that never do, signal reads, signal references and drives among them; a new instruction is assumed to allocate. Waits and `Suspend` stay off the list: the predecoder's `static_wait` and compiled code's short cut start a wait at its `Stmt` and need the marker, #588), equal single-definition constants and preloaded addresses are merged, and registers are renumbered densely (an instruction operand the instruction does not read, such as the second operand of `Bool Not`, is pointed at a register that exists: the interpreter reads the cell) | Loops loaded and stored the same slots on every pass (a quarter of the executed instructions in the verification-library testbenches); a debugger reads and writes variables in their slots | #444 |
| The storage of a local composite variable of a subprogram that cannot suspend is `Inst::NewFrame` (pinned temporary memory, not a heap object): once per call, no handles in the type, the handle only dereferenced or stored into the variable's handle slot, no debugger | A heap object per call cost an allocation, a copy and collection work; a result pointing into it lives as long as any temporary result (#444) | `docs/decisions.md` "Local composite variables live in the frame's temporary memory" |
| Descriptor lengths and layouts are facts of the walk (`Key::Dope`, `lwords`): a `MakeDope` of constants, a pool descriptor or a layout of a one-dimensional array type under a descriptor of known length fold `DopeLen`, the null test, an equal-length `SubtypeCheck` and the loads of the layout words; a block only `MakeDope` writes is dropped (`dce`); `Cat`, `LCopy`, `LSet`, `LFill` and `SigRead` forget only their own `Cls::Block`; positions, checks and range-checked arithmetic repeated with another message are one expression; a `Select` on a constant or with equal operands is a `Move`; after a pass that folded a branch up to four more run; code that suspends has its blocks reached from the entry (`reachable`) | Straight-line vector code (a shift register, a slice read) goes from 30 instructions per operation to a few | #443, `docs/decisions.md` "Concatenation instruction and descriptor-length folds" |
| Layout words that do not depend on the descriptor are constants: the size, alignment and field offsets of a record without a descriptor (`static_words`) and the stride (word 2) of a one-dimensional array whose element size does not depend on the bounds (`static_stride`, checked for three lengths); a `LayoutOf` only they read goes, and with it the statement marker that kept its temporary | The element stride of every access to an array of records was a layout read (#493) | `opt.rs` `lstride` |
| A `NewFrame` copy of constant size that only constant-offset loads read (a local record variable initialised from a table element and never written) is not made: the loads read the source (`forward_frame_copies`), provided every instruction between the copy and the load is a read, a computation or a branch (a statement marker only when the source is in a heap or the constant pool) | A copy per call of every method of a pointer table (#493) | `opt.rs` |
| Loop-invariant code motion (`opt/licm.rs`) runs in a function or procedure that cannot suspend, and on the loops of a process that hold no suspension (no `Suspend`, no call that may suspend; #541), without a debugger and before inlining. A loop is the natural loop of a back edge with a single entry (not the function's entry block); loops are taken inner first, and a header shared by several back edges is split (the latch with the smallest loop keeps it, the entry and the other back edges go through a new jump block) so that nested loops get a preheader each. A computation moves to the preheader when its operands are not written in the loop and its result register is defined once. One that can neither fail nor read memory (`speculable`: constants, moves, compares, selects, addresses) moves from anywhere in the loop. One that can fail (positions, checked arithmetic, checks) or reads a descriptor (`Pos`, `DopeLen`: only when nothing in the loop writes memory a descriptor can be in, logic element writes excepted) moves only from the start of the header up to its first instruction with an effect, and the preheader then runs that start as the first pass would: the moved instructions in order between copies (fresh results) of the ones that stay and can fail, so the first failure and its message are the ones of the unmoved code. Moving such instructions stops at the point where the most moved instructions outweigh the copies. Loads are not moved, except from read-only memory (instance data, constant pool) at a constant address, which move like a constant | Index and descriptor arithmetic of nested array loops was recomputed per element; failures must stay identical (#526) | `docs/decisions.md` "Loop-invariant code motion" |
| A call is inlined (`opt/inline.rs`) only when the callee is a function or procedure of the plain kind (not nested, no nested subprogram, no static link, no suspension) with parameters of 8 bytes passed in, at most 24 instructions in one path or 60 in at most 8 blocks after its parameter loads (read at the start of the entry block): reads, computations, checks, calls, branches, coverage counters (`Cover`, `CoverIn`, `CoverCond`: they add to the running instance's row, so inlined they count the same, and they do not count against the size limits, #699) (a `Case` of at most 6 arms becomes compares: the program's case tables cannot grow), no frame slot but its parameters', no allocation, and the caller a function, procedure or process without a debugger. The callee's `Stmt` markers go (a new frame has no temporaries to free), its parameters are the arguments' registers where the body never writes them (a `CallProt` passes the object as the first), its result is made in the call's result register or, with branches, moved there before a jump to the block that holds the rest of the call's block. Blocks are appended after the caller's last (existing ids are named by the program's case tables and cannot move). The callee is the forwarder of its level: level 0 its optimised body, level 1 that body with the calls inlined that level 0 makes inlinable (so a wrapper in front of a method is one callee), which stops cycles and does not depend on the order functions are first used. An inlined instruction keeps the statement of the callee and `Func::via` the chain of (call statement, callee) pairs from the innermost call out (`Func::inlined_chain`), so `Machine::trace` and `std.env` call paths list each callee as a frame of its own; the verifier accepts each callee's statements there. After inlining into a function or procedure the walk of the optimiser (`tidy`) runs once more over the result | A call costs about 500 host instructions and a library testbench is a chain of subprograms in front of protected methods (#493, #509); traces are part of the CLI contract | `docs/cli-contract.md` 5 |
| A `TempRoot` of a fat pair (`ty: None`) goes when the pair is in a block this function allocated and the two words stored into it just before (within 16 instructions of the same block, only pure instructions and stores to other allocated blocks between) are addresses of the frame, the constant pool, instance data or temporary memory, or constants whose tag is no heap's: `Machine::fat_root` would record nothing (`opt.rs` `drop_clean_roots`, #565). A word of unknown origin (a loaded pointer, a native's result) keeps the root | A string built for a native call or a report is such a pair; compiled code stepped each root, and every `Stmt` after it while roots are recorded (116 million exits in a testbench of 8 million assertions) | `docs/decisions.md` "Host callbacks of compiled code" |
| Memory facts about instance data and the constant pool (`read_only`) are never forgotten: nothing writes them while a subprogram or process runs | Repeated loads of an instance constant's address and descriptor in loops, and repeated positions in an instance signal array | `docs/decisions.md` "Optimiser round 11" |
| A register defined more than once has a version per definition on the walk's path (`Opt::vsn`, `Opn::V` in keys, `Val::V`), and a constant or address it holds is known until it is written again (`Opt::mval`); `define` bumps the versions of the results of every walked instruction and records what is known. The versions are undone when the walk leaves a block, so siblings of an extended basic block do not see each other | Loop counters and promoted variables took part in no sharing; #511 | `docs/decisions.md` "Optimiser round 11" |
| Registers share cells by live range (`opt/share.rs`): never a signal reference, a register a frame starts with (defined once by a constant or an address), a fusable compare/index/position/layout/signal-value temporary, the temporaries of a linear run (a `Bin` add/sub/mul, `Pos` or `DopeLen` defined once and read in its block: the predecoder fuses them only if defined once), or two classes (`I64`, `F64`, `Ptr`, `Handle`) | The collector's register types, the must-defined check and the predecoder's read counts rely on it; frames shrink by a fifth to a quarter | #478, `docs/decisions.md` "Registers share cells by live range" |
| In a process the intervals hold within one activation: a suspension resets the registers and, for the slots of variables, to the interval all stores keep them in (`docs/decisions.md` "Intervals and register promotion in processes"); a slot no suspension leaves live is promoted; `opt::external_variables` (VHPI, `--wave-variables`) keeps named variables in memory and unknown after a suspension; a process that registers no wait never resumes (the verifier knows) | Loops in processes loaded, stored and checked their variables on every pass (#444) | `docs/decisions.md` "Intervals and register promotion in processes" |
| Integer registers get intervals (`opt/range.rs`) and a check is dropped, a compare or branch decided, only when the interval proves it; arithmetic overflow is a runtime error, which bounds every result by `i64`. Definitions of registers defined once are never removed by liveness (`opt/live.rs`): frames start with their constant or address | Concatenations and counters were checked and selected on lengths that cannot be negative (#444) | `docs/decisions.md` "Interval analysis, jump threading and dead register definitions" |
| Array elements of an integer type within 32 bits are 4 bytes (`Ty::elem_size`), scalars 8; `Width::B4` loads sign-extend | Memory and cache of integer arrays (R12, #415) | `docs/decisions.md` "Narrow integer storage" |
| A slice's start position is `Inst::SlicePos` (null slice: 0 and no check; else `Pos` of both bounds and the direction check), not a branch; the memo pass (`opt/memo.rs`) keeps a descriptor built from instance constants (`Alloc`, one `MakeDope`, reads only) in frame bytes (`K::Dope`) and lets the state after the join of an `if` on an instance-constant condition be what both arms agree on | A slice with generic bounds in a process cost a dozen operations per activation and cut the statement into blocks the memoisation could not plan (#520) | `docs/decisions.md` "Slice positions, memoised descriptors and static waits over slices" |
| A specialised copy of a process (`copies.rs`) is a function of the program in a slot reserved at its end, so every table indexed by function (the runtime's, the tiers') already has its place and no lookup of a copy costs more than that of any function (a table that grows after the runtime exists cost 50 to 100 instructions per activation of a switched process in the first version; slots that never get a copy cost about 1 KB each). The optimiser folds a load from instance data (`Opt::inst`, `const_read`) only into an integer register (a pointer or handle register keeps its load: the roots rule), never from the bytes of a `for` generate's parameter, and never when instance data are not frozen yet (`specialise_on`: off for `--dap`, VHPI and wave variables, `--tier=llvm`, `YAVS_NO_IROPT`). Slots are not stored with a program (`Func::spare`); optimised copies are stored apart (`export_copies`), never among the functions' (`export_optimized` skips spares) | The tables of the runtime and of the tiers are sized once; copies made lazily during a run | `docs/decisions.md` "Specialised copies of processes" |
| The declarative part of a process copy is run per copy on an abstract machine (`opt/decl.rs`) and the frame words the body never writes become facts (`Opt::wf`, `Opt::rdesc`): scalar words fold to constants (into integer registers only), address words to `AddrOf`, the pointer to a record variable's heap descriptor to a register whose bytes are known, so `DopeLen`, `Pos`, `SlicePos`, `SubtypeCheck`, descriptor loads, `LayoutOf` (any type whose descriptor bytes are known, shared code included, via `known_layout`/`read_at`) and `Field` (from `lwords`) fold. Unmodelled instructions, calls and pointers stored where the machine cannot see make what their operands reach unknown for good (`Mem::poison`); an unknown branch, a load of an unknown word out of memory that holds pointers, or 50 000 steps give no facts; only descriptors (heap objects', array variables' in the frame) are taken as never written after the declaration | The body of `iu3` read the descriptors of its record variables through frame slots and recomputed every layout and field offset (551 `LayoutOf` and 653 `Field` in the interpreter copy, #678) | `docs/decisions.md` "Facts the declarative part leaves in a process copy" |
| A zero-delay drive of a process that a later zero-delay drive of the same elements deletes (`opt/drives.rs`) is delayed down the control flow as partial dead code elimination: dropped where the second drive follows, copied (fresh registers) to the end of the other paths, before the first instruction that can see the driver's transactions (a drive onto overlapping or unknown elements, `DriveSlot`, `SigScatter`, `Disconnect`, `Force`, `Release`, `Driving`, `DrivingValue`, a procedure, protected, indirect or foreign call), in front of the `Stmt` of a wait, never into a cycle or past a join that some path enters undelayed, at most six copies; the unit that moves is the drive with the instructions that build its waveform (none can fail, none reads memory but signals and what it allocates); two drives are the same when instance signal, offset (constant or register defined once) and constant length are, the driver slot not being part of it (two slots of one process on the same elements are one kernel driver) | The second drive deletes the first's transactions at the same time (LRM 10.5.2.2); 17 percent of the drives of a CPU testbench were such repeats | `docs/decisions.md` "IR optimiser round 13" |
| A repeated `to_integer` of an `unsigned` (`opt/sink/calls.rs`) is called once: the later call runs only when the first returned 0 (a null or metavalue argument returns 0 with a warning, so a nonzero result proves the later call silent and equal), with its own argument code moved in front of it by `sink`. ## 4. Invariants and pitfalls

- **Breaking the IR breaks three crates.** `README.md` "Stable" lists what producers rely on;
  record any change under "Changes" (an exhaustive `match` on `ForeignArg` or `Inst` needs new
  arms in `yavs-interp` and `yavs-lower`).
- **The IR is serialised (`Program`, `ProgramBuilder`; the compilation cache stores lowered packages, #407).** A new type reachable from them derives `serde::Serialize`/`Deserialize`; derived caches (`Func::opt`, `Program::layouts`) are `#[serde(skip)]` and rebuilt on use. `ProgramBuilder::fingerprint` (the identity of the ids handed out), `callers_of` and `undefined_funcs` serve the library stages (`docs/decisions.md` "Library stages"). Big byte strings go through the `bytes` module of `program.rs` (a sequence of numbers decodes at a byte per call).
- **A stored program may hold function bodies as bytes (`yavs_ir::lazy_bodies`, #481).** `Program::funcs` entries of a program read that way have their header only (`code`, `loc`, `operands`, `resume` empty): read a function through `Program::func`, or through `Func::full` when you need the lowered code of an entry of `funcs` (the optimiser and the verifier do). The serialised form of `funcs` is the one in `program.rs` `funcs`; a new field of `Func` that is part of the body goes into `Body`/`BodyRef` there.
- Verifier errors are ICEs of the producer: never relax the verifier to make lowering pass
  without an ir.md note.
- The descriptor format and the fat pair `[data, dope]` for unconstrained results are shared with
  `yavs-lower`, `yavs-interp` and `yavs-elab`; change all of them together.
- Element order inside logic leaves: row-major position `p` is kernel offset `n - 1 - p`
  (`docs/decisions.md` "Elaboration"); lowering of non-static indices must match
  `NetGraph::select`.
- Heap addresses carry no generation; the interpreter quarantines deallocated slots instead
  (#81, `docs/decisions.md`).
- Precise roots (plan rule 6, #422): a register holding an access or protected handle is
  `RegTy::Handle` (the verifier wants one for `New`, `Deref`, `CallProt`; an `I64` operand
  takes it too), a frame slot holding a handle or a heap address is in `Func::roots`
  (`RootKind::Handle`, `Composite`, `Addr`), and a temporary that holds handles or heap
  addresses is recorded by `Inst::TempRoot`. An emitter that keeps a handle anywhere else
  makes the collection inside an activation free a live object. The optimiser (`opt.rs`)
  never replaces a `Handle` register by another register (`Opt::single` takes `I64` and
  `Ptr` only); replacing one by an `I64` would hide a root.

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-ir -p yavs-interp     # IR tests plus end-to-end designs on the interpreter
cargo test -p yavs-lower -p yavs-elab                       # producers
```

- New instruction: add it to `inst.rs`, the verifier, the dump, the interpreter (`yavs-interp`
  `exec.rs`) and a test in both crates; note it in README "Changes".
- No diagnostic codes: verifier failures surface as `E9999` ICEs of the producer.
