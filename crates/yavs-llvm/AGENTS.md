# AGENTS.md: yavs-llvm

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-llvm`.
Binding choices are in `docs/decisions.md` "LLVM bindings: llvm-sys 211, no inkwell"; Windows
in `crates/yavs-llvm/WINDOWS.md`; measurements in `docs/STATUS.md` "llvm".

## 1. Purpose and boundaries

- The **LLVM tier** (M6): `compile(&Program, OptLevel, max_size) -> LlvmTier` lowers every
  non-elaboration IR function to LLVM 21 and JITs it through ORC LLJIT (portable CPU, O2, Rust
  runtime callbacks as absolute symbols). `LlvmTier` implements `yavs_interp::Tier`; `yavs run
  --tier=llvm` sets it on the runtime. Design: `docs/decisions.md` "LLVM tier: side exits to the
  interpreter".
- Compiled code runs on the interpreter frame's registers, slots and temporary area
  (`yavs_interp::TierFrame`, a `#[repr(C)]` view of the machine's stacks the interpreter keeps
  current). Inline: `Cover` (one atomic add on `TierFrame::cov`, #692), `CoverIn`, `Const`, `ConstF`, `Move`, `Bin`/`BinRange` (not `**`), `Un`, `FBin` (not
  `**`), `FUn`, `IToF`, `Cmp`, `FCmp`, `Bool`, `Check`, `FCheck`, `Index`, `Br`, `CondBr`,
  `Case`, and with a slow path that steps the instruction: `AddrOf` (`Up` one or two levels
  through the view), `Load`, `Store`, `Copy`, `Alloc`, `Stmt`, `MakeDope`, `DopeLen`, `Pos`,
  `SubtypeCheck`, `Field`, `LayoutOf` (types whose element layout is static), `LGet`, `LSet`,
  `LCopy` (up to eight plane blocks each side, through `yavs_rt_lcopy`, which runs the
  interpreter's `yavs_interp::copy_bits`), `Deref` (through `yavs_rt_fast`, `TierHost::deref`), `MemEq` (`yavs_rt_memeq` on the bytes `Mem` found), `SigVal`, the scalar `std_ulogic` natives as
  tables (`yavs_interp::code_table`), a `Cat` of non-logic elements (`Gen::cat_bytes`, as on a native frame), a `LayoutOf` of a one-dimensional array of static element layout (`Gen::layout_words`), and a `CallNative` of a native `yavs_interp::direct_native` allows through `yavs_rt_native` with `NATIVE_FRAME_MODE` (`TierHost::native_frame`: the argument cells from the registers, the result into one register, no frame view, no flush or reload of the other registers; where it declines the call is stepped; #565); `math_real.uniform` (three scalar registers, no result) is computed in place instead (`Gen::uniform_fast`, #519). Memory is reached through `Mem` (the view plus a direct-mapped
  table of 16 384 objects `yavs_rt_host` asked `TierHost::object` for, keyed by the address high half or-ed with the tag of its space (`Mem::tags`, `Mem::slot`; entry `obj_at(hi)` xor the tag's offset `Mem::mixes`), looked up inline by every access of unknown space, with the access value a `Deref` found each one for, so a `Deref` of a handle found before is inline; a tag stands for whose objects they are, and a new tag drops them all at once (no walk): frames and temporaries until the next host call (`Mem::forget`, `forget_end`), heap objects of a machine while its `TierFrame::heap_epoch` and `shared_epoch` are unchanged, or for the slots the heaps' change logs (`Heap::log`, `TierFrame::heap_log`, the last `HEAP_LOG` changes) do not name (`Mem::drop_changed` drops only those entries; a heap more changes on gets a new tag), #520, instance and package data of a machine (`TierFrame::owner`), constants (`Life::Runtime`) of a runtime (the runtime id is in the high bits of `owner`); the objects of every machine stay in the table across other machines' activations, a process's record (`TierState`) holds the table's identity, its heap epoch and its two tags (`Mem::begin`, `Mem::save_tag`), #510, #634, #679; frame, temporary and instance
  addresses are found inline (frame-mode code asks `yavs_rt_host` for an address of unknown space, #634, except where `rt::track` has a guess: `Known::LikelyTemp` and `Known::LikelyHeap` get one inline test of the temporary area or the object entry first, `Gen::host`, #711; a native frame tests `LikelyTemp` first too, then its chain, #757), and a constant the generator knows (`Known::Const`) is read from a
  private copy in the module, `Gen::const_global`). Through the `yavs_rt_signal` callback
  (`TierHost::signal`: the interpreter's own functions without its generic step):
  `SigRead` (one range), `SigGather` and `SigScatter` of a frame-mode function (#790), `Drive`, `DriveSlot` (one range), `WaitOn` and
  `WaitFor` (each with the `Suspend` after it), `Suspend` and the `rising_edge`/`falling_edge`
  natives (#339); `SigReadScalar` of a logic signal that keeps its codes, and `rising_edge` /
  `falling_edge` of the edge the kernel resumed the process for, are read in place from
  `TierFrame::sigtab` and `known_*` (`Gen::sig_read_scalar`, `Gen::edge`; the callback is their slow
  path, #440). The same callback runs the instructions that only change the temporary area or one register without the generic step and without forgetting the cached objects: `TempRoot`, `Stmt` (when roots are recorded), `NewFrame`, and the slow paths of `Deref` and `MemEq` (`Gen::step`); a `TempRoot` of a fat pair asks `yavs_rt_fast` (`FAST_FAT_ROOT`) first and records nothing when no word points into a heap (#432). Every other instruction runs in place through
  the `yavs_rt_step` callback (`TierHost::step`): calls, the other natives, foreign calls, reports, the
  other signal operations and waits; a frame a call pushed runs its compiled code directly from
  the callback and is popped by `TierHost::ret` (#336). Compiled code returns to the interpreter
  at `Ret`, every guard failure (overflow, check, zero divisor, non-finite real, address over
  4 GiB, re-executed by the interpreter for the identical error), and with `TIER_UNWIND` /
  `TIER_SUSPEND` when frames it pushed are left to the interpreter or the process suspends. The open native lowerings are issues (section 6).
- `AutoTier::start_deferred` + `launch` (`yavs run --tier=auto`: the tier exists at once, the compile thread is created by `launch`, which the CLI calls from the signal thread after `START_AFTER`, 5 ms, so a run under 5 ms creates no compile thread, #426; `stop` needs no launch and a launch after it does nothing). `AutoTier::start` is both with the 5 ms wait inside the thread (the tests). The thread, once launched, reads the cache's list and samples (#426) compiles at O2, on one background thread, the
  functions where the sampled interpreter time reaches their kind's payback (`Model::payback`) times their estimated compile
  time (2 for a function the interpreter calls on a native frame), with their small callees (`Worker::tree`), and only while the compile time spent is at
  most `Heat::budget` percent (2; fifty times that for a compute loop, `compute`, which also needs two times its compile time seen) of the interpreter
  time the sampler saw (`Worker::pick`, #432). With the hidden `--tier-heat` there is no budget
  and the first level is O0, those still hot in their compiled code compile again at O2
  (`Heat::o2_threshold`);
  `AutoTier::stop` ends that at the end of the run. The
  spike (`spike.rs`) stays as the JIT smoke test.
- Everything is behind the `llvm` feature (off by default), so the workspace builds without
  LLVM 21.
- Compiled code is kept across runs in the compilation cache (`objcache.rs`, #505): the object
  file of every module, keyed by its LLVM IR, linked again instead of compiled; under `--tier=auto`
  a function's object is also found by a pre-key made before its code is generated (#785), so a
  warm run links it without generating it.
- Depends on: `llvm-sys`, `yavs-ir`, `yavs-interp`, `yavs-cache` (all optional, feature `llvm`).
  Called by: the `yavs` binary (feature `llvm`).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| The interpreter is the semantic reference: every suite must give identical output LLVM-only and interpreter-only | Rule 5 | `docs/plan.md` rule 5, "Verification" |
| LLVM 21 pinned (`llvm-sys =211.1.1`, `strict-versioning`, `prefer-dynamic`), optional feature; LLVM is an approved manual dependency | Rule 5; root `AGENTS.md` rule 9 | `docs/decisions.md` "LLVM bindings" |
| Raw llvm-sys, no inkwell | inkwell lacks ORC LLJIT | same |
| ORC LLJIT, no hand-written object loader; host functions as absolute symbols, nothing looked up in the process | Rule 5 | same |
| Portable CPU: `x86-64-v2` or `generic` aarch64, never the host CPU; `default<O2>` | Rule 5 | same |
| One `LLVMContext` per module (`LLVMOrcCreateNewThreadSafeContextFromLLVMContext`) | LLVM 21 removed `ThreadSafeContextGetContext` | same |
| Runtime errors call a Rust `extern "C"` callback and return a status; no unwinding through JIT frames | Win64 has no unwind info for them | same; WINDOWS.md |
| Shared `libLLVM-21.so` on Linux, opened on first use through generated stubs (`build.rs`); static libs from the release tarball on Windows | Link memory; llvm-sys refuses dynamic on Windows; loading it at start cost 5 ms per process (#426) | same |
| Self-contained compiled code on interpreter frames: every instruction it does not lower runs in place through `yavs_rt_step` (calls and natives included); a pushed callee with compiled code runs directly and `TierHost::ret` pops it; it returns to the interpreter only at `Ret`, `Suspend`, failing inline instructions and frames it cannot finish (`TIER_UNWIND`) | Rule 5 by construction; one implementation of frames, heap and traces; no exit per call (user decision, 2026-10-20) | `docs/decisions.md` "LLVM tier: side exits", #336, #337 |
| A non-native process function without `MAY_SUSPEND` stays in compiled code across its retreating `Br`s (`Gen::func`, `Inst::Br`): it polls `TierFrame::stop` (#737) and adds one to a local jump count (loaded from `TierFrame::spin`, the machine's `Machine::spin`, at the entry; stored back in every exit block by `spin_out`), and leaves at that `Br` on a stop request or when the count is a multiple of `yavs_interp::SPIN_CHECK`: the interpreter steps the `Br`, counts it, trims the run's lists (`Ctx::trim_run`) and reports `E3009` at the limit (10^9, `YAVS_SPIN_LIMIT`). The count and the stop flag have their own alias scopes (`AA_SPIN`, `AA_STOP`, `AA_MEM`) so a loop without calls keeps the count in a register; a count kept in memory cost 23 percent of a compute loop | Ctrl-C must end any run and the activation must be bounded (#583) whatever tier runs the process, without taking the process out of compiled code (user, 2026-10-26); the interpreter stays the one implementation of both | `docs/decisions.md` "A process that never suspends stays in compiled code" |
| Memory instructions run natively only where the bytes lie in memory `Mem` reaches and no error is possible; anything else steps the whole instruction, before any side effect | Rule 5: one implementation of address spaces and errors | `docs/decisions.md` "LLVM tier: side exits" (Memory) |
| Vector work compiled code does not inline calls the interpreter's own Rust functions directly (`yavs_rt_lcopy` runs `copy_bits`; `TierHost::signal` runs `sig_read_vec`, `drive`, `wait_for`), never a second implementation in LLVM IR; a constant known at generation time (`Bytes` form, at most 4 KiB) is read from a private copy in the module, the bytes the interpreter reads | Rule 5; constants never change; the object lookup per activation cost 5% of clocked RTL | `docs/decisions.md` "LLVM tier: side exits" (Vector process bodies) |
| GC roots: `New`, `Free`, `TempRoot`, natives and calls are stepped with the registers, slots and temporaries in the machine (compiled code stores every register at once and hands the temporary length back before a step), so a collection inside an activation sees them; frames compiled code called through wait at their call's pc; `Stmt` steps while `Mem::temp_roots` (`TierFrame::temp_roots`) is non-zero so the interpreter drops the ending statement's recorded temporaries | Precise roots in both tiers (#422) | `docs/decisions.md` "Shared heap collection" |
| Native frames for native-callable functions (`native_set`): compiled callers call them directly; the frame becomes an interpreter frame (`TierHost::materialise`) only at a step, a failing instruction, the depth limit or the native stack allowance, and the interpreter goes on from there (`TIER_UNWIND`); processes and other functions stay frame-mode; frame-mode code has entries after preloaded definitions | A compiled call cost what an interpreted one did; materialised frames keep traces, roots and errors the interpreter's | `docs/decisions.md` "Compiled frames and calls between compiled functions", #432 |
| A native frame leaves at an exit site, never through a shared block carrying every register: `Gen::leave` stores the registers live before the pc (`regs::Live`) into the function's spill buffer (an `alloca` that escapes only to `yavs_rt_deopt`) and branches with the pc; blocks of failing guards go behind the rest of the function (`Cur::cold`) | One block taking all registers through phis made the code generator copy every register on every guard edge (475 blocks, 130 phis for a 100-instruction procedure) and kept all of them live to the last guard; `--tier=llvm` ran codec loops slower than the interpreter | `docs/decisions.md` "Native frames: every exit records the registers live at its pc", #554 |
| A register `Deref` defined is a known heap address (`Known::Heap`): `Gen::host` leaves out the frame, temporary and instance tries for it; the object table key is the object index with bit 3 flipped for a shared heap, computed from an address (`obj_at`, `Gen::obj_entry`) and from an access value (`obj_entry` with `handle`) alike | A private and a shared heap object of the same index evicted each other at every access of a protected-type library function; a frame test per heap access was a third of the access | `docs/decisions.md` "Compiled memory access: heap addresses are known", #554 |

- Deferred register stores (frame mode, `regs.rs`, `Gen::std`/`flush`; decisions.md "Tight compute loops"): a pure instruction's result is an SSA value stored only where the interpreter can look at the frame, by liveness. New code that reads or writes `c.regs` directly, or calls a callback with the register pointer, must go through `call_go`/`reg_out` or call `Gen::flush(c, pc)` itself; an arm with a fast and a slow path uses `Gen::st` (immediate), never `std`. `YAVS_LLVM_DUMP=<dir>` dumps the LLVM IR before and after optimisation and the yavs IR of each compiled function. `YAVS_PERFMAP=1` writes `/tmp/perf-<pid>.map` so `perf report` names the compiled code `f<id>` / `f<id>_n` (match the ids with the `f<id>.ir` files of `YAVS_LLVM_DUMP`). `Live::new` solves liveness per basic block and sweeps the rows of each block once (#710), so a process of tens of thousands of instructions costs milliseconds, not seconds; `MAX_WORDS` (1 << 25 words, 256 MiB of rows) is only a memory guard, and a function over it gets no deferral. Code generated after a step in a slow path (`Gen::layout_keep`) reads the register the stepped instruction defined from the frame, never through `ld`/`pend`: it takes the deferred value of that register out for its length (the fast path may still read it as an input and redefines it with `st`).

- Registers and frame variables across blocks (frame mode, `regs.rs`, `Gen::edge_prep`/`edge_to`/`begin_block`, `Plan`, `Scalars`; decisions.md "Registers and frame variables across blocks"): in the natural loops of a function a deferred register is not stored at a block edge but passed to the successor's phi (`Plan::regs`/`phis`, only registers some instruction defers (`deferrable`), live into the block, not preloaded or fixed); a block reached by one edge from an earlier instruction takes that edge's deferred values as they are (`Plan::single`, `inherit`); every other block takes its registers from the frame as before, and `edge_prep` stores a deferred value no phi takes. Only the start, the pcs after a call, wait or report (`resumes`), loop headers and the preloaded definitions after them have an entry stub (loads the phi values from the frame); the interpreter that lands elsewhere gets `pc` back and runs on to the next jump (`tier_go`). A frame variable (a slot only `Load` and `Store` reach through address registers of its own, at one width, in a function no other function nests in, accessed in a loop without a `loud` instruction; at most 12) is deferred register `nregs + k`: `Gen::vslot_value` loads it once, `Store` only defines it, and it is written back by `flush_row`/`flush_exit` where something may look at the frame (`Scalars::observes` is the liveness rule: every instruction that can leave or call out). A `quiet` step (no collection, no other code: everything but calls, allocation, reports, waits) writes variables back only when it fails (`call_go`), a direct call to a native frame likewise (`native_call`). The last pend entry is the base of the frame's slots (`own_slots_cached`), carried through loops and forgotten by `call_go` and by `join` after a slow path that may push a frame (`slow_path`/`slow_signal` save and restore it: a value found in a branch does not dominate the join). New code that creates a join block of a slow path must go through `slow_path`/`join`; one that defines a deferred value between a branch and its join must use `st`, not `std`. Registers defined once by `Const` or `ConstF` are constants everywhere (`fixed_consts`).

Tuning aids: `YAVS_LLVM_TIMES=1` (per `compile_one`: LLVM instructions before and after the passes, microseconds per phase; per module in the compilation cache the `objtimes` line: key, look-up, passes, code generation, store, link), `YAVS_LLVM_PIPELINE=<pass pipeline>` and `YAVS_LLVM_ARGS=<LLVM options>` replace the defaults (an unknown option makes LLVM exit); `YAVS_LLVM_KINDS=1` (`--tier=llvm`) prints the LLVM instructions generated per IR instruction kind (frame-mode code before the passes: where the code size goes), `YAVS_LLVM_ABLATE=Kind,Kind` has the interpreter step those kinds instead (only kinds with a step path, not control flow), to measure what compiling them is worth (both hidden measuring aids); `perf stat -e cpu_core/instructions/u` on a run gives a load-independent compile cost. A module of more than `HUGE_MIN` (100 000) LLVM instructions gets `LEAN_HUGE`: `dce` for `simplifycfg` and `adce`, which grew with the square of the module (66 s and 31 s of 115 s at 7 million instructions). - Element loops on native frames (#757; `yavs_interp::elem_loops`, `eloop.rs`, `Gen::eloop_plan`, `yavs_rt_eloop_exec`, `yavs_rt_eloop`, `Cb::Eloop`, decisions.md "Element loops in compiled code" and "Element loops planned in the compiled code itself"): the loop's program is straight-line code at the head of the loop (`eloop_plan`: values as pairs, the checks of `eloop::run` as overflow flags and bounds tests, `Gen::host` for the memory (`Gen::eloop_host`: unknown space is `LikelyTemp`, the temporary area first), then the elements: a copy inside one plane block each side with equal unit steps and the blocks apart inline (four masked word moves), else one `yavs_rt_eloop_exec` call; `eloop::invariant_steps` says which programs it takes, the others and `YAVS_LLVM_ELOOP_HELPER=1` use the helper call described next, `eloop_call`). - `--tier=auto` decisions are a function of the looks (#670, #673, #680, #681; decisions.md "`--tier=auto` decisions follow the looks of a sampler thread"): the `yavs-sampler` thread (`sampler_loop`; started by the compile thread after `START_AFTER` and ended by it, every sleep is `nap`, parkable: a stop never waits out a period, #725) sends `Look`s (CPU time of the simulation threads since the last look, `Look::dt`, and what they run) in batches of `BATCH`, also while the compile thread compiles or runs a trial (`Shared::trial` pauses it); the compile thread takes one batch at a time (`Worker::see`, then the decisions), so the sequence of decisions does not depend on how long a compile took. Time is the CPU time of the simulation threads (`sim_cpu_sampler`: process less the sampler's and the compile thread's own clocks), not wall time, which counted the time the compile thread took from the simulation. Prices are constants, never measured (`price`, `payback_cost`, `US_PER_INSTR*`): a measured rate depends on load and on whether the cache hit. `payback_cost` is flat 800 per IR instruction so that big `Fast` processes compile as late as before; the budget (`price`, `cost`) charges `Fast` code its own 110. `spent` is charged by the model too. A new decision must read only the looks and the program, never a clock or the time a compile took (`what_is_hot_depends_on_the_looks_only`); a `HashSet` is sorted before it decides an order. - Optimised register allocation for hot large frame-mode functions (#715, decisions.md "llvm: `OptLevel::FastRa` ..."): `OptLevel::FastRa` is `Fast` with the greedy allocator, made per target machine (level `Less`, `LLVMSetTargetMachineFastISel`, functions `optnone noinline` after the passes, `jit::no_opt`), never by `-optimize-regalloc`/`-regalloc` (process-wide, and the first cannot be put back to unset). The policy: `Worker::fast` marks a frame-mode function (not `natively`) compiled at `Fast`; its compiled-time threshold is `PAYBACK_RA` times `ra_cost` of its IR instructions (`Worker::threshold`), then the O2 recompile queue makes it `FastRa`. The constants belong to the pricing (#670): change them with `US_PER_INSTR*` and `ra_cost`, from measured code generation times, and keep the payback rule a function of the looks. With `--tier-heat` (budget 0) every second compile of a function of `FAST_MIN` instructions or more is `FastRa`, which is how the differential tests run the level.

- `--tier=auto` policy (#572; `auto.rs` `pick`, `first_fit`, `Trace`; decisions.md "`--tier=auto` compile policy"): `pick` prices every candidate and compiles the hottest per cost that fits the budget, a refused one waits alone for `pick_at` (it used to hold up all the others); a function called natively is compiled after its kind's payback times its compile time seen and gets `NATIVE_BUDGET` (16) times the budget. A callee of a candidate that was never seen running and has more than `UNSEEN_MIN` IR instructions is left out of its compile (`left_out`; its caller's native code is published without it, #493). `publish` asks `Worker::ready`: the native callees reachable from the function, the walk stopping at a callee that is `left` or was never seen running, must be compiled; it used to ask that of the whole native set, so a never-called callee that no tree brought kept the function and its native callers unpublished for the run (#797). `YAVS_AUTO_TRACE=1` prints the compile thread's timeline on stderr (compiles with first-seen and candidate ages, refusals with the time they fit at, the most sampled functions at the end): read it first when a hot function is compiled late. Measure a policy change with `perf stat --no-inherit -e cycles:u,instructions:u` on `exec yavs ...` (the main thread only: the compile thread's work is not in it, and instructions vary by 1 percent where wall varies by 10 on a loaded host), on a fresh world per binary and tier (a warm world must not outlive a binary: the compilation cache and its list of compiled functions are part of the result), cold = a copy of the pristine world per run.
- Rules per generator (#481; `auto.rs` `Tune`, `Worker::tune`): the rules for clocked processes that depend on how dear the code is to make are one struct, `Tune::MAIN` (the LLVM values above: `RTL_MIN`, the `RTL_BAND` wait, `RTL_INSTANCES`, `RTL_SHARE`) and `Tune::FIRST` for a first-level generator (Cranelift: 64 IR instructions at least, no wait outside the band, `Kind::RtlFew` under four instances, a thirty-second of the run; every kind priced at `FIRST_US_PER_INSTR` (45 us an IR instruction) with the speedups of `MODELS`; a root owes 8 times the price of the callees compiled with it, `tree_payback`, `Worker::pick`; a clocked process 16 times its own price, `payback_rtl`; both because the compiled code of library functions and of small processes gained next to nothing in instructions, #718). Without a main generator (a Cranelift-only build) a subprogram of the size LLVM compiles at `OptLevel::Fast` (`native::big`) is `Kind::Big`/`BigLoop` (`Tune::big`), processes are not, and `Kind::Frame` functions are not compiled (`Tune::frame`: their frame-mode code sends every calling process through the interpreter's loop for compiled code, decisions.md "Cranelift tier, round 11"). `YAVS_FIRST_TUNE=rtl_min=N,band=0|1,instances=N,share=N,o2_after=N,tree_payback=N,payback_rtl=N,big=0|1,frame=0|1` overrides `FIRST` for a measurement. A new generator-dependent rule goes into `Tune`, not into a second constant. - Copies of processes under `--tier=auto` (#661; `docs/design/specialisation.md` section 11, decisions.md "Specialised copies of processes"): a copy (`Program::copy_of`, its own function id in a reserved slot) is sampled under its own id, but every policy decision goes by its process (`Program::base_of`): `Worker::group` is the interpreted time of the process and all its copies, which `threshold`, the payback rule, `wants_probe` and `cold` read; `Worker::is_rtl`, `base_len` and `cost` classify and price a copy as the process's shared code (the copy's own length only prices its compile); every copy that is seen running is a candidate once the process is hot (`asked_for`) and, unless the process is a clocked one (`rtl`), once the copy itself was seen for its own payback (`need` of its own length: copies differ in their constants, so each is a module of its own, #757), compiled from its own code; the cache list (`listed`, `Worker::list_key`) names a copy by its `Program::copy_tag`, so one compiled copy does not make the others look cached; a trial that takes one copy back keeps the others not compiled yet interpreted (`lost`); the trial of the shared code of a process that can have copies (`Program::specialisable`) is not run, and its loss would not stop the copies (#675): its processes switch to their copies, which the tier compiles (`Tier::compiles_copies`), so the windows timed code that no longer ran (`rtl_lfsr` taken back at 1.0 after the copies were compiled by the tier). `compile_one` names a copy's symbols by `Program::copy_tag` (`f<process>c<tag>`), not by its id, so the compilation cache key (the bitcode) is the same in every run whatever order the processes switched in (`tests/objcache.rs`).
- Looks get sparser as a run goes on (#675; `auto.rs` `stretch`): the sampler takes a look every `Heat::period` of work for the first 300 ms of work seen, every second period to 1 s, then every fourth (a function of the work seen, so decisions stay a function of the looks). A look costs the simulation's core a wake-up (the sampler shares it under `taskset`): 1 ms looks were +3 percent wall on a 4 s run that compiles nothing (`fletcher_bufferwriter_512`), 4 ms looks +1.5. - Closed native frames (#626; `closed_frame`, `Nat::closed`, decisions.md "Compiled protected-method accessors, round 2"): a native frame none of whose frame addresses leaves its own `Load`/`Store` addresses is not registered in `Mem::nslots` (length 0 is written) and its slots are an `alloca` that `sroa` promotes. - Address spaces across blocks (#684, #685; `regs::spaces`, `Known::InstAny`, `Known::Up`): `Gen::func` starts a block with the preloaded facts plus the registers `spaces` proves hold an instance-data, temporary or heap address on every path (`Alloc` and `NewFrame` are temporary addresses) (a new instruction that defines such an address must be added to its transfer function, else the fact lapses safely); an `Index` keeps the space of its base; a `Load` through the address of a variable's slot (not a parameter's) or an enclosing subprogram's gives `Known::LikelyHeap` the same way (`Sp::Likely`, #768: a load the optimiser moved to a loop preheader keeps the hint, else each access of the loop asks the runtime). `Known::Up(d)` is an address in the slots of the frame `d` links up, read from `TierFrame::up_slots`/`up_len` (frame-mode code only; a new place that changes the stacks must refresh the view with `tier_view`, which fills them).

- Held heap objects (#626; `ObjRef`, `Known::Heap(Some(_))`, `Cur::objnew`, native frames only): after a `Deref` the generated code has the object's pointer and length as values and every address derived from it (`Index`, `Field`, `Move`) carries its offset; `Gen::host` uses them. - Address parameters (#726; `rt::param_addrs`, `stable_activation`, `Known::Param`, `Cur::pres`, `yavs_rt_region`, native frames only): a parameter a function loads in its entry block and uses as an address in a loop is resolved once at the entry into a host pointer and length; the register is `Known::Param(k)` in `base_known` (and again after its definition, `track` clears it) and `Gen::host` tests the pair before the old lookup, which a failed test takes. A held region that misses takes `host_lookup` with `LikelyTemp`. A new way to derive an address from a parameter register must set `Known::Param` in `track` or leave the fact to lapse. `cb_region` counts the callbacks.

- Code arena and the shape of frame-mode code (#679; `arena.rs`, `Gen::entry_dispatch`, `Gen::cond_br`; decisions.md "llvm: code in one arena of huge pages, ..."): on Linux x86_64 the object layer is RuntimeDyld with our own section allocator (JITLink's allocator cannot be replaced through the C API), so all compiled code is one region that can be a huge page; the code zone is read-write-execute (nothing to finalise); anything else keeps LLJIT's default. The entry switch of a frame-mode function (`pc` to the entry blocks) is a tree of range compares with `switch` leaves of at most four cases: the unoptimised code generator lowers a big `switch` to a chain of compares, and a process is entered at one of thousands of pcs at every resume. `cond_br(.., likely = true)` branches on the negation of a condition that is not a compare, so the rare edge is the `jcc` and the hot path falls through (the code generator turns `br c, hot, cold` of a computed `c` into `jcc hot; jmp cold` with `hot` the next block). Tried and dropped: machine function splitting (a made-up profile summary and entry counts make LLVM move the blocks the guards' weights call rare into a second section; the arena put it in its own zone): the hot part of a 24 000-instruction process was 1.1 MB instead of 3.7 MB but L1i misses rose by a fifth and cycles did not move, because the rare edges are taken more often than their weights say; `zext(trunc)` for the 32-bit masks (instcombine turns it back into the mask). Small code model (#679, `jit.rs` `model`): with the arena the target machine is small + PIC and the runtime callbacks are `nonlazybind` (`Gen::effects`/`declare`: `call [rip+got]`; without the attribute RuntimeDyld makes a PLT stub per callback and object and every call pays a second jump); `YAVS_LLVM_CODEMODEL=large` keeps the JIT default; `target_id` carries the model; a section outside the arena in this model aborts (32-bit displacements, the release linker does not check them). Block order (`lower.rs` `layout`, at the end of `Gen::func`): blocks are put in execution order (likelier successor by branch weights next, cold blocks last); creation order put every join block before its fast path. `narrow_masks` (`jit.rs`, after the passes, only for the unoptimised code generator): `and (load i64), 0xffffffff` as `zext (load i32)`; before the passes it blocks store-to-load forwarding of constants. Tried and dropped: the address of an access made before its guard (code 0.4 percent larger, cycles level), other pass pipelines (`early-cse<memssa>`, `gvn`: code level or larger). Open: the reloads of the three function arguments at every block are 10 percent of the instructions of a large process (decisions.md).
- Element access in native frames (#493; `Inst::Pos` arms, `index_muls`/`Cur::imul`/`Cur::fused`, `Obj` aligned to 64 bytes, `OBJ_SHIFT`, `Gen::obj_entry`; decisions.md "llvm: element access in native frames ..."): `Pos` has one arm per direction (any other `dir` is the interpreter's); a `Bin Mul` by a constant whose product is used once, by the `Index` after it, is one test of its operand and settles the `Index`'s guard (`Cur::fused`; the `Index` must be no entry point); an entry of `Mem::objs` is one cache line and `obj_entry` builds its offset from the whole address or access value (`obj_entry_expression_is_obj_at` keeps it equal to `obj_at`). A new way to produce a position for `Index` must not rely on `fused`. Measure with `--tier=llvm` (deterministic) and, for `--tier=auto`, only after about twelve untimed runs of a private world: the set of compiled functions keeps growing and fewer runs compare unsettled builds. LLVM-level inlining of native callees was measured and not taken (instructions down, cycles level); the accessors wait for dependent loads.
- Search loops (#578; `yavs_interp::search_loops`, `yavs_rt_scan`, `Mem::span`, `scan_ctl`): at the head of a search loop in a native frame the generated code calls the helper with the loop's registers; `hit` 1 and 2 jump to the loop's exits (`ways` of those blocks is raised, so they take nothing from a predecessor), anything else falls into the generic head. The loop's exit blocks need the registers the loop defines besides the element and index dead (`search_loops` checks). `auto.rs` `fused_search` (#573) stays: the compiled loop is as fast as the interpreter's, but a function around it still ran 1.05 to 1.12 times the interpreter's cycles without the rule (#652, decisions.md "callees with their caller, `band_wait` 0.25 s, trials of looping processes").

- Copies of one module (#713; `compile_one`, `Jit::twins`, `Module::rename`, `objcache::note_twin`): a specialised copy of a process (`Program::copy_tag`) is generated under the fixed name `ftwin`, keyed by its module (bitcode with that name, level, `full`, part, native), renamed to `t<key>` and compiled once per `Jit`; another copy whose module is the same up to its name (instances that differ in data the code does not read) gets the entry points of the first and counts as linked from the cache (the auto budget charges the cache price). The compilation cache holds one object per distinct module and a warm run finds it by that name whatever order the copies switch in. Only copies are keyed this way (`YAVS_LLVM_TIMES` shows `pass` and `codegen` of the first only); a function whose module has any other difference is compiled as before.
- Callbacks of large processes (#679, `docs/decisions.md` "llvm: large compiled processes lose to their callbacks, ..."): measure a big process by what its compiled code calls, not only by its bytes: `perf record -j any_call` (the last branch out of compiled code is the site) with `YAVS_PERFMAP`, and `YAVS_LLVM_PCLOC=1` with `YAVS_LLVM_KINDLOC` (debug line `2 * pc + 2` of the IR instruction, one more in a cold block, file `i<function id>`) and `YAVS_LLVM_OBJ` to map a site to its IR instruction. A `LayoutOf` that would be stepped and whose layout only one word is read of right after it (`Field`, `Load` of word 0, constant `Index` then `Load`; `fuse_layout`, `LayoutFuse`) is one `yavs_rt_layout_word` call into the interpreter's layout memo (`TierHost::layout_word`); the fused instructions generate nothing (`Cur::layout_fused`) and a decline leaves to the interpreter at the `LayoutOf`. A new instruction kind that reads a layout word belongs in `fuse_layout` only if the interpreter's predecoder fuses it too. The object table is keyed by machine as well as address (`Mem::tags`, one tag per address space: the machine's for instance data, package data and shared variables, the machine's at its heap epoch for heap objects, the runtime's for constants, the activation's for frames and temporaries; decisions.md "llvm: an object table keyed by machine"): a change of machine walks and restores nothing. Every lookup, in `rt.rs` (`Mem::get`, `Mem::slot`) and in generated code (`Gen::obj_tag`, `Gen::obj_entry`; the `Deref` hit test compares the tag too), must use the key of the object's space; a new way to drop objects is a new tag (`Mem::issue`), never a walk. A new address space needs its tag kind in `Mem::begin`/`restart`.

## 4. Invariants and pitfalls

- The native-frame calling convention is shared with `yavs-clift` (decisions.md "One native-frame calling convention for both generators"): `f<id>_n(env, mem, depth, [up1, up2], cells...) -> i64`, recorded frames signalled by `Mem::ndeopt`, variants in `Mem::ntab`. A change of `native_ty` or of the deopt protocol is a change of `native_sig` and `Gen::native_call` in `crates/yavs-clift/src/lower.rs`; `tests/compiled_mixed.rs` and `difftest.py --candidate yavs-mixed` catch a mismatch. `auto.rs`, `native.rs`, `regs.rs` and `generator.rs` are built without LLVM and take no `llvm_sys` type.
- A frame's registers when compiled code enters at any pc: the preloaded `Const`/`ConstF`/`AddrOf` values of `Pre`, zero elsewhere, and the registers holding a `lean` function's parameter slot address are zero too (`Pre::next` skips their `AddrOf`; #566). Never read them: address preloaded frame slots by the known offset (`Known::Frame`, `base_known` in `Gen::func`). A second code generator read the caller's parameter this way. Contract and test: `crates/yavs-interp/AGENTS.md` (`Pre::lean`).
- Compile cost is measured with `--no-cache` (or a fresh work library): with the cache a second run
  links what the first compiled, and `YAVS_LLVM_TIMES` then shows the generation and the link only.
- Measuring code quality: `--tier=llvm` gives a module over 150000 LLVM instructions the unoptimised code generator; `YAVS_LLVM_FAST_MIN=99999999` gives it the code `--tier=auto` makes for the functions it compiles at `O2`. Compare instructions or the simulate time of runs whose objects are all in the compilation cache (a difference of two runs that compiled differently measures the compile).
  A new setting that changes the machine code without changing the IR (a pass, a code generator
  switch, an environment variable) must be part of `objcache::key` (`jit::target_id`).
- A new runtime callback or table must reach compiled code as a symbol (`new_jit`) or as data of the
  module, never as an address constant in the IR: a stored object is linked in other processes
  (`objcache.rs`). The object cache key holds the IR, so such an address would only cost hits, but
  a module that stays identical while its meaning changes (code that reads a process-wide table
  through an address it did not put in the IR) would be wrong.
- A pre-key hit skips generation (#785): the generator may read only the program (named by
  `Program::identity`), the function, the level, `full` and the part. A new input from outside them
  (an environment variable, a process-wide setting, something of the run) must go into
  `objcache::pre_key` or `GEN_SWITCHES`; `YAVS_LLVM_PREKEY_CHECK=1` (the CI `llvm` jobs, the
  `yavs-auto-warm` difftest candidate) is what catches one that does not.
- `cargo test --workspace` does **not** build this crate's code (feature off): run the feature
  build yourself after any change here.
- `build.rs` runs `llvm-config` (`LLVM_SYS_211_PREFIX/bin`, else the path) and `llvm-nm`/`llvm-readelf` from its bindir on Linux; a stub exists for every `LLVM*` export, so an unused one costs nothing (the linker drops it).
- LLVM 21.1.8 with static libs is in `/usr/lib/llvm-21` on the dev host; `llvm-sys` finds it via
  `llvm-config` (Windows packages have none, see WINDOWS.md).
- Codegen cost grows faster than linearly with function size; measure with
  `examples/measure.rs` before changing thresholds, one process per row.
- CI (`llvm` job in `.github/workflows/ci.yml`, #127, #128) clippys, tests and runs 47 difftest cases
  with `--tier=llvm` and with `--tier=auto --tier-heat=1,0,0` (at 1 and 4 threads) on Linux x86_64, Linux aarch64 (native runner) and Windows x86_64 (tests only,
  the difftest harness needs a POSIX shell). Windows needs the steps in WINDOWS.md section 4: static
  CRT, empty `libxml2s.lib`, SDK import libs copied into the LLVM `lib` dir.

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-llvm --features llvm
CARGO_BUILD_JOBS=6 cargo test -p yavs-llvm --features llvm,gc-stress   # unit tests with a collection at every safepoint (#500)
cargo build --release -p yavs --features llvm,clift,table-check  # a release yavs that panics when a lean activation reaches the object table (#766)
cargo build -p yavs --features llvm                    # yavs with --tier=llvm
cargo clippy -p yavs-llvm --features llvm --all-targets -- -D warnings
cargo run --release -p yavs-llvm --features llvm --example measure -- <stmts> [O0|O1|O2]
```

- No diagnostic codes of its own: the `yavs` binary reports `--tier=llvm`/`auto` problems (`E0120`,
  `E0121`); a code of this crate would take a range in `crates/yavs-diag/src/lib.rs`.

- Measured take-back (#596, #652; `auto.rs` `Worker::trial`, `run_trial`, `decide`, `Rule`, `window`): after the swap of a compiled function seen for an eighth of the sampled time the compile thread compares the progress per CPU second with the compiled code and with the interpreter running the function (`Entry::clear`, `NativeFlags::clear`/`clear_call`, the `ntab`/`ctab` slots zeroed) in turn, and takes the code back (`lost`) when it did not pay. A clocked process (`rtl`) is judged by the process runs of the kernel (`yavs_interp::sim_progress`, once per delta cycle; `BY_RUNS`: at least 1.05 times as fast, early verdicts); any other process (one that loops between its waits) by its activations (a process that is not `rtl`: `NativeFlags::count_on`/`count_off`/`entries`, flag `NAT_COUNT`, counted in `run_quick` only while its trial runs; `BY_ENTRIES`: all three pairs of windows, taken back below 0.95 only, because activations come in bursts and vary 10 to 25 percent between windows). Keep in step: anything that publishes compiled code of a function (`compile`, `publish`) must skip `lost` ones; Decisions.md "the callback count sees what leaves compiled code, and compiled code is measured and taken back" and "callees with their caller, `band_wait` 0.25 s, trials of looping processes".
- Callees with their caller (#652; `must_calls`, `Worker::hot`, `unseen`): a callee of at most `CALLEE_MAX` IR instructions that every path of a candidate calls (transitively) is compiled with it even if the sampler never saw it (`UNSEEN_MIN` leaves out only callees that may be rare): a call from compiled code to an interpreted callee is a `yavs_rt_step` out of the native frame.
- Code size (#679, `docs/decisions.md` "llvm: smaller frame-mode code"): the unoptimised code generator puts every value that crosses a block in a stack slot, and frame-mode code has a block per guard, so the bytes go to cross-block values, not guards. Keep values local: a definition is deferred only when its register is live over `MAX_SPAN` instructions or fewer (`Defer::keep`), address arithmetic is copied per block after the passes (`jit.rs` `remat_geps`), tests that feed a guard are made in the block that uses them (`Gen::host`), a decode of a cold shape is a pure runtime call (`yavs_rt_codes`, `yavs_rt_scalar`). Measure with `YAVS_LLVM_KINDLOC=<file>` (every LLVM instruction gets debug line = IR kind number, +1000 in cold blocks; `YAVS_LLVM_OBJ` objects then `objdump -dl` sum bytes per kind, `perf record` instructions:u per kind) before and after; judge by bytes, instructions, L1i/iTLB/branch misses and frontend stalls, cycles on this host are noisy.
- Compiled copies and cheaper bodies (#679, `docs/decisions.md` "llvm: compiled copies of processes, ..."): `AutoTier` returns `compiles_copies()`, so `Machine::specialise` moves a process whose shared code is compiled to its copy and the copy is compiled (the shared code's `LayoutOf`/`Field`/`DopeLen`/`SubtypeCheck` were 35 to 45 percent of its bytes; the copy folds them, `opt/decl.rs`); `--tier=llvm` does not and keeps the shared code. A constant `LCopy` inside one plane block each side is `Gen::lcopy_const` (test `constant_logic_copies_match_the_interpreter`); `Gen::std` stores nothing for a register defined once by a constant or an address (`Defer::pre`), loops or not. Measure compiled code in heat mode against `--tier=interp` of the same session and design, not against another session's cycles.
