# AGENTS.md: yavs-llvm

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-llvm`.
Binding choices are in `docs/decisions.md` "LLVM bindings: llvm-sys 211, no inkwell"; Windows
in `crates/yavs-llvm/WINDOWS.md`; measurements in `docs/STATUS.md` "llvm".

## 1. Purpose and boundaries

- The **LLVM tier** (M6): `compile(&Program, OptLevel, max_size) -> LlvmTier` lowers every
  non-elaboration IR function to LLVM 21 and JITs it through ORC LLJIT (portable CPU, O2, Rust
  runtime callbacks as absolute symbols). `LlvmTier` implements `yavs_interp::Tier`; `yavs run
  --tier=llvm` sets it on the runtime. Design: `docs/decisions.md` "LLVM tier: side exits to the
  interpreter".
- Compiled code runs on the interpreter frame's registers, slots and temporary area
  (`yavs_interp::TierFrame`, a `#[repr(C)]` view of the machine's stacks the interpreter keeps
  current). Inline: `Cover` (one atomic add on `TierFrame::cov`, #692), `CoverIn`, `Const`, `ConstF`, `Move`, `Bin`/`BinRange` (not `**`), `Un`, `FBin` (not
  `**`), `FUn`, `IToF`, `Cmp`, `FCmp`, `Bool`, `Check`, `FCheck`, `Index`, `Br`, `CondBr`,
  `Case`, and with a slow path that steps the instruction: `AddrOf` (`Up` one or two levels
  through the view), `Load`, `Store`, `Copy`, `Alloc`, `Stmt`, `MakeDope`, `DopeLen`, `Pos`,
  `SubtypeCheck`, `Field`, `LayoutOf` (types whose element layout is static), `LGet`, `LSet`,
  `LCopy` (up to eight plane blocks each side, through `yavs_rt_lcopy`, which runs the
  interpreter's `yavs_interp::copy_bits`), `Deref` (through `yavs_rt_fast`, `TierHost::deref`), `MemEq` (`yavs_rt_memeq` on the bytes `Mem` found), `SigVal`, the scalar `std_ulogic` natives as
  tables (`yavs_interp::code_table`), a `Cat` of non-logic elements (`Gen::cat_bytes`, as on a native frame), a `LayoutOf` of a one-dimensional array of static element layout (`Gen::layout_words`), and a `CallNative` of a native `yavs_interp::direct_native` allows through `yavs_rt_native` with `NATIVE_FRAME_MODE` (`TierHost::native_frame`: the argument cells from the registers, the result into one register, no frame view, no flush or reload of the other registers; where it declines the call is stepped; #565). Memory is reached through `Mem` (the view plus a direct-mapped
  table of 1024 objects `yavs_rt_host` asked `TierHost::object` for (`Mem::occ` marks the entries in use, the walks visit only those), entry `obj_at(hi)`, looked up inline by every access of unknown space, with the access value a `Deref` found each one for, so a `Deref` of a handle found before is inline; entries live as `Life` says: frames and temporaries until the next host call, heap objects while `TierFrame::heap_epoch` is unchanged (`Mem::forget_since`, and into the next activation or call of the same machine, `Mem::begin`), constants, instance and package data while the same machine (`TierFrame::owner`) runs, #510; frame, temporary and instance
  addresses are found inline (frame-mode code asks `yavs_rt_host` for an address of unknown space, #634, except where `rt::track` has a guess: `Known::LikelyTemp` and `Known::LikelyHeap` get one inline test of the temporary area or the object entry first, `Gen::host`, #711), and a constant the generator knows (`Known::Const`) is read from a
  private copy in the module, `Gen::const_global`). Through the `yavs_rt_signal` callback
  (`TierHost::signal`: the interpreter's own functions without its generic step):
  `SigRead` (one range), `Drive`, `DriveSlot` (one range), `WaitOn` and
  `WaitFor` (each with the `Suspend` after it), `Suspend` and the `rising_edge`/`falling_edge`
  natives (#339); `SigReadScalar` of a logic signal that keeps its codes, and `rising_edge` /
  `falling_edge` of the edge the kernel resumed the process for, are read in place from
  `TierFrame::sigtab` and `known_*` (`Gen::sig_read_scalar`, `Gen::edge`; the callback is their slow
  path, #440). The same callback runs the instructions that only change the temporary area or one register without the generic step and without forgetting the cached objects: `TempRoot`, `Stmt` (when roots are recorded), `NewFrame`, and the slow paths of `Deref` and `MemEq` (`Gen::step`); a `TempRoot` of a fat pair asks `yavs_rt_fast` (`FAST_FAT_ROOT`) first and records nothing when no word points into a heap (#432). Every other instruction runs in place through
  the `yavs_rt_step` callback (`TierHost::step`): calls, the other natives, foreign calls, reports, the
  other signal operations and waits; a frame a call pushed runs its compiled code directly from
  the callback and is popped by `TierHost::ret` (#336). Compiled code returns to the interpreter
  at `Ret`, every guard failure (overflow, check, zero divisor, non-finite real, address over
  4 GiB, re-executed by the interpreter for the identical error), and with `TIER_UNWIND` /
  `TIER_SUSPEND` when frames it pushed are left to the interpreter or the process suspends. The open native lowerings are issues (section 6).
- `AutoTier::start` (`yavs run --tier=auto`; its thread waits `START_AFTER`, 5 ms, before it reads the cache's list or samples, #426) compiles at O2, on one background thread, the
  functions where the sampled interpreter time reaches `PAYBACK` times their estimated compile
  time (`PAYBACK_NATIVE`, 2, for a function the interpreter calls on a native frame), with their small callees (`Worker::tree`), and only while the compile time spent is at
  most `Heat::budget` percent (2; fifty times that for a compute loop, `compute`, which also needs two times its compile time seen) of the interpreter
  time the sampler saw (`Worker::pick`, #432). With the hidden `--tier-heat` there is no budget
  and the first level is O0, those still hot in their compiled code compile again at O2
  (`Heat::o2_threshold`);
  `AutoTier::stop` ends that at the end of the run. The
  spike (`spike.rs`) stays as the JIT smoke test.
- Everything is behind the `llvm` feature (off by default), so the workspace builds without
  LLVM 21.
- Compiled code is kept across runs in the compilation cache (`objcache.rs`, #505): the object
  file of every module, keyed by its LLVM IR, linked again instead of compiled.
- Depends on: `llvm-sys`, `yavs-ir`, `yavs-interp`, `yavs-cache` (all optional, feature `llvm`).
  Called by: the `yavs` binary (feature `llvm`).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| The interpreter is the semantic reference: every suite must give identical output LLVM-only and interpreter-only | Rule 5 | `docs/plan.md` rule 5, "Verification" |
| LLVM 21 pinned (`llvm-sys =211.1.1`, `strict-versioning`, `prefer-dynamic`), optional feature; LLVM is an approved manual dependency | Rule 5; root `AGENTS.md` rule 9 | `docs/decisions.md` "LLVM bindings" |
| Raw llvm-sys, no inkwell | inkwell lacks ORC LLJIT | same |
| ORC LLJIT, no hand-written object loader; host functions as absolute symbols, nothing looked up in the process | Rule 5 | same |
| Portable CPU: `x86-64-v2` or `generic` aarch64, never the host CPU; `default<O2>` | Rule 5 | same |
| One `LLVMContext` per module (`LLVMOrcCreateNewThreadSafeContextFromLLVMContext`) | LLVM 21 removed `ThreadSafeContextGetContext` | same |
| Runtime errors call a Rust `extern "C"` callback and return a status; no unwinding through JIT frames | Win64 has no unwind info for them | same; WINDOWS.md |
| Shared `libLLVM-21.so` on Linux, opened on first use through generated stubs (`build.rs`); static libs from the release tarball on Windows | Link memory; llvm-sys refuses dynamic on Windows; loading it at start cost 5 ms per process (#426) | same |
| Self-contained compiled code on interpreter frames: every instruction it does not lower runs in place through `yavs_rt_step` (calls and natives included); a pushed callee with compiled code runs directly and `TierHost::ret` pops it; it returns to the interpreter only at `Ret`, `Suspend`, failing inline instructions and frames it cannot finish (`TIER_UNWIND`) | Rule 5 by construction; one implementation of frames, heap and traces; no exit per call (user decision, 2026-10-20) | `docs/decisions.md` "LLVM tier: side exits", #336, #337 |
| Memory instructions run natively only where the bytes lie in memory `Mem` reaches and no error is possible; anything else steps the whole instruction, before any side effect | Rule 5: one implementation of address spaces and errors | `docs/decisions.md` "LLVM tier: side exits" (Memory) |
| Vector work compiled code does not inline calls the interpreter's own Rust functions directly (`yavs_rt_lcopy` runs `copy_bits`; `TierHost::signal` runs `sig_read_vec`, `drive`, `wait_for`), never a second implementation in LLVM IR; a constant known at generation time (`Bytes` form, at most 4 KiB) is read from a private copy in the module, the bytes the interpreter reads | Rule 5; constants never change; the object lookup per activation cost 5% of clocked RTL | `docs/decisions.md` "LLVM tier: side exits" (Vector process bodies) |
| GC roots: `New`, `Free`, `TempRoot`, natives and calls are stepped with the registers, slots and temporaries in the machine (compiled code stores every register at once and hands the temporary length back before a step), so a collection inside an activation sees them; frames compiled code called through wait at their call's pc; `Stmt` steps while `Mem::temp_roots` (`TierFrame::temp_roots`) is non-zero so the interpreter drops the ending statement's recorded temporaries | Precise roots in both tiers (#422) | `docs/decisions.md` "Shared heap collection" |
| Native frames for native-callable functions (`native_set`): compiled callers call them directly; the frame becomes an interpreter frame (`TierHost::materialise`) only at a step, a failing instruction, the depth limit or the native stack allowance, and the interpreter goes on from there (`TIER_UNWIND`); processes and other functions stay frame-mode; frame-mode code has entries after preloaded definitions | A compiled call cost what an interpreted one did; materialised frames keep traces, roots and errors the interpreter's | `docs/decisions.md` "Compiled frames and calls between compiled functions", #432 |
| A native frame leaves at an exit site, never through a shared block carrying every register: `Gen::leave` stores the registers live before the pc (`regs::Live`) into the function's spill buffer (an `alloca` that escapes only to `yavs_rt_deopt`) and branches with the pc; blocks of failing guards go behind the rest of the function (`Cur::cold`) | One block taking all registers through phis made the code generator copy every register on every guard edge (475 blocks, 130 phis for a 100-instruction procedure) and kept all of them live to the last guard; `--tier=llvm` ran codec loops slower than the interpreter | `docs/decisions.md` "Native frames: every exit records the registers live at its pc", #554 |
| A register `Deref` defined is a known heap address (`Known::Heap`): `Gen::host` leaves out the frame, temporary and instance tries for it; the object table key is the object index with bit 3 flipped for a shared heap, computed from an address (`obj_at`, `Gen::obj_entry`) and from an access value (`obj_entry` with `handle`) alike | A private and a shared heap object of the same index evicted each other at every access of a protected-type library function; a frame test per heap access was a third of the access | `docs/decisions.md` "Compiled memory access: heap addresses are known", #554 |
| `Deref` and heap addresses go through the object table (`Mem::objs`), not a flat view of the heap's slots: the view (#655) was built and passed its cross-check, but its hit path is longer than the table's (24 LLVM instructions against 18) and the whole of the callbacks it saves is 1 to 3 percent of the window generator; a change to this rule starts from the measurements in decisions.md | Instructions of one protected `get` 336 to 367, `protected_queue` +7 percent, window generator +3 percent with the view | `docs/decisions.md` "A flat view of the heap slots for compiled `Deref`" |
| Calls from the interpreter on native frames (`Tier::call`, #510): a function without a static link that has native-frame code gets an adapter `f<id>_c(env, mem, depth, cells)`; the interpreter's `Call`/`CallProt` of a function `NativeFlags::set_call` marks calls it with the argument cells from its registers instead of pushing a frame, as a frame-mode caller's `Gen::native_call` would (depth limit, shared state of a protected call, `TIER_SHARED_ALLOC`); a materialisation pushes the frames on the caller and the interpreter goes on with them | A compiled function entered from the interpreter cost a frame push, the frame view and frame-mode code that steps `NewFrame`, `Cat`, `Fill`, `TempRoot`, so short functions ran slower compiled (#510) | `docs/decisions.md` "Native calls from the interpreter and the object table" |
| Native frames never see a collection: instructions that can collect first ask `Machine::reclaim_pending` and leave to the interpreter when one is due; natives, `New`, `Free` and the rest without an inline form run on the interpreter's own code (`native_direct`, `native_step`), and a failure there is a replay by the interpreter, never an error reported from compiled code | Precise roots (#422) and the interpreter's errors and traces with no spill map | `docs/decisions.md` "Native frames, round two" |
| Natives of frame-mode code (`frame_direct`, #565): a `CallNative` of a native `direct_native` allows (pure natives, `now`, `writeline`, the file open and close) calls `yavs_rt_native` with `NATIVE_FRAME_MODE | pc` as its depth, which runs `TierHost::native_frame` (the machine's `native_direct` for the top frame without the slot windows; declines while a package initialisation or an elaboration trace is on, a collection is due, the native fails or hands its call to the VHDL body). The result goes to the destination register with `st`; `Stop` (a native that reported at the stop severity) flushes and returns `TIER_SUSPEND` with the frame's pc at the call (`native_frame` sets it). `Mem::forget_since` returns at once when no volatile object was found and no heap object changed. Light natives (`yavs_interp::light_native`: the `ieee` ones `Op::CallIeee` runs) call `yavs_rt_native_light` (`TierHost::native_light`) in both modes: same arguments and results, no collection check, no heap epoch, a view update of the temporary area only (#698). The light `numeric_std` natives of `ieee_layout` (`to_integer`, `+ -`, relations, `to_unsigned`/`to_signed`, `resize`, shifts and rotations, the logical operators) are computed in place on operands of at most 64 elements without a metavalue (`Gen::ieee_fast`, `small_operand`: the arithmetic of `ieee::small`/`put_small`, result block taken with `temp_alloc`); every guard that fails goes to the callback of the same site (`native_direct`), which runs the native, so warnings and errors are the native's (#698). A new operation here must copy the bail conditions of the native's own fast path, and the site is not a callback for `leaves` | A step builds the frame view, dispatches on the instruction and forgets the objects found; the lean call is about a third of that, and the other registers stay in machine registers across it | `docs/decisions.md` "Host callbacks of compiled code" |
| The memo of pure calls (#701, `docs/decisions.md` "Memo of pure calls"): `Gen::native_call` of a callee with `Program::memo_sig` (and a cell count equal to the call's) calls `yavs_rt_memo` before the call (`TierHost::memo_probe`; depth as for `yavs_rt_native`, `NATIVE_FRAME_MODE` for a frame-mode caller; returns 1 = hit with the result in `out[0]`, 2 = miss with the report count in `out[1]`, 0 = call as usual) and, on the normal return edge after the `ndeopt` test, `yavs_rt_memo_keep` (`TierHost::memo_keep`; result in `out[0]`). The two blocks meet in a phi for the call's result. Neither callback runs VHDL code or collects; a hit allocates temporary memory only (view and `temp_seen` as a light native). Every callback that may change the machine's temporary area ends with `temp_seen = fr.temp_len` (a keep that did not made the machine's length lag behind the compiled code's: `native_step` then read past the end). `Cb::Memo` counts both | A compiled caller bypassed the interpreter's memo: `poc_cache_cpu` under `--tier=llvm` ran its `ffdre`/`mux`/`resize` in full | `docs/decisions.md` "Memo of pure calls" |
| A function whose generated LLVM does not verify, or that names a register beyond its frame, stays interpreted with a note (`--verbose`); never a guess | Fail clearly, per function | `src/lower.rs` `compile` |
| Size cap: a function of more than 50k yavs IR instructions stays interpreted unless `--tier-max-size` raises it (both tiers); `--tier=auto` compiles only hot functions | Superlinear codegen time (user, 2026-10-19) | `docs/decisions.md` "LLVM bindings"; #126 |
| `--tier=auto` (opt-in, default `interp`): a sampler thread reads which function each simulation thread interprets (`Runtime::sampler`, every `Heat::period`, 1 ms) with the CPU time the simulation threads used since the last look, and the compile thread works through those looks in order (#670) and compiles one once seen for `Heat::DEFAULT` (2 ms plus 40 us per IR instruction, about twice its O0 compile time); time in compiled code entered from interpreted code counts for the caller; ONE compile thread (it keeps the CPU mask the process was started with, #681: under `taskset` it shares the simulation's CPUs), one module per function at O0 (the CLI picks it: O2 codegen costs about 7x), compiled again at O2 once seen running compiled for 30 times its `Heat`; a process without a loop of its own is compiled at O2 at once; a sampled function under 64 IR instructions without a loop (a cycle of blocks; a process's way through its suspension does not count) stays interpreted (`too_short`) until a compiled function calls it, then it is compiled at O2; entries published through an atomic word, swapped in on entry and within 256 jumps; `stop(false)` drops the queue and joins an idle thread, and when it is busy the CLI closes the design's open files (`Runtime::close_files`) and ends the process with `exit_now` (`_exit` after flushing) | Compile time is paid in CPU and compiled code of testbenches gains little (a hot set of 22 library functions compiled before time 0 ran 8% faster at 6 s of compile), so tier-up must not cost more than a few percent of the run: compile time at most `Heat::budget` percent of the interpreted time seen, a function only after `PAYBACK` times its compile time, callees with their caller (a call into an interpreted function leaves the compiled code); the simulation and the exit never wait for compilation; output independent of compile timing (rule 5); LLVM static destructors never run under the compile thread; sampling costs the simulation one store per function entered, the per-op counting it replaced 12% to 25%; Module-local decisions go in this section in the same commit (root `AGENTS.md` rule 24).

- Deferred register stores (frame mode, `regs.rs`, `Gen::std`/`flush`; decisions.md "Tight compute loops"): a pure instruction's result is an SSA value stored only where the interpreter can look at the frame, by liveness. New code that reads or writes `c.regs` directly, or calls a callback with the register pointer, must go through `call_go`/`reg_out` or call `Gen::flush(c, pc)` itself; an arm with a fast and a slow path uses `Gen::st` (immediate), never `std`. `YAVS_LLVM_DUMP=<dir>` dumps the LLVM IR before and after optimisation and the yavs IR of each compiled function. `YAVS_PERFMAP=1` writes `/tmp/perf-<pid>.map` so `perf report` names the compiled code `f<id>` / `f<id>_n` (match the ids with the `f<id>.ir` files of `YAVS_LLVM_DUMP`). `Live::new` solves liveness per basic block and sweeps the rows of each block once (#710), so a process of tens of thousands of instructions costs milliseconds, not seconds; `MAX_WORDS` (1 << 25 words, 256 MiB of rows) is only a memory guard, and a function over it gets no deferral. Code generated after a step in a slow path (`Gen::layout_keep`) reads the register the stepped instruction defined from the frame, never through `ld`/`pend`: it takes the deferred value of that register out for its length (the fast path may still read it as an input and redefines it with `st`).

- Registers and frame variables across blocks (frame mode, `regs.rs`, `Gen::edge_prep`/`edge_to`/`begin_block`, `Plan`, `Scalars`; decisions.md "Registers and frame variables across blocks"): in the natural loops of a function a deferred register is not stored at a block edge but passed to the successor's phi (`Plan::regs`/`phis`, only registers some instruction defers (`deferrable`), live into the block, not preloaded or fixed); a block reached by one edge from an earlier instruction takes that edge's deferred values as they are (`Plan::single`, `inherit`); every other block takes its registers from the frame as before, and `edge_prep` stores a deferred value no phi takes. Only the start, the pcs after a call, wait or report (`resumes`), loop headers and the preloaded definitions after them have an entry stub (loads the phi values from the frame); the interpreter that lands elsewhere gets `pc` back and runs on to the next jump (`tier_go`). A frame variable (a slot only `Load` and `Store` reach through address registers of its own, at one width, in a function no other function nests in, accessed in a loop without a `loud` instruction; at most 12) is deferred register `nregs + k`: `Gen::vslot_value` loads it once, `Store` only defines it, and it is written back by `flush_row`/`flush_exit` where something may look at the frame (`Scalars::observes` is the liveness rule: every instruction that can leave or call out). A `quiet` step (no collection, no other code: everything but calls, allocation, reports, waits) writes variables back only when it fails (`call_go`), a direct call to a native frame likewise (`native_call`). The last pend entry is the base of the frame's slots (`own_slots_cached`), carried through loops and forgotten by `call_go` and by `join` after a slow path that may push a frame (`slow_path`/`slow_signal` save and restore it: a value found in a branch does not dominate the join). New code that creates a join block of a slow path must go through `slow_path`/`join`; one that defines a deferred value between a branch and its join must use `st`, not `std`. Registers defined once by `Const` or `ConstF` are constants everywhere (`fixed_consts`).

- Clocked RTL (#432, #339): `Drive` of one waveform element runs `yavs_rt_drive` (`TierHost::drive_block`, kernel `Ctx::assign_blocks`), `WaitOn`+`Suspend` runs `yavs_rt_wait`, a `WaitOn` of a wait on several signals `yavs_rt_wait_on` (`TierHost::wait_on_again`, the full callback only when the kernel has no registration to reuse, #532), the first statement of a wait that names the same signals every time (`yavs_interp::static_wait`) `yavs_rt_wait_same` (`TierHost::wait_same`: the process suspends there when the kernel still holds the last wait, #530), `SigRead` of a known count up to 64 and `Cat` of known piece lengths are inline (`Gen::sig_read_block`, `Gen::cat_block`; the groups of eight codes must lie within `TierSig::cap`, the codes rounded up to whole plane blocks, not within `TierSig::len`, so a vector of 1, 4 or 9 elements takes the inline path too; a count known only at run time, 1 to 64, calls `yavs_rt_codes`, which builds the planes from the codes and touches no host state, #565), `Alloc`/`DopeLen` and temporary and instance memory need no call; registers defined once by a `Const` are known everywhere (`fixed_consts`). `--tier=auto` compiles `rtl` process bodies at O0 (`auto.rs`). Alias scopes separate slots, temporaries, instance data, constants and code bytes. Rules: decisions.md "Compiled clocked RTL processes".

- Clocked RTL, round 2 (#432): `Tier::run_cached` keeps the heap objects `Mem::objs` found between activations (`TierState`, `Mem::load_objs`/`save_objs`/`forget_end`; valid while `TierFrame::heap_epoch` is unchanged; every space but frames and the temporary area, #510), `yavs_rt_drive` asks `TierHost::drive_now` first and `yavs_rt_wait` `TierHost::wait_again` (no view, no result), `LCopy` of up to 64 elements is inline (`Gen::lcopy_inline`). `--tier=auto` compiles clocked process bodies (`rtl`, 120 to 600 IR instructions) at the final level at once and measures them after the swap (`Worker::trial`, #596; the 160 to 300 band of #575 is a wait of `BAND_WAIT` (0.25 s, user 2026-10-23) for the bodies outside it now, `band_wait`). Rules: decisions.md "Compiled clocked RTL processes, round 2".

- Scalar logic assignments (#634; `Gen::drive_bit`, `yavs_rt_drive_bit`, `yavs_interp::scalar_drives`): the five instructions the lowering writes for `sig <= v` (waveform `Alloc`, `Store`, `Index`, `LSet`, `Drive`) are skipped at the sites the interpreter's predecoder fuses (`Op::LSetDrive`) and the `Drive` calls the host with the delay and the code; the sites must stay the interpreter's (it continues where compiled code leaves and does not define the waveform's registers either). Decisions.md "Compiled clocked RTL processes, round 5".

- Scalar drives kept for one host call (#676; `Batch`, `Gen::drive_bit`/`batch_flush`/`ret_exit`, `batched_drives`, `batch_pure`, `yavs_rt_drive_flush`, `TierHost::drive_bits`, `Ctx::assign_codes_now`): a zero-delay `ScalarDrive` of a process (time register a constant 0) is appended to a stack buffer of `yavs_interp::DRIVE_BATCH` entries when it is a plain one-element reference into a signal with `TierSig::codes` or `planes` and the code is at most 8; the host gets the buffer in one call before every instruction that is not in `batch_pure` and in every exit block (`exit_for` builds them through `ret_exit`). A new instruction kind that can drive, wait, call or look at a driver must stay out of `batch_pure`; a new way to leave the function must go through `exit_for`. A site is kept only when another kept drive can follow it within the activation (`batched_drives`). The unkept and the refused cases drive as before (`drive_bit_now`, `drive_bit_replay`). Decisions.md "Compiled clocked RTL processes, round 7".

- Clocked RTL, round 4 (#532, #339; decisions.md "Compiled clocked RTL processes, round 4"): `Inst::Edge` of every kind (`Gen::edge`; the known edge is one compare of `edge_key` with `TierFrame::known`, #632) and `'event` (`Gen::sig_event`) are answered from the kernel's event stamps and `'last_value` planes (`TierSig::stamps`/`last`, `TierFrame::cycle`; a signal of at most 64 elements), after the known-edge test; `SigReadScalar` reads the codes, else the kernel's plane blocks (`TierSig::planes`), else the bytes of an enumeration/integer/boolean/real signal (`bytes`/`es`, a four-byte element sign-extended); `SigRead` of any length reads the planes through `yavs_rt_planes` when the codes are not there (`Gen::sig_read_planes`, `sig_read_wide`); `Drive` of one waveform element takes `TierHost::drive_now` for 1 to 64 logic elements and one byte-signal scalar (the wave is 16 bytes there, flag bit 1 of `yavs_rt_drive`) and `TierHost::drive_wide` above 64 (flag bit 2); `LEq` of 1 to 64 elements is the four planes under a mask (its slow path, like that of `LFill`, goes through `slow_path_x`: a native frame hands the instruction to the interpreter's `native_step` instead of materialising the frame, which interpreted the rest of the call, #648); a `LayoutOf` with a frame slot (`cache`) checks the descriptor bytes against the slot's copy and answers with the address of the kept words (`layout_keep` fills it after the interpreter's step); `TempRoot` of a fat pair and `Stmt` with recorded roots call `yavs_rt_troot`/`yavs_rt_endstmt` in frame-mode code too; a constant `SigVal` is two deferred registers with `Known::Int` halves and a leaving guard. The slow path of an inline fast path (`slow_path`, `slow_path_with`, `slow_path_then`) is out of line: its blocks are in `Cur::cold`, its callbacks carry the `cold` call attribute, so the hot path falls through (`Gen::cold_depth`). `YAVS_COUNTERS=kinds|pc` (`yavs-interp` `tier_census`, printed as `counters: cb_<entry>.<Kind>` lines with the other work counters) counts what compiled code still sends to the host, by entry point and instruction kind (and function and pc): the tool for finding the next exit.

- Cache lines of an activation (#634, round 6; decisions.md "Compiled clocked RTL processes, round 6"): a design of thousands of processes misses in the cache on every line of a process it touches, and `view_root` read five scattered lines of a machine and its instance data for compiled code (`rtl_fan` compiled was 1.2 times the interpreter at equal instructions; `ibs_op` data sources showed the L3 hits in `view_again` and `run_quick`). `yavs_interp::Machine::vc` now holds them in one line, and the first three lines hold `spec_at`. When you add a read of machine state to `Host::view_again` or the entry, count the lines it touches (`perf record -e ibs_op// -d`, `ls_any_fills_from_sys.local_ccx`), not only the instructions. The scalar drive and the wait callbacks are a small hot function and a `#[cold]` slow path (`yavs_rt_drive_bit_slow`): the slow path inline gave the hot one a six-register prologue.

- Processes that leave their compiled code too often (#507; `auto.rs` `callbacks`, `too_many_callbacks`, `CALLBACKS`): a sampled process whose activation (the instructions reached from after each `Suspend` up to the next) has more than one instruction in ten that leaves the compiled code (`lower::leaves`: steps, stepped natives, drives, waits in the middle, `yavs_rt_native` natives, layouts through `yavs_rt_layout`; each `Stmt` too where `TempRoot`s record temporaries; signal reads, `'event`, clock edges, the wait that ends the activation and direct calls stay, #633; `is_inline` is what runs on native frames and no longer feeds the policy) stays interpreted with a note, as `too_short` does: each way out and back costs more than interpreting the instruction (the testbench process of `rtl_ram`, 33 of 258, ran 10% slower compiled; the clocked processes that gain have one in eleven or fewer). In every function an address of unknown space is looked up inline in `Mem::objs`, then in the temporary area and (reading) the instance data before `yavs_rt_host` is called (`Gen::host`; every function since #527, processes only before).

- Compile cost (#432, #501; `jit.rs`, `Gen::host`, `Gen::exit_for`, `lower::level_for`, `auto.rs` `tree`): the pass pipeline is `LEAN` (`sroa`, `early-cse`, one `instcombine`, `simplifycfg`, `adce`) for every function but a compute loop (`auto::compute`, full `default<O2>`, at most `FULL_MAX` LLVM instructions) and for the whole-program module of `--tier=llvm`; `CODEGEN_ARGS` switch off instruction scheduling and the machine-level motion passes (process-wide LLVM options, set once in `init`; no FastISel: it makes compute loops 40% slower). Optimised code generation is more than linear in a function's size (the register allocator's live-variable analysis over thousands of blocks): functions of `FAST_MIN` IR instructions or more and `--tier=llvm` modules over `EAGER_FAST_MIN` LLVM instructions are compiled at `OptLevel::Fast` (`LEAN` and the unoptimised code generator, 5 to 10 times cheaper per instruction, compiled code about 1.7 times slower). A phi with thousands of incoming values makes the simplifier quadratic: the exits of a function are blocks of at most `EXIT_PHI` predecessors. An access of unknown address space calls `yavs_rt_host` instead of testing frame, temporary and instance data inline (in processes the kept objects and the temporary area are tested inline first, round 3); `LCopy` is inline only in processes. `--tier=auto` compiles a hot native-callable function without a static link and without a loop as native-frame code only (the interpreter calls it through `Tier::call`; with a loop also its frame-mode code, for the interpreter to enter again after a materialisation; #510), and other functions' native-frame code only when a compiled caller needs it, and opens the LLVM library (40 million cycles) on the compile thread at the first compile, not at start (a failure is one warning on stderr). Tuning aids: `YAVS_LLVM_TIMES=1` (per `compile_one`: LLVM instructions before and after the passes, microseconds per phase), `YAVS_LLVM_PIPELINE=<pass pipeline>` and `YAVS_LLVM_ARGS=<LLVM options>` replace the defaults (an unknown option makes LLVM exit); `YAVS_LLVM_KINDS=1` (`--tier=llvm`) prints the LLVM instructions generated per IR instruction kind (frame-mode code before the passes: where the code size goes), `YAVS_LLVM_ABLATE=Kind,Kind` has the interpreter step those kinds instead (only kinds with a step path, not control flow), to measure what compiling them is worth (both hidden measuring aids); `perf stat -e cpu_core/instructions/u` on a run gives a load-independent compile cost. Aids for one big function (#630): `YAVS_LLVM_ONLY=12,34` (`--tier=llvm`: compile just these function ids, the rest runs in the interpreter; with `YAVS_LLVM_DUMP` the `f<id>.ir` of every function says which id is which, `--tier-max-size` lifts the cap), `YAVS_LLVM_TIMES` also prints generation, verification, passes and code generation of that module, `YAVS_LLVM_KINDS` counts every `1 + len/5000`th instruction and shares the growth among the kinds in between (exact below 5 000 IR instructions), `YAVS_LLVM_DUMP` writes `f<id>.ir` for every function `compile_one` makes too (copies of processes included), `YAVS_LLVM_OBJ=<dir>` writes the object files of a store (`objdump -d` next to `perf` and `YAVS_LLVM_PERFMAP`), `YAVS_AUTO_FORCE=name@min#first,..` (`--tier=auto`) compiles every function of that name with at least `min` IR instructions and an id of at least `first` (the copies of processes have the last ids) when it is first sampled, whatever the budget says. A module of more than `HUGE_MIN` (100 000) LLVM instructions gets `LEAN_HUGE`: `dce` for `simplifycfg` and `adce`, which grew with the square of the module (66 s and 31 s of 115 s at 7 million instructions). A function of `COMPUTE_MAX` (1 500) IR instructions or more is compiled at `Fast` even when `auto::compute` calls it a compute loop (a process of 30 000 instructions and two short `for` loops took 35 s of optimised code generation for 670 000 LLVM instructions, `Fast` 8 s).

- Search loops (#573; `auto.rs` `fused_search`): a sampled function whose loops are all of the shape `Pos`, `Index`, `Load`, compare, index step stays interpreted, the interpreter runs such a loop as one fused op (`pre::SCAN`) faster than the compiled code reads the elements (#578). Keep the test in step with the interpreter's fusion when it changes; decisions.md "search loops stay interpreted".

- `--tier=auto` decisions are a function of the looks (#670, #673, #680, #681; decisions.md "`--tier=auto` decisions follow the looks of a sampler thread"): the `yavs-sampler` thread (`sampler_loop`) sends `Look`s (CPU time of the simulation threads since the last look, `Look::dt`, and what they run) in batches of `BATCH`, also while the compile thread compiles or runs a trial (`Shared::trial` pauses it); the compile thread takes one batch at a time (`Worker::see`, then the decisions), so the sequence of decisions does not depend on how long a compile took. Time is the CPU time of the simulation threads (`sim_cpu_sampler`: process less the sampler's and the compile thread's own clocks), not wall time, which counted the time the compile thread took from the simulation. Prices are constants, never measured (`price`, `payback_cost`, `US_PER_INSTR*`): a measured rate depends on load and on whether the cache hit. `payback_cost` is flat 800 per IR instruction so that big `Fast` processes compile as late as before; the budget (`price`, `cost`) charges `Fast` code its own 110. `spent` is charged by the model too. A new decision must read only the looks and the program, never a clock or the time a compile took (`what_is_hot_depends_on_the_looks_only`); a `HashSet` is sorted before it decides an order. What stays timing dependent: the CPU speed of the host itself (a function near a threshold flips), trial verdicts near their keep line, the compile that is running when the run ends (not stored), and through the compilation cache the marginal functions of the earlier runs.

- Optimised register allocation for hot large frame-mode functions (#715, decisions.md "llvm: `OptLevel::FastRa` ..."): `OptLevel::FastRa` is `Fast` with the greedy allocator, made per target machine (level `Less`, `LLVMSetTargetMachineFastISel`, functions `optnone noinline` after the passes, `jit::no_opt`), never by `-optimize-regalloc`/`-regalloc` (process-wide, and the first cannot be put back to unset). ORC cannot be given the FastISel setting: a `FastRa` module is always `Module::emit`ted and added as an object (`objcache::add`), in its own `Jit` (`Worker::jitr`: same symbol names as the `Fast` module). The policy: `Worker::fast` marks a frame-mode function (not `natively`) compiled at `Fast`; its compiled-time threshold is `PAYBACK_RA` times `ra_cost` of its IR instructions (`Worker::threshold`), then the O2 recompile queue makes it `FastRa`. The constants belong to the pricing (#670): change them with `US_PER_INSTR*` and `ra_cost`, from measured code generation times, and keep the payback rule a function of the looks. With `--tier-heat` (budget 0) every second compile of a function of `FAST_MIN` instructions or more is `FastRa`, which is how the differential tests run the level.
- `--tier=auto` policy (#572; `auto.rs` `pick`, `first_fit`, `Trace`; decisions.md "`--tier=auto` compile policy"): `pick` prices every candidate and compiles the hottest per cost that fits the budget, a refused one waits alone for `pick_at` (it used to hold up all the others); a function called natively is compiled after `PAYBACK_NATIVE` (2) times its compile time seen and gets `NATIVE_BUDGET` (16) times the budget. A callee of a candidate that was never seen running and has more than `UNSEEN_MIN` IR instructions is left out of its compile (`left_out`; its caller's native code is published without it, #493). `YAVS_AUTO_TRACE=1` prints the compile thread's timeline on stderr (compiles with first-seen and candidate ages, refusals with the time they fit at, the most sampled functions at the end): read it first when a hot function is compiled late. Measure a policy change with `perf stat --no-inherit -e cycles:u,instructions:u` on `exec yavs ...` (the main thread only: the compile thread's work is not in it, and instructions vary by 1 percent where wall varies by 10 on a loaded host), on a fresh world per binary and tier (a warm world must not outlive a binary: the compilation cache and its list of compiled functions are part of the result), cold = a copy of the pristine world per run.
- Copies of processes under `--tier=auto` (#661; `docs/design/specialisation.md` section 11, decisions.md "Specialised copies of processes"): a copy (`Program::copy_of`, its own function id in a reserved slot) is sampled under its own id, but every policy decision goes by its process (`Program::base_of`): `Worker::group` is the interpreted time of the process and all its copies, which `threshold`, the payback rule, `wants_probe` and `cold` read; `Worker::is_rtl`, `base_len` and `cost` classify and price a copy as the process's shared code (the copy's own length only prices its compile); every copy that is seen running is a candidate once the process is hot (`asked_for`), compiled from its own code; a trial that takes one copy back keeps the others not compiled yet interpreted (`lost`). `compile_one` names a copy's symbols by `Program::copy_tag` (`f<process>c<tag>`), not by its id, so the compilation cache key (the bitcode) is the same in every run whatever order the processes switched in (`tests/objcache.rs`).

- Closed native frames (#626; `closed_frame`, `Nat::closed`, decisions.md "Compiled protected-method accessors, round 2"): a native frame none of whose frame addresses leaves its own `Load`/`Store` addresses is not registered in `Mem::nslots` (length 0 is written) and its slots are an `alloca` that `sroa` promotes. A new instruction that takes a frame address register must make `closed_frame` return `None` for it (it does by default: only `Load`/`Store` addresses are allowed). `Gen::host` leaves out the own-frame test for such a frame.

- Address spaces across blocks (#684, #685; `regs::spaces`, `Known::InstAny`, `Known::Up`): `Gen::func` starts a block with the preloaded facts plus the registers `spaces` proves hold an instance-data, temporary or heap address on every path (a new instruction that defines such an address must be added to its transfer function, else the fact lapses safely); an `Index` keeps the space of its base. `Known::Up(d)` is an address in the slots of the frame `d` links up, read from `TierFrame::up_slots`/`up_len` (frame-mode code only; a new place that changes the stacks must refresh the view with `tier_view`, which fills them).

- Held heap objects (#626; `ObjRef`, `Known::Heap(Some(_))`, `Cur::objnew`, native frames only): after a `Deref` the generated code has the object's pointer and length as values and every address derived from it (`Index`, `Field`, `Move`) carries its offset; `Gen::host` uses them. Facts are dropped at the first instruction outside `keeps_objects` and at block starts. A new instruction that frees or moves a heap object must stay out of `keeps_objects`; a new way to derive an address from a held one must set `Cur::objnew` or leave the fact to lapse (it does by default).

- Code arena and the shape of frame-mode code (#679; `arena.rs`, `Gen::entry_dispatch`, `Gen::cond_br`; decisions.md "llvm: code in one arena of huge pages, ..."): on Linux x86_64 the object layer is RuntimeDyld with our own section allocator (JITLink's allocator cannot be replaced through the C API), so all compiled code is one region that can be a huge page; the code zone is read-write-execute (nothing to finalise); anything else keeps LLJIT's default. The entry switch of a frame-mode function (`pc` to the entry blocks) is a tree of range compares with `switch` leaves of at most four cases: the unoptimised code generator lowers a big `switch` to a chain of compares, and a process is entered at one of thousands of pcs at every resume. `cond_br(.., likely = true)` branches on the negation of a condition that is not a compare, so the rare edge is the `jcc` and the hot path falls through (the code generator turns `br c, hot, cold` of a computed `c` into `jcc hot; jmp cold` with `hot` the next block). Tried and dropped: machine function splitting (a made-up profile summary and entry counts make LLVM move the blocks the guards' weights call rare into a second section; the arena put it in its own zone): the hot part of a 24 000-instruction process was 1.1 MB instead of 3.7 MB but L1i misses rose by a fifth and cycles did not move, because the rare edges are taken more often than their weights say; `zext(trunc)` for the 32-bit masks (instcombine turns it back into the mask). Small code model (#679, `jit.rs` `model`): with the arena the target machine is small + PIC and the runtime callbacks are `nonlazybind` (`Gen::effects`/`declare`: `call [rip+got]`; without the attribute RuntimeDyld makes a PLT stub per callback and object and every call pays a second jump); `YAVS_LLVM_CODEMODEL=large` keeps the JIT default; `target_id` carries the model; a section outside the arena in this model aborts (32-bit displacements, the release linker does not check them). Block order (`lower.rs` `layout`, at the end of `Gen::func`): blocks are put in execution order (likelier successor by branch weights next, cold blocks last); creation order put every join block before its fast path. `narrow_masks` (`jit.rs`, after the passes, only for the unoptimised code generator): `and (load i64), 0xffffffff` as `zext (load i32)`; before the passes it blocks store-to-load forwarding of constants. Tried and dropped: the address of an access made before its guard (code 0.4 percent larger, cycles level), other pass pipelines (`early-cse<memssa>`, `gvn`: code level or larger). Open: the reloads of the three function arguments at every block are 10 percent of the instructions of a large process (decisions.md).
- Element access in native frames (#493; `Inst::Pos` arms, `index_muls`/`Cur::imul`/`Cur::fused`, `Obj` aligned to 64 bytes, `OBJ_SHIFT`, `Gen::obj_entry`; decisions.md "llvm: element access in native frames ..."): `Pos` has one arm per direction (any other `dir` is the interpreter's); a `Bin Mul` by a constant whose product is used once, by the `Index` after it, is one test of its operand and settles the `Index`'s guard (`Cur::fused`; the `Index` must be no entry point); an entry of `Mem::objs` is one cache line and `obj_entry` builds its offset from the whole address or access value (`obj_entry_expression_is_obj_at` keeps it equal to `obj_at`). A new way to produce a position for `Index` must not rely on `fused`. Measure with `--tier=llvm` (deterministic) and, for `--tier=auto`, only after about twelve untimed runs of a private world: the set of compiled functions keeps growing and fewer runs compare unsettled builds. LLVM-level inlining of native callees was measured and not taken (instructions down, cycles level); the accessors wait for dependent loads.
- Search loops (#578; `yavs_interp::search_loops`, `yavs_rt_scan`, `Mem::span`, `scan_ctl`): at the head of a search loop in a native frame the generated code calls the helper with the loop's registers; `hit` 1 and 2 jump to the loop's exits (`ways` of those blocks is raised, so they take nothing from a predecessor), anything else falls into the generic head. The loop's exit blocks need the registers the loop defines besides the element and index dead (`search_loops` checks). `auto.rs` `fused_search` (#573) stays: the compiled loop is as fast as the interpreter's, but a function around it still ran 1.05 to 1.12 times the interpreter's cycles without the rule (#652, decisions.md "callees with their caller, `band_wait` 0.25 s, trials of looping processes").

- Copies of one module (#713; `compile_one`, `Jit::twins`, `Module::rename`, `objcache::note_twin`): a specialised copy of a process (`Program::copy_tag`) is generated under the fixed name `ftwin`, keyed by its module (bitcode with that name, level, `full`, part, native), renamed to `t<key>` and compiled once per `Jit`; another copy whose module is the same up to its name (instances that differ in data the code does not read) gets the entry points of the first and counts as linked from the cache (the auto budget charges the cache price). The compilation cache holds one object per distinct module and a warm run finds it by that name whatever order the copies switch in. Only copies are keyed this way (`YAVS_LLVM_TIMES` shows `pass` and `codegen` of the first only); a function whose module has any other difference is compiled as before.

## 4. Invariants and pitfalls

- A frame's registers when compiled code enters at any pc: the preloaded `Const`/`ConstF`/`AddrOf` values of `Pre`, zero elsewhere, and the registers holding a `lean` function's parameter slot address are zero too (`Pre::next` skips their `AddrOf`; #566). Never read them: address preloaded frame slots by the known offset (`Known::Frame`, `base_known` in `Gen::func`). A second code generator read the caller's parameter this way. Contract and test: `crates/yavs-interp/AGENTS.md` (`Pre::lean`).
- Compile cost is measured with `--no-cache` (or a fresh work library): with the cache a second run
  links what the first compiled, and `YAVS_LLVM_TIMES` then shows the generation and the link only.
- Measuring code quality: `--tier=llvm` gives a module over 150000 LLVM instructions the unoptimised code generator; `YAVS_LLVM_FAST_MIN=99999999` gives it the code `--tier=auto` makes for the functions it compiles at `O2`. Compare instructions or the simulate time of runs whose objects are all in the compilation cache (a difference of two runs that compiled differently measures the compile).
  A new setting that changes the machine code without changing the IR (a pass, a code generator
  switch, an environment variable) must be part of `objcache::key` (`jit::target_id`).
- A new runtime callback or table must reach compiled code as a symbol (`new_jit`) or as data of the
  module, never as an address constant in the IR: a stored object is linked in other processes
  (`objcache.rs`). The object cache key holds the IR, so such an address would only cost hits, but
  a module that stays identical while its meaning changes (code that reads a process-wide table
  through an address it did not put in the IR) would be wrong.
- `cargo test --workspace` does **not** build this crate's code (feature off): run the feature
  build yourself after any change here.
- `build.rs` runs `llvm-config` (`LLVM_SYS_211_PREFIX/bin`, else the path) and `llvm-nm`/`llvm-readelf` from its bindir on Linux; a stub exists for every `LLVM*` export, so an unused one costs nothing (the linker drops it).
- LLVM 21.1.8 with static libs is in `/usr/lib/llvm-21` on the dev host; `llvm-sys` finds it via
  `llvm-config` (Windows packages have none, see WINDOWS.md).
- Codegen cost grows faster than linearly with function size; measure with
  `examples/measure.rs` before changing thresholds, one process per row.
- CI (`llvm` job in `.github/workflows/ci.yml`, #127, #128) clippys, tests and runs 47 difftest cases
  with `--tier=llvm` and with `--tier=auto --tier-heat=1,0,0` (at 1 and 4 threads) on Linux x86_64, Linux aarch64 (native runner) and Windows x86_64 (tests only,
  the difftest harness needs a POSIX shell). Windows needs the steps in WINDOWS.md section 4: static
  CRT, empty `libxml2s.lib`, SDK import libs copied into the LLVM `lib` dir.

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-llvm --features llvm
CARGO_BUILD_JOBS=6 cargo test -p yavs-llvm --features llvm,gc-stress   # unit tests with a collection at every safepoint (#500)
cargo build -p yavs --features llvm                    # yavs with --tier=llvm
cargo clippy -p yavs-llvm --features llvm --all-targets -- -D warnings
cargo run --release -p yavs-llvm --features llvm --example measure -- <stmts> [O0|O1|O2]
```

- No diagnostic codes of its own: the `yavs` binary reports `--tier=llvm`/`auto` problems (`E0120`,
  `E0121`); a code of this crate would take a range in `crates/yavs-diag/src/lib.rs`.

A clocked process (`rtl`) is judged by the process runs of the kernel (`yavs_interp::sim_progress`, once per delta cycle; `BY_RUNS`: at least 1.05 times as fast, early verdicts); any other process (one that loops between its waits) by its activations (a process that is not `rtl`: `NativeFlags::count_on`/`count_off`/`entries`, flag `NAT_COUNT`, counted in `run_quick` only while its trial runs; `BY_ENTRIES`: all three pairs of windows, taken back below 0.95 only, because activations come in bursts and vary 10 to 25 percent between windows). A function is not measured: compiled callers use its native code (taking it away for a window makes each of their calls materialise a frame) and its entries vary with the phase of the run.
