# AGENTS.md: yavs-rt

Read the root `AGENTS.md` first. This file is for an agent about to change `crates/yavs-rt`.

## 1. Purpose and boundaries

- The **runtime of the compiled tier**. It was `yavs-llvm` until 2026-11-10: the LLVM tier it was
  written for (LLVM 21, ORC LLJIT, `--tier=llvm` and `--tier=auto3`) was removed on 2026-11-08 (user
  decision, `docs/decisions.md` "LLVM tier removed"). The Cranelift tier (`yavs-clift`, feature
  `clift`) is the compiled tier and runs on this crate.
- What stays: `rt.rs` (the frame view `Mem`, the `yavs_rt_*` host callbacks compiled code calls,
  `enter`/`call`, the per-function analyses the lowering uses), `native.rs` (which functions run on
  native frames), `regs.rs` (frame-mode analyses), `eloop.rs` (element loops), `generator.rs` (the
  `Generator` trait the policy drives; `yavs-clift`'s `First` is the one generator), `auto.rs` (the
  tier-up policy of `--tier=auto`: sampler, count rule, budget, `--tier-compile`), `census.rs`,
  `profile.rs` (the run-to-run profile), `work.rs` (the work clock), `hugezone.rs` (the huge-page
  zones behind `yavs-clift`'s code arena) and `perfmap.rs`.
- Rows below that name `Gen`, `lower.rs`, `jit.rs`, `objcache.rs`, `arena.rs`, `LlvmTier` or LLVM
  passes describe the removed LLVM generator. They stay as the record of why the shared runtime is
  shaped as it is (the Cranelift lowering follows the same designs: native-frame convention, exits,
  object table, drives and waits); prune them as you touch them. The policy's branches for a second,
  optimising generator (`Gens::main`, `OptLevel`, `Fast`/`FastRa`, `PAYBACK_RA`, `Tune::MAIN`) were
  removed on 2026-11-10 with the rename: `AutoTier::start_with` takes the one generator.
- Depends on: `yavs-ir`, `yavs-interp`, `yavs-kernel`, `yavs-cache`. Called by: `yavs-clift` and the
  `yavs` binary (feature `clift`).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| The interpreter is the semantic reference: every suite must give identical output compiled and interpreter-only | Rule 5 | `docs/plan.md` rule 5, "Verification" |
| Self-contained compiled code on interpreter frames: every instruction it does not lower runs in place through `yavs_rt_step` (calls and natives included); a pushed callee with compiled code runs directly and `TierHost::ret` pops it; it returns to the interpreter only at `Ret`, `Suspend`, failing inline instructions and frames it cannot finish (`TIER_UNWIND`) | Rule 5 by construction; one implementation of frames, heap and traces; no exit per call (user decision, 2026-10-20) | `docs/decisions.md` "LLVM tier: side exits", #336, #337 |
| A non-native process function without `MAY_SUSPEND` stays in compiled code across its retreating `Br`s (`Gen::func`, `Inst::Br`): it polls `TierFrame::stop` (#737) and adds one to a local jump count (loaded from `TierFrame::spin`, the machine's `Machine::spin`, at the entry; stored back in every exit block by `spin_out`), and leaves at that `Br` on a stop request or when the count is a multiple of `yavs_interp::SPIN_CHECK`: the interpreter steps the `Br`, counts it, trims the run's lists (`Ctx::trim_run`) and reports `E3009` at the limit (10^9, `YAVS_SPIN_LIMIT`). The count and the stop flag have their own alias scopes (`AA_SPIN`, `AA_STOP`, `AA_MEM`) so a loop without calls keeps the count in a register; a count kept in memory cost 23 percent of a compute loop | Ctrl-C must end any run and the activation must be bounded (#583) whatever tier runs the process, without taking the process out of compiled code (user, 2026-10-26); the interpreter stays the one implementation of both | `docs/decisions.md` "A process that never suspends stays in compiled code" |
| Memory instructions run natively only where the bytes lie in memory `Mem` reaches and no error is possible; anything else steps the whole instruction, before any side effect | Rule 5: one implementation of address spaces and errors | `docs/decisions.md` "LLVM tier: side exits" (Memory) |
| Vector work compiled code does not inline calls the interpreter's own Rust functions directly (`yavs_rt_lcopy` runs `copy_bits`; `TierHost::signal` runs `sig_read_vec`, `drive`, `wait_for`), never a second implementation in LLVM IR; the one exception is `yavs_rt_cat` (a native frame's `Cat` of bytes, `Cb::Cat`), which makes the moves and stores of `Machine::cat` itself on what `Mem::find` reaches, because `Machine::cat` reads the machine's registers; a constant known at generation time (`Bytes` form, at most 4 KiB) is read from a private copy in the module, the bytes the interpreter reads | Rule 5; constants never change; the object lookup per activation cost 5% of clocked RTL | `docs/decisions.md` "LLVM tier: side exits" (Vector process bodies) |
| GC roots: `New`, `Free`, `TempRoot`, natives and calls are stepped with the registers, slots and temporaries in the machine (compiled code stores every register at once and hands the temporary length back before a step), so a collection inside an activation sees them; frames compiled code called through wait at their call's pc; `Stmt` steps while `Mem::temp_roots` (`TierFrame::temp_roots`) is non-zero so the interpreter drops the ending statement's recorded temporaries | Precise roots in both tiers (#422) | `docs/decisions.md` "Shared heap collection" |
| Native frames for native-callable functions (`native_set`): compiled callers call them directly; the frame becomes an interpreter frame (`TierHost::materialise`) only at a step, a failing instruction, the depth limit or the native stack allowance, and the interpreter goes on from there (`TIER_UNWIND`); processes and other functions stay frame-mode; frame-mode code has entries after preloaded definitions | A compiled call cost what an interpreted one did; materialised frames keep traces, roots and errors the interpreter's | `docs/decisions.md` "Compiled frames and calls between compiled functions", #432 |
| A native frame leaves at an exit site, never through a shared block carrying every register: `Gen::leave` stores the registers live before the pc (`regs::Live`) into the function's spill buffer (an `alloca` that escapes only to `yavs_rt_deopt`) and branches with the pc; blocks of failing guards go behind the rest of the function (`Cur::cold`) | One block taking all registers through phis made the code generator copy every register on every guard edge (475 blocks, 130 phis for a 100-instruction procedure) and kept all of them live to the last guard; `--tier=llvm` ran codec loops slower than the interpreter | `docs/decisions.md` "Native frames: every exit records the registers live at its pc", #554 |
| A register `Deref` defined is a known heap address (`Known::Heap`): `Gen::host` leaves out the frame, temporary and instance tries for it; the object table key is the object index with bit 3 flipped for a shared heap, computed from an address (`obj_at`, `Gen::obj_entry`) and from an access value (`obj_entry` with `handle`) alike | A private and a shared heap object of the same index evicted each other at every access of a protected-type library function; a frame test per heap access was a third of the access | `docs/decisions.md` "Compiled memory access: heap addresses are known", #554 |
| `Deref` and heap addresses go through the object table (`Mem::objs`), not a flat view of the heap's slots: the view (#655) was built and passed its cross-check, but its hit path is longer than the table's (24 LLVM instructions against 18) and the whole of the callbacks it saves is 1 to 3 percent of the window generator; a change to this rule starts from the measurements in decisions.md | Instructions of one protected `get` 336 to 367, `protected_queue` +7 percent, window generator +3 percent with the view | `docs/decisions.md` "A flat view of the heap slots for compiled `Deref`" |
| Calls from the interpreter on native frames (`Tier::call`, #510): a function without a static link that has native-frame code gets an adapter `f<id>_c(env, mem, depth, cells)`; the interpreter's `Call`/`CallProt` of a function `NativeFlags::set_call` marks calls it with the argument cells from its registers instead of pushing a frame, as a frame-mode caller's `Gen::native_call` would (depth limit, shared state of a protected call, `TIER_SHARED_ALLOC`); a materialisation pushes the frames on the caller and the interpreter goes on with them; `call_on` begins with the calling machine's record (`TierHost::tier_state`) and keeps it again after the call (`set_tier_state`, `at` left as it was), so the objects its compiled code found stay found when the interpreter calls in from another machine's turn (#520) | A compiled function entered from the interpreter cost a frame push, the frame view and frame-mode code that steps `NewFrame`, `Cat`, `Fill`, `TempRoot`, so short functions ran slower compiled (#510) | `docs/decisions.md` "Native calls from the interpreter and the object table" |
| Native frames never see a collection: instructions that can collect first ask `Machine::reclaim_pending` and leave to the interpreter when one is due; natives, `New` and the rest without an inline form run on the interpreter's own code (`native_direct`, `native_step`), and a failure there is a replay by the interpreter, never an error reported from compiled code; a `Free` is one call of `yavs_rt_free` (`TierHost::free`: the object deallocated, the heap epochs in the view, `Mem::forget_heap`), which declines with nothing changed when `Machine::reclaim_work` (a collection or recycling due), a stale value or a cell inside the freed object would make the interpreter's step do more | Precise roots (#422) and the interpreter's errors and traces with no spill map | `docs/decisions.md` "Native frames, round two" |
| Natives of frame-mode code (`frame_direct`, #565): a `CallNative` of a native `direct_native` allows (pure natives, `now`, `writeline`, the file open and close) calls `yavs_rt_native` with `NATIVE_FRAME_MODE | pc` as its depth, which runs `TierHost::native_frame` (the machine's `native_direct` for the top frame without the slot windows; declines while a package initialisation or an elaboration trace is on, a collection is due, the native fails or hands its call to the VHDL body). - Deferred register stores (frame mode, `regs.rs`, `Gen::std`/`flush`; decisions.md "Tight compute loops"): a pure instruction's result is an SSA value stored only where the interpreter can look at the frame, by liveness. New code that reads or writes `c.regs` directly, or calls a callback with the register pointer, must go through `call_go`/`reg_out` or call `Gen::flush(c, pc)` itself; an arm with a fast and a slow path uses `Gen::st` (immediate), never `std`. `YAVS_LLVM_DUMP=<dir>` dumps the LLVM IR before and after optimisation and the yavs IR of each compiled function. `YAVS_PERFMAP=1` (same as `YAVS_LLVM_PERFMAP`) writes `/tmp/perf-<pid>.map` so `perf report` names the compiled code `f<id>_<label>` / `n<id>_<label>` (object sizes from the object files; match the ids with the `f<id>.ir` files of `YAVS_LLVM_DUMP`). `Live::new` solves liveness per basic block and sweeps the rows of each block once (#710), so a process of tens of thousands of instructions costs milliseconds, not seconds; `MAX_WORDS` (1 << 25 words, 256 MiB of rows) is only a memory guard, and a function over it gets no deferral. Code generated after a step in a slow path (`Gen::layout_keep`) reads the register the stepped instruction defined from the frame, never through `ld`/`pend`: it takes the deferred value of that register out for its length (the fast path may still read it as an input and redefines it with `st`).

- Registers and frame variables across blocks (frame mode, `regs.rs`, `Gen::edge_prep`/`edge_to`/`begin_block`, `Plan`, `Scalars`; decisions.md "Registers and frame variables across blocks"): in the natural loops of a function a deferred register is not stored at a block edge but passed to the successor's phi (`Plan::regs`/`phis`, only registers some instruction defers (`deferrable`), live into the block, not preloaded or fixed); a block reached by one edge from an earlier instruction takes that edge's deferred values as they are (`Plan::single`, `inherit`); every other block takes its registers from the frame as before, and `edge_prep` stores a deferred value no phi takes. Only the start, the pcs after a call, wait or report (`resumes`), loop headers and the preloaded definitions after them have an entry stub (loads the phi values from the frame); the interpreter that lands elsewhere gets `pc` back and runs on to the next jump (`tier_go`). A frame variable (a slot only `Load` and `Store` reach through address registers of its own, at one width, in a function no other function nests in, accessed in a loop without a `loud` instruction; at most 12) is deferred register `nregs + k`: `Gen::vslot_value` loads it once, `Store` only defines it, and it is written back by `flush_row`/`flush_exit` where something may look at the frame (`Scalars::observes` is the liveness rule: every instruction that can leave or call out). A `quiet` step (no collection, no other code: everything but calls, allocation, reports, waits) writes variables back only when it fails (`call_go`), a direct call to a native frame likewise (`native_call`). The last pend entry is the base of the frame's slots (`own_slots_cached`), carried through loops and forgotten by `call_go` and by `join` after a slow path that may push a frame (`slow_path`/`slow_signal` save and restore it: a value found in a branch does not dominate the join). New code that creates a join block of a slow path must go through `slow_path`/`join`; one that defines a deferred value between a branch and its join must use `st`, not `std`. Registers defined once by `Const` or `ConstF` are constants everywhere (`fixed_consts`).

- Round 12 (decisions.md "Compiled clocked RTL processes, round 12"): `rt::direct_entry::<T>` is a tier's `Tier::direct`, the whole compiled activation in one function, with `Tier::run_cached` and `rt::enter` inlined (`#[inline(always)]`) and `InterpProcess::run` jumping to it with no frame of its own. `Tier::run_cached` and `enter` have no `state` parameter any more: `View::record` gives the record, a raw pointer read at `Mem::begin` and written at the end, never held across the call of compiled code. `Env::pending` is `Option<Box<..>>`, `Mem::sync` tests in line. A new generator returns `Some(direct_entry::<Self>)` from `direct` or runs through `run_cached` as before.
- Cache lines of an activation (#634, round 6; decisions.md "Compiled clocked RTL processes, round 6"): a design of thousands of processes misses in the cache on every line of a process it touches, and `view_root` read five scattered lines of a machine and its instance data for compiled code (`rtl_fan` compiled was 1.2 times the interpreter at equal instructions; `ibs_op` data sources showed the L3 hits in `view_again` and `run_quick`). `yavs_interp::Machine::vc` now holds them in one line, and the first three lines hold `spec_at`. When you add a read of machine state to `Host::view_again` or the entry, count the lines it touches (`perf record -e ibs_op// -d`, `ls_any_fills_from_sys.local_ccx`), not only the instructions. The scalar drive and the wait callbacks are a small hot function and a `#[cold]` slow path (`yavs_rt_drive_bit_slow`): the slow path inline gave the hot one a six-register prologue.

- Processes that leave their compiled code too often (#507; `auto.rs` `callbacks`, `too_many_callbacks`, `CALLBACKS`): a sampled process whose activation (the instructions reached from after each `Suspend` up to the next) has more than one instruction in ten that leaves the compiled code (`lower::leaves`: steps, stepped natives, drives, waits in the middle, `yavs_rt_native` natives, layouts through `yavs_rt_layout`; each `Stmt` too where `TempRoot`s record temporaries; signal reads, `'event`, clock edges, the wait that ends the activation and direct calls stay, #633; with `Tune::wait_same` the `WaitOn`s of a static wait count as one, #1046; `is_inline` is what runs on native frames and no longer feeds the policy) stays interpreted with a note, as `too_short` does: each way out and back costs more than interpreting the instruction (the testbench process of `rtl_ram`, 33 of 258, ran 10% slower compiled; the clocked processes that gain have one in eleven or fewer). In every function an address of unknown space is looked up inline in `Mem::objs`, then in the temporary area and (reading) the instance data before `yavs_rt_host` is called (`Gen::host`; every function since #527, processes only before).


- Element loops on native frames (#757; `yavs_interp::elem_loops`, `eloop.rs`, `Gen::eloop_plan`, `yavs_rt_eloop_exec`, `yavs_rt_eloop`, `Cb::Eloop`, decisions.md "Element loops in compiled code" and "Element loops planned in the compiled code itself"): the loop's program is straight-line code at the head of the loop (`eloop_plan`: values as pairs, the checks of `eloop::run` as overflow flags and bounds tests, `Gen::host` for the memory (`Gen::eloop_host`: unknown space is `LikelyTemp`, the temporary area first), then the elements: a copy inside one plane block each side with equal unit steps and the blocks apart inline (four masked word moves), else one `yavs_rt_eloop_exec` call; `eloop::invariant_steps` says which programs it takes, the others and `YAVS_LLVM_ELOOP_HELPER=1` use the helper call described next, `eloop_call`). The helper: at the first instruction of the head block, when at least two iterations are to go (`ind != bound` and `ind + step != bound`), compiled code calls `yavs_rt_eloop(env, mem, prog, nprog, inputs, ind, bound, step, depth, fhi, slots, slots_len)` with the loop's program as a private 8-byte aligned constant of the module (so the compilation cache key holds it) and the values of the registers it reads in an `alloca` of `MAX_INPUTS` words; a result over 0 is the iterations done, the loop variable moves by that many steps and the generic code goes on in the same block, running the last iteration (and with it the exit and every register the body defines) or the whole loop when the result is 0 (a position or element out of range, a vector that overlaps what was read, memory the table does not reach: the failure comes at its own iteration with its own message). The calling frame's own slots are passed (`Mem::region` finds the frames above it only), so a loop over a descriptor in a slot works; a closed frame (`Nat::closed`) gets no hook, the slots are not in memory. Frame-mode code has no hook. `YAVS_LLVM_NO_ELOOP=1` leaves the hooks out (A/B measurements), `YAVS_LLVM_KINDLOC=1` prints each loop found. `yavs_rt_lcopy` of at most 64 elements within the blocks it was given does not stage them (the same `get_run`/`put_run`)

- Native-frame code that cannot be made (`auto.rs` `no_native`, `native_ok`, `refused_at`, `frame_instead`, `entered_from_code`, `declined`, decisions.md "`--tier=auto`: a function the generator has no native-frame variant for gets frame-mode code once compiled code calls it"): a `Part::Native` compile with no `native` and no `run` records the refusal for its generator's rank; the function gets `Part::Frame` once a caller has compiled code, else it is `declined` and `see` asks again when one has; `natural_part` and `tree` choose by `native_ok`, `kind_of`/`factor` stay static. Tests: `crates/yavs/tests/clift_natfall.rs` (eager heat, where the caller is compiled first on any host, and the sampler path, which waits for the compile in the trace instead of guessing a run length).

- A compile pays for its tree (#757; `auto.rs` `Worker::repays`, decisions.md "`--tier=auto`: a compile pays for the callees it brings"): `pick` leaves a candidate waiting (no `pick_at`) while the seen time of its tree over each kind's payback is below the prices of the tree (`/ profile::EARLY_RUNS` once `earlier.base` says the program ran before); the root's term is `need`, so a new rule on the root belongs in `threshold`. `need` rounds up so that `threshold` and `repays` agree at the line.

- Large functions with loops (#679; `auto.rs` `Kind::BigLoop`, `loop_share`, `BIG_LOOP_SHARE`; decisions.md "`--tier=auto`: large functions with loops are a kind of their own"): a large function (`native::big`) is `BigLoop` (speedup 1.15) when 10 percent or more of its own IR instructions are in loops, else `Big` (1.037, compiled about as late as the flat price had it). Straight-line large processes are level with the interpreter compiled (front-end bound, their work is drives and signal reads both tiers do alike); keep the line in a gap of measured processes (forced one by one, `--profile` pairs) when it moves. `Worker::tree` counts the root against `TREE_MAX`: dropping that brought the callees of large roots but made mid-size trees cost more than they saved (decisions.md).

- Search loops (#573; `auto.rs` `fused_search`): a sampled function whose loops are all of the shape `Pos`, `Index`, `Load`, compare, index step stays interpreted, the interpreter runs such a loop as one fused op (`pre::SCAN`) faster than the compiled code reads the elements (#578). Keep the test in step with the interpreter's fusion when it changes; decisions.md "search loops stay interpreted".

- `--tier=auto` decisions are a function of the looks (#670, #673, #680, #681; decisions.md "`--tier=auto` decisions follow the looks of a sampler thread"): the `yavs-sampler` thread (`sampler_loop`; started by the compile thread after `START_AFTER` and ended by it, every sleep is `nap`, parkable: a stop never waits out a period, #725) sends `Look`s (CPU time of the simulation threads since the last look, `Look::dt`, and what they run) in batches of `BATCH`, also while the compile thread compiles or runs a trial (`Shared::trial` pauses it); the compile thread takes one batch at a time (`Worker::see`, then the decisions), so the sequence of decisions does not depend on how long a compile took. Where the counters are refused, time is the simulation CPU (`sim_cpu`: the CPU clock of the kernel thread, the one that made the tier; the trials' windows and the profile's `base` read it too), not wall time, which counted the time the compile thread took from the simulation, nor the process's CPU time, which counted the pool workers of `--threads` spinning between batches (a threaded `rtl_lfsr` read 6 times its wall time, #884). Prices are constants, never measured (`price`, `payback_cost`, `US_PER_INSTR*`): a measured rate depends on load and on whether the cache hit. `payback_cost` is flat 800 per IR instruction so that big `Fast` processes compile as late as before; the budget (`price`, `cost`) charges `Fast` code its own 110. `spent` is charged by the model too. A new decision must read only the looks and the program, never a clock or the time a compile took (`what_is_hot_depends_on_the_looks_only`); a `HashSet` is sorted before it decides an order. What stays timing dependent: the CPU speed of the host itself (a function near a threshold flips), trial verdicts near their keep line, the compile that is running when the run ends (not stored), and through the compilation cache the marginal functions of the earlier runs.

- `Worker::see` asks the class rules of `Worker::threshold` only of a function at or above the base threshold (#544): `natively` walks and optimises everything a function can call, which for every function the sampler ever saw meant optimising library code the run never executes.
- `--tier=auto` policy (#572; `auto.rs` `pick`, `first_fit`, `Trace`; decisions.md "`--tier=auto` compile policy"): `pick` prices every candidate and compiles the hottest per cost that fits the budget, a refused one waits alone for `pick_at` (it used to hold up all the others); a function called natively is compiled after its kind's payback times its compile time seen and gets `NATIVE_BUDGET` (16) times the budget. A callee of a candidate that was never seen running and has more than `UNSEEN_MIN` IR instructions is left out of its compile (`left_out`; its caller's native code is published without it, #493). `publish` asks `Worker::missing`: the native callees reachable from the function, the walk stopping at a callee that is `left` or was never seen running, must be compiled; it used to ask that of the whole native set, so a never-called callee that no tree brought kept the function and its native callers unpublished for the run (#797). `YAVS_AUTO_TRACE=1` prints the compile thread's timeline on stderr (compiles with first-seen and candidate ages, refusals with the time they fit at, the most sampled functions at the end, and `the run ends while compiling ...` for a compile the end of the run cut off, which the next run starts again): read it first when a hot function is compiled late. Measure a policy change with `perf stat --no-inherit -e cycles:u,instructions:u` on `exec yavs ...` (the main thread only: the compile thread's work is not in it, and instructions vary by 1 percent where wall varies by 10 on a loaded host), on a fresh world per binary and tier (a warm world must not outlive a binary: the compilation cache and its list of compiled functions are part of the result), cold = a copy of the pristine world per run.
- Rules per generator (#481; `auto.rs` `Tune`, `Worker::tune`): the rules for clocked processes that depend on how dear the code is to make are one struct, `Tune::FIRST` (Cranelift; the LLVM tier had a second set, removed with it: 64 IR instructions at least, no wait outside the band, `Kind::RtlFew` under four instances, a thirty-second of the run; every kind priced at `FIRST_US_PER_INSTR` (45 us an IR instruction) with the speedups of `MODELS`; a root owes 8 times the price of the callees compiled with it, `tree_payback`, `Worker::pick`; a clocked process 16 times its own price, `payback_rtl`; both because the compiled code of library functions and of small processes gained next to nothing in instructions, #718). A subprogram of the size `native::big` says is `Kind::Big`/`BigLoop` (`Tune::big`), processes are not, and a `Kind::Frame` process is compiled (`Tune::frame`, on since #1046) but a `Kind::Frame` subprogram is not (`Tune::frame_calls`: its frame-mode code sends every calling process through the interpreter's loop for compiled code, decisions.md "Cranelift tier, round 11" and "Compiling `Kind::Frame` processes"; a process is called by nothing, so only its own body changes; the compile budget and payback rules are the only limit). A wait that names the same signals every activation (`yavs_interp::static_wait`) counts once in `callbacks`, not once per `WaitOn` of its list (`Tune::wait_same`, #1046: compiled code skips the whole wait with one `yavs_rt_wait_same` call). `YAVS_FIRST_TUNE=rtl_min=N,band=0|1,instances=N,share=N,tree_payback=N,payback_rtl=N,big=0|1,frame=0|1,frame_calls=0|1,wait_same=0|1` overrides `FIRST` for a measurement. The compilation cache the policy probes and prices is the generator's: its list of compiled functions (`listed`), its cached-only mode during a probe, its notes after a compile; a link from its cache costs `FIRST_HIT` (4 us an IR instruction). The class rules of `Worker::threshold` (`natively`, `is_compute`) walk everything a function can call and optimise it, so `Worker::see` asks them only of a function at or above the base threshold (#544). A new generator-dependent rule goes into `Tune`, not into a second constant. The generators are told which functions a compile covers (`Generator::tree`, `Worker::announce`) and the budget is charged for the variants the generator reports as `Compiled::extra` (the root's compile made them, their own compile finds nothing to do).
- Copies of processes under `--tier=auto` (#661; `docs/design/specialisation.md` section 11, decisions.md "Specialised copies of processes"): a copy (`Program::copy_of`, its own function id in a reserved slot) is sampled under its own id, but every policy decision goes by its process (`Program::base_of`): `Worker::group` is the interpreted time of the process and all its copies, which `threshold`, the payback rule, `wants_probe` and `cold` read; `Worker::is_rtl`, `base_len` and `cost` classify and price a copy as the process's shared code (the copy's own length only prices its compile); every copy that is seen running is a candidate once the process is hot (`asked_for`) and, unless the process is a clocked one (`rtl`), once the copy itself was seen for its own payback (`need` of its own length: copies differ in their constants, so each is a module of its own, #757), compiled from its own code; the cache list (`listed`, `Worker::list_key`) names a copy by its `Program::copy_tag`, so one compiled copy does not make the others look cached; a trial that takes one copy back keeps the others not compiled yet interpreted (`lost`); the trial of the shared code of a process that can have copies (`Program::specialisable`) is not run, and its loss would not stop the copies (#675): its processes switch to their copies, which the tier compiles (`Tier::compiles_copies`), so the windows timed code that no longer ran (`rtl_lfsr` taken back at 1.0 after the copies were compiled by the tier). `compile_one` names a copy's symbols by `Program::copy_tag` (`f<process>c<tag>`), not by its id, so the compilation cache key (the bitcode) is the same in every run whatever order the processes switched in (`tests/objcache.rs`).
- Looks get sparser as a run goes on (#675; `auto.rs` `stretch`): the sampler takes a look every `Heat::period` of work for the first 300 ms of work seen, every second period to 1 s, then every fourth (a function of the work seen, so decisions stay a function of the looks). A look costs the simulation's core a wake-up (the sampler shares it under `taskset`): 1 ms looks were +3 percent wall on a 4 s run that compiles nothing (`fletcher_bufferwriter_512`), 4 ms looks +1.5. Every refusal is a line of `YAVS_AUTO_TRACE` (`refused f.. ... : why`, also the static rules `cold`, `too_short`, `too_many_callbacks`; once per function), and the final `seen` lines name each function's `Kind` and the seen time it is a candidate at. What compiling would gain was measured by forcing each hot function alone (`YAVS_AUTO_FORCE`, warm, medians of 4 to 6 worlds): the processes of `neorv32_single_min` (`request`, `exec_comb`, `counter_increment`, `arbiter_*`, `trace_packet_buffer`) gain nothing (+0 to +5 percent cycles each), so their refusals are right; in `sc5_fifo_repack` `p_in`, `p_sreg`, `p_input`, `p_pack` gain 3 to 7 percent each warm (compiled together 26 percent) but the copies of a process are different modules that each cost 50 to 90 ms of compile on the simulation's core for 20 to 50 ms of seen time, so the cold run does not repay them (decisions.md "`--tier=auto` round 5")

- Closed native frames (#626; `closed_frame`, `Nat::closed`, decisions.md "Compiled protected-method accessors, round 2"): a native frame none of whose frame addresses leaves its own `Load`/`Store` addresses is not registered in `Mem::nslots` (length 0 is written) and its slots are an `alloca` that `sroa` promotes. A new instruction that takes a frame address register must make `closed_frame` return `None` for it (it does by default: only `Load`/`Store` addresses are allowed). `Gen::host` leaves out the own-frame test for such a frame.

- Address spaces across blocks (#684, #685; `regs::spaces`, `Known::InstAny`, `Known::Up`): `Gen::func` starts a block with the preloaded facts plus the registers `spaces` proves hold an instance-data, temporary or heap address on every path (`Alloc` and `NewFrame` are temporary addresses) (a new instruction that defines such an address must be added to its transfer function, else the fact lapses safely); an `Index` keeps the space of its base; a `Load` through the address of a variable's slot (not a parameter's) or an enclosing subprogram's gives `Known::LikelyHeap` the same way (`Sp::Likely`, #768: a load the optimiser moved to a loop preheader keeps the hint, else each access of the loop asks the runtime). `Known::Up(d)` is an address in the slots of the frame `d` links up, read from `TierFrame::up_slots`/`up_len` (frame-mode code only; a new place that changes the stacks must refresh the view with `tier_view`, which fills them).

- Held heap objects (#626; `ObjRef`, `Known::Heap(Some(_))`, `Cur::objnew`, native frames only): after a `Deref` the generated code has the object's pointer and length as values and every address derived from it (`Index`, `Field`, `Move`) carries its offset; `Gen::host` uses them. Facts are dropped at the first instruction outside `keeps_objects` and at block starts. A new instruction that frees or moves a heap object must stay out of `keeps_objects`; a new way to derive an address from a held one must set `Cur::objnew` or leave the fact to lapse (it does by default).
- Address parameters (#726; `rt::param_addrs`, `stable_activation`, `Known::Param`, `Cur::pres`, `yavs_rt_region`, native frames only): a parameter a function loads in its entry block and uses as an address in a loop is resolved once at the entry into a host pointer and length; the register is `Known::Param(k)` in `base_known` (and again after its definition, `track` clears it) and `Gen::host` tests the pair before the old lookup, which a failed test takes. Native callers' frame slots are held for every function; the top frame, temporary area, instance data and heap objects only in a stable activation (no allocation, call, `Stmt`, `Deref`): a new instruction in the allowlist of `stable_activation` must not free or move any of them, resize the temporary area or push a frame, also in its slow path. In a `fixed_activation` (that allowlist plus `Alloc`, `NewFrame`, `Stmt`, `TempRoot`, `MakeDope`, `LayoutOf`: only the temporary area may move) everything but the temporary area is held (`yavs_rt_region` flag 4); a new instruction there must not free or move a heap object or push a frame, also in its slow path. Where objects are held the entry probes the parameter's `Mem::objs` entry inline before the callback (not for a frame or temporary address). A held region that misses takes `host_lookup` with `LikelyTemp`. A new way to derive an address from a parameter register must set `Known::Param` in `track` or leave the fact to lapse. `cb_region` counts the callbacks.

- Element access in native frames (#493; `Inst::Pos` arms, `index_muls`/`Cur::imul`/`Cur::fused`, `Obj` aligned to 64 bytes, `OBJ_SHIFT`, `Gen::obj_entry`; decisions.md "llvm: element access in native frames ..."): `Pos` has one arm per direction (any other `dir` is the interpreter's); a `Bin Mul` by a constant whose product is used once, by the `Index` after it, is one test of its operand and settles the `Index`'s guard (`Cur::fused`; the `Index` must be no entry point); an entry of `Mem::objs` is one cache line and `obj_entry` builds its offset from the whole address or access value (`obj_entry_expression_is_obj_at` keeps it equal to `obj_at`). A new way to produce a position for `Index` must not rely on `fused`. Measure with `--tier=llvm` (deterministic) and, for `--tier=auto`, only after about twelve untimed runs of a private world: the set of compiled functions keeps growing and fewer runs compare unsettled builds. LLVM-level inlining of native callees was measured and not taken (instructions down, cycles level); the accessors wait for dependent loads.
- Search loops (#578; `yavs_interp::search_loops`, `yavs_rt_scan`, `Mem::span`, `scan_ctl`): at the head of a search loop in a native frame the generated code calls the helper with the loop's registers; `hit` 1 and 2 jump to the loop's exits (`ways` of those blocks is raised, so they take nothing from a predecessor), anything else falls into the generic head. The loop's exit blocks need the registers the loop defines besides the element and index dead (`search_loops` checks). `auto.rs` `fused_search` (#573) stays: the compiled loop is as fast as the interpreter's, but a function around it still ran 1.05 to 1.12 times the interpreter's cycles without the rule (#652, decisions.md "callees with their caller, `band_wait` 0.25 s, trials of looping processes").

- Callbacks of large processes (#679, `docs/decisions.md` "llvm: large compiled processes lose to their callbacks, ..."): measure a big process by what its compiled code calls, not only by its bytes: `perf record -j any_call` (the last branch out of compiled code is the site) with `YAVS_PERFMAP`, and `YAVS_LLVM_PCLOC=1` with `YAVS_LLVM_KINDLOC` (debug line `2 * pc + 2` of the IR instruction, one more in a cold block, file `i<function id>`) and `YAVS_LLVM_OBJ` to map a site to its IR instruction. A `LayoutOf` that would be stepped and whose layout only one word is read of right after it (`Field`, `Load` of word 0, constant `Index` then `Load`; `fuse_layout`, `LayoutFuse`) is one `yavs_rt_layout_word` call into the interpreter's layout memo (`TierHost::layout_word`); the fused instructions generate nothing (`Cur::layout_fused`) and a decline leaves to the interpreter at the `LayoutOf`. A new instruction kind that reads a layout word belongs in `fuse_layout` only if the interpreter's predecoder fuses it too. The object table is keyed by machine as well as address (`Mem::tags`, one tag per address space: the machine's for instance data, package data and shared variables, the machine's at its heap epoch for heap objects, the runtime's for constants, the activation's for frames and temporaries; decisions.md "llvm: an object table keyed by machine"): a change of machine walks and restores nothing. Every lookup, in `rt.rs` (`Mem::get`, `Mem::slot`) and in generated code (`Gen::obj_tag`, `Gen::obj_entry`; the `Deref` hit test compares the tag too), must use the key of the object's space; a new way to drop objects is a new tag (`Mem::issue`), never a walk. A new address space needs its tag kind in `Mem::begin`/`restart`.

## 4. Invariants and pitfalls

- The native-frame calling convention is shared with `yavs-clift` (decisions.md "One native-frame calling convention for both generators"): `f<id>_n(env, mem, depth, [up1, up2], cells...) -> i64`, recorded frames signalled by `Mem::ndeopt`, variants in `Mem::ntab`. A change of `native_ty` or of the deopt protocol is a change of `native_sig` and `Gen::native_call` in `crates/yavs-clift/src/lower.rs`; `tests/compiled_mixed.rs` and `difftest.py --candidate yavs-mixed` catch a mismatch. `auto.rs`, `native.rs`, `regs.rs` and `generator.rs` are built without LLVM and take no `llvm_sys` type.
- A frame's registers when compiled code enters at any pc: the preloaded `Const`/`ConstF`/`AddrOf` values of `Pre`, zero elsewhere, and the registers holding a `lean` function's parameter slot address are zero too (`Pre::next` skips their `AddrOf`; #566). Never read them: address preloaded frame slots by the known offset (`Known::Frame`, `base_known` in `Gen::func`). A second code generator read the caller's parameter this way. Contract and test: `crates/yavs-interp/AGENTS.md` (`Pre::lean`).

## 5. How to work here

```sh
CARGO_BUILD_JOBS=6 cargo test -p yavs-rt                       # the policy and runtime unit tests
CARGO_BUILD_JOBS=6 cargo test -p yavs-rt --features gc-stress  # with a collection at every safepoint (#500)
cargo test -p yavs-clift -p yavs --features clift                # the compiled tier on this runtime
cargo build --release -p yavs --features clift,table-check       # a release yavs that panics when a lean activation reaches the object table (#766)
```

- No diagnostic codes of its own: the `yavs` binary reports `--tier` problems (`E0120`, `E0121`);
  a code of this crate would take a range in `crates/yavs-diag/src/lib.rs`.

## 6. Coordination

- `--candidate yavs-auto` and `yavs-clift` run the difftest corpus with the compiled tier (must equal
  `yavs-interp`); `YAVS_RUN_FLAGS=--tier-heat=1,0,0` (period 0) compiles every function from its first
  call or jump, so the swap-ins happen in the middle of each test.
  In that eager mode `Tier::hot` waits for the compile to finish (or to be declined), so a short run cannot
  end before its compile and `--verbose` notes (the #533 flake: the test saw no note when the run won the race).
- Measured take-back (#596, #652; `auto.rs` `Worker::trial`, `run_trial`, `decide`, `Rule`, `window`): after the swap of a compiled function seen for an eighth of the sampled time the compile thread compares the progress per CPU second with the compiled code and with the interpreter running the function (`Entry::clear`, `NativeFlags::clear`/`clear_call`, the `ntab`/`ctab` slots zeroed) in turn, and takes the code back (`lost`) when it did not pay. A clocked process (`rtl`) is judged by the process runs of the kernel (`yavs_interp::sim_progress`, once per delta cycle; `BY_RUNS`: at least 1.05 times as fast, early verdicts); any other process (one that loops between its waits) by its activations (a process that is not `rtl`: `NativeFlags::count_on`/`count_off`/`entries`, flag `NAT_COUNT`, counted in `run_quick` only while its trial runs; `BY_ENTRIES`: all three pairs of windows, taken back below 0.95 only, because activations come in bursts and vary 10 to 25 percent between windows). A function is not measured: compiled callers use its native code (taking it away for a window makes each of their calls materialise a frame) and its entries vary with the phase of the run. Keep in step: anything that publishes compiled code of a function (`compile`, `publish`) must skip `lost` ones; Decisions.md "the callback count sees what leaves compiled code, and compiled code is measured and taken back" and "callees with their caller, `band_wait` 0.25 s, trials of looping processes".
- Callees with their caller (#652; `must_calls`, `Worker::hot`, `unseen`): a callee of at most `CALLEE_MAX` IR instructions that every path of a candidate calls (transitively) is compiled with it even if the sampler never saw it (`UNSEEN_MIN` leaves out only callees that may be rare): a call from compiled code to an interpreted callee is a `yavs_rt_step` out of the native frame.
- Code size (#679, `docs/decisions.md` "llvm: smaller frame-mode code"): the unoptimised code generator puts every value that crosses a block in a stack slot, and frame-mode code has a block per guard, so the bytes go to cross-block values, not guards. Keep values local: a definition is deferred only when its register is live over `MAX_SPAN` instructions or fewer (`Defer::keep`), address arithmetic is copied per block after the passes (`jit.rs` `remat_geps`), tests that feed a guard are made in the block that uses them (`Gen::host`), a decode of a cold shape is a pure runtime call (`yavs_rt_codes`, `yavs_rt_scalar`). Measure with `YAVS_LLVM_KINDLOC=<file>` (every LLVM instruction gets debug line = IR kind number, +1000 in cold blocks; `YAVS_LLVM_OBJ` objects then `objdump -dl` sum bytes per kind, `perf record` instructions:u per kind) before and after; judge by bytes, instructions, L1i/iTLB/branch misses and frontend stalls, cycles on this host are noisy.
- Compiled copies and cheaper bodies (#679, `docs/decisions.md` "llvm: compiled copies of processes, ..."): `AutoTier` returns `compiles_copies()`, so `Machine::specialise` moves a process whose shared code is compiled to its copy and the copy is compiled (the shared code's `LayoutOf`/`Field`/`DopeLen`/`SubtypeCheck` were 35 to 45 percent of its bytes; the copy folds them, `opt/decl.rs`); `--tier=llvm` does not and keeps the shared code. A constant `LCopy` inside one plane block each side is `Gen::lcopy_const` (test `constant_logic_copies_match_the_interpreter`); `Gen::std` stores nothing for a register defined once by a constant or an address (`Defer::pre`), loops or not. Measure compiled code in heat mode against `--tier=interp` of the same session and design, not against another session's cycles.
