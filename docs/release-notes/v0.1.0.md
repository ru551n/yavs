yavs 0.1.0 is the first release: a pre-release for people who want to try a new VHDL-2008 and
VHDL-2019 simulator early. Expect gaps (listed below) and please report what breaks at
<https://github.com/ru551n/yavs/issues>.

## What works

- `yavs analyze`, `yavs elab` and `yavs run` for VHDL-2008 and 2019, mixed in one project, with
  rustc-style diagnostics (codes, source snippets, VHDL call stacks for runtime errors) and NVC's
  report format on stdout. The command line is specified in `docs/cli-contract.md`.
- The IEEE packages (`std_logic_1164`, `numeric_std`, `numeric_bit`, `math_real`,
  `math_complex`, `fixed_pkg`, `float_pkg` and their textio) are analyzed and run from source,
  in 2008 and 2019.
- Differential corpus against NVC (`tests/corpus/RESULTS.md`): 112 of 114 testbenches give the
  same output at 1 thread, at 4 threads and at 4 threads with shuffled process order.
- Analysis corpora (`tools/corpus/RESULTS.md`): 3505 of 3851 files analyze clean over 29
  corpus runs, among them VUnit (143 of 143 in 2008 and 2019, plus 218 of 218 of its tests),
  OSVVM (174 of 174 in 2008, 172 of 174 in 2019), UVVM (221 of 235), PoC, neorv32, SatCat5,
  en_cl_fix and json-for-vhdl (all files). Larger gaps remain in surf (152 of 318) and Fletcher
  (12 of 101).
- VUnit: VUnit's `examples/vhdl/user_guide` and a pass/fail `test_runner` give the right result
  per test with `run.py` on yavs (#110).
- Linux x86_64, Linux aarch64 and Windows x86_64 builds, tested in CI on all three.

## Install

Download the archive for your platform, check it against `SHA256SUMS`
(`sha256sum -c SHA256SUMS --ignore-missing`), unpack it and put the directory on `PATH`:

- `yavs-0.1.0-x86_64-unknown-linux-gnu.tar.gz`
- `yavs-0.1.0-aarch64-unknown-linux-gnu.tar.gz`
- `yavs-0.1.0-x86_64-pc-windows-msvc.zip`

Keep `lib/` next to the `yavs` executable: it holds the `std` and `ieee` sources that yavs
analyzes on demand. `YAVS_STDLIB=/path/to/lib` points yavs at another copy.

```sh
yavs analyze --std=2008 --work=work:out/work tb.vhd
yavs run --work=work:out/work tb
```

## Using yavs with VUnit

The yavs simulator interface for VUnit (`vunit/sim_if/yavs.py`) is not in a VUnit release yet:
it lives on a VUnit branch together with three open VUnit pull requests (#1235 parallel compile,
#1236 batch compile, #1239 `record_dict_pkg`). Until it is upstream, a released VUnit cannot
select yavs. Once it is, `VUNIT_SIMULATOR=yavs python run.py` (with `yavs` on `PATH` or in
`VUNIT_YAVS_PATH`) runs the testbenches; each yavs runs with `--threads 1` under VUnit's `-p N`.

## Known gaps

- Not yet: VHPI and cocotb (`--vhpi`), waveforms (`--wave`), foreign libraries (`--load`), the
  DAP debug server and the GUI. These flags report "not implemented yet" instead of being
  ignored. The Windows archive does not ship `yavs.lib` yet (#124).
- The LLVM tier is not in the release binaries: everything runs in the interpreter.
- Synopsys `std_logic_arith`/`std_logic_unsigned`/`std_logic_signed` (#117) and
  `ieee.std_logic_misc` (#171) are missing.
- Generic types, subprograms and packages on entities (#75).
- textio `READ`/`WRITE` copy the whole line per call, so very long lines are slow (#196).
- Semantic analysis (milestone M1) is still in progress: `STATUS.md` lists what is in.
- No performance work yet: correctness first.
