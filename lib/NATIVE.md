# Native subprograms of the std library

The IEEE sources for `standard`, `textio`, `env` and `reflection` contain **no package
bodies**, so every subprogram below is implemented natively by yavs (crate `yavs-std`).
The ieee packages are ordinary VHDL with bodies and need no natives; a few hot subprograms
also run natively (`yavs-ir` `ieee`, `YAVS_NO_NATIVE_IEEE`), keyed by mangled name, not listed here.

## Symbol naming

`yavs.<package>.[<protected type>.]<name>.<param types joined by _>[.r_<return type>]`

- Lower case. `void` stands for an empty parameter list. Parameter modes and classes are not part
  of the symbol (they are in the Signature column); the parameter types are the declared type
  marks, so `VALUE: out BIT_VECTOR` gives `bit_vector`.
- Operators use `add sub mul div` for `+ - * /`; the return type suffix `.r_<type>` is added for
  functions only, so overloads that differ only in the result type (`getenv`) stay distinct.
- A protected-type method additionally takes the object (`self`) as first argument; the protected
  type name is the `<protected type>` component, in lower case, e.g.
  `yavs.reflection.subtype_mirror_pt.get_type_class.void.r_type_class`.
- Default values (`:= X`) are omitted from the Signature column; see the source.
- The symbol is stable: it depends only on the declaration text in the vendored IEEE source.

## 2. Implicit (predefined) operations

These have no source declaration at all (the IEEE `standard.vhdl` lists them in comments).
The semantic analyzer creates them with every type declaration (LRM 5.2.6, 5.3.2.4, 5.4.2, 5.5.2,
5.6.2, 7.2 and 16.3 `TO_STRING` rules); yavs-std provides one generic implementation
per family, keyed by the type class, with the family symbol below. Individual symbols are
`yavs.implicit.<family>.<type>[#<form>]`: the optional form after `#` (operand shapes such as
`as`, `sa`, `ss`, `reduce`, `pi`; `status`, `function`, `digits`) is separated by a character no
type name contains, so a type named like a form stays unambiguous.

| Family symbol | Applies to | Revision |
|---|---|---|
| `yavs.implicit.eq`, `.neq` | `=` `/=` on every type except file and protected | 2008, 2019 |
| `yavs.implicit.lt`, `.le`, `.gt`, `.ge` | scalar types and discrete arrays | 2008, 2019 |
| `yavs.implicit.minimum`, `.maximum` | scalar types (`MINIMUM`, `MAXIMUM`); array form in 2008 | 2008, 2019 |
| `yavs.implicit.add`, `.sub`, `.mul`, `.div`, `.neg`, `.pos`, `.abs`, `.rem`, `.mod`, `.exp` | integer, floating and physical types | 2008, 2019 |
| `yavs.implicit.and`, `.or`, `.nand`, `.nor`, `.xor`, `.xnor`, `.not` | BOOLEAN, BIT and their arrays (array/scalar reduction forms in 2008+) | 2008, 2019 |
| `yavs.implicit.sll`, `.srl`, `.sla`, `.sra`, `.rol`, `.ror` | BIT and BOOLEAN one-dimensional arrays | 2008, 2019 |
| `yavs.implicit.cat` | `&` on one-dimensional arrays | 2008, 2019 |
| `yavs.implicit.meq`, `.mneq`, `.mlt`, `.mle`, `.mgt`, `.mge`, `.cond` | matching `?=` `?/=` `?<` `?<=` `?>` `?>=` and `??` on BIT and arrays | 2008, 2019 |
| `yavs.implicit.to_string`, `.to_ostring`, `.to_hstring` | `TO_STRING` on scalar types and array types of character literals; `TO_OSTRING`, `TO_HSTRING` on BIT_VECTOR | 2008, 2019 |
| `yavs.implicit.rising_edge`, `.falling_edge` | `RISING_EDGE`, `FALLING_EDGE` on `signal BOOLEAN` and `signal BIT` (listed in `standard.vhdl`) | 2008, 2019 |
