# yavs standard libraries (sources)

yavs analyzes `std` and `ieee` from these sources on demand. The sources are built into the executable
(`$YAVS_STDLIB` names a tree on disk instead), and the analysed units are kept in a shared per-user cache
of std/ieee units (`--std-cache`, `docs/cli-contract.md` section 3), not in each library.
Select the directory by language revision: `lib/std/1993`, `lib/std/2008`, `lib/std/2019`,
`lib/ieee/1993`, `lib/ieee/2008`, `lib/ieee/2019`.

| Path | Content |
|---|---|
| `std/1993/` | `standard`, `textio` (no `env`) |
| `std/{2008,2019}/` | `standard`, `textio`, `env`; 2019 also `reflection` |
| `ieee/1993/` | `std_logic_1164` (`std_logic_vector` is a type of its own), `std_logic_textio` (Synopsys), `numeric_std`, `numeric_bit` (derived from the 2008 files with the 1076.3 types, see below), `math_real`, `math_complex`, the Synopsys and VITAL packages; no fixed/float, `*_unsigned` or context files |
| `ieee/{2008,2019}/` | `std_logic_1164`, `std_logic_textio`, `numeric_std`, `numeric_std_unsigned`, `numeric_bit`, `numeric_bit_unsigned`, `math_real`, `math_complex`, `fixed_float_types`, `fixed_generic_pkg`, `fixed_pkg`, `float_generic_pkg`, `float_pkg`, the VITAL packages `vital_timing`, `vital_primitives`, `vital_memory`, the Synopsys packages `std_logic_arith`, `std_logic_unsigned`, `std_logic_signed`, `std_logic_misc`, the two contexts; declaration and `-body` files |
| `ORDER.md` | dependency order for analysis, per revision (machine readable) |
| `NATIVE.md` | every subprogram without a VHDL body that yavs implements natively, with proposed native symbol names (generated by `tools/gen_native_md.py`) |
| `SOURCES.md` | origin, pinned commit, licence check and edits for each file |
| `UPSTREAM.sha256`, `SHA256SUMS` | hashes of the upstream files and of the vendored files |

The black-box testbenches for the Synopsys packages are in `tests/corpus/synopsys/` (generator `gen.py` there).

## Licensing

The Synopsys package files (eight per revision: `ieee/*/std_logic_{arith,unsigned,signed,misc}*`, 24 in
all, and `ieee/1993/std_logic_textio*`) are also an exception: Synopsys copyright with permission to use and distribute without restriction provided
the notice is kept; they are redistributed unmodified (`LICENSE-SYNOPSYS`, origin in `SOURCES.md`).

The six IEEE 1076.4 VITAL package files of each revision (`ieee/*/vital_*`, 18 in all, VITAL 2000) are the exception: IEEE
copyright, no explicit licence grant, redistributed unmodified as GHDL and NVC do
(`LICENSE-IEEE-VITAL`, origin in `SOURCES.md`).

The four 1993 `numeric_std` and `numeric_bit` files (`ieee/1993/numeric_*`) are derived from the
Apache-2.0 2008 files by `tools/derive_libs.py` (edits in `SOURCES.md`).

Apart from the Synopsys and VITAL files above, all files come from the IEEE VASG repository (<https://opensource.ieee.org/vasg/Packages>), licensed
Apache-2.0 ("Copyright 2019 IEEE P1076 WG Authors"), except two small context files written for yavs
(also Apache-2.0). Edited files keep the upstream header; the edits are listed in `SOURCES.md`.
yavs itself is MIT/Apache, so these files can be redistributed with it. `SOURCES.md` records where each
Synopsys and VITAL file was obtained and under which notice. No yavs code is taken from the reference simulators (GPL).

## Tools

- `tools/update-ieee-libs.sh [--check|--write]`: re-fetch at the pinned commit, verify hashes, compare or rewrite.
- `tools/check-sim1.sh [2008|2019]`: analyze the tree with the reference simulator in `ORDER.md` order (scratch libraries under
  `~/.cache/rsim-libs/work`, each run under `timeout 300 systemd-run --user --scope -p MemoryMax=2G`).

## The reference simulator analysis result (the reference simulator 1.23-devel)

Dated note 2026-10-28: this result was recorded for `2008` and `2019` only, which is what `tools/check-sim1.sh` runs by default; the
1993 trees (`ORDER.md` has their order) have no recorded result here. The file counts below are those of the time and are not
re-measured.

53 of 55 files analyze cleanly (27 for 2008, 26 of 28 for 2019), no warnings.

- `std/2019/standard.vhdl` is analyzed from a copy: the reference simulator hardcodes its own bootstrap and wants the
  type named `RANGE_DIRECTION` declared after `BOOLEAN` (the reference simulator limitation, the vendored LRM text is
  valid). `tools/check-sim1.sh` renames and moves it. `--bootstrap` is needed for `standard.vhdl`.
- `std/2019/env.vhdl` is **rejected**: `DIR_CLOSE (Dir : in DIRECTORY)` and the three
  `TO_STRING (call_path : ...)` functions have `in` parameters of types containing access types; the reference simulator
  requires class `variable` for those (LRM 4.2.2). This is an upstream defect in the IEEE file, kept
  verbatim.
- `std/2019/reflection.vhdl` is **rejected**: the `*_MIRROR_PT` protected types return the
  incomplete types (`VALUE_MIRROR`, `SUBTYPE_MIRROR`, ...) from their methods. The reference simulator does not support
  this; the LRM allows it (the incomplete types are completed by access types to the protected
  types). yavs has to accept it.
- All of `ieee/` analyzes in both modes against the reference simulator's own `std` (the `ieee` check does not use the
  scratch `std`).

## Cross-check against another VHDL front end's library sources (reference only, MPL; not used)

- `ieee2008/`: all files except the four below are byte-identical to ours (`float_generic_pkg` differs
  only in CRLF line endings). Differences: `numeric_std` has `subtype U_UNSIGNED/U_SIGNED` instead of `alias`, and the
  (c) sign written as `(c)` (also `numeric_bit`); `std_logic_textio` is an empty package there
  (ours has the LRM aliases); `fixed_generic_pkg-body` lacks upstream's later fixes (`rlow` in
  `add_carry`, and `c_out := result_slv(left_index-right_index)` in two places). The contexts match ours.
- `std/standard`: INTEGER `-2147483647 to 2147483647` (ours 2008: `-2147483648 to 2147483647`), explicit
  `RISING_EDGE`/`FALLING_EDGE` declarations (we treat them as implicit natives), no `FILE_OPEN_*`
  comments; same enumerations.
- `std/textio`: extra `FILE_REWIND`, `FILE_MODE`, `FILE_SIZE` (implicit file operations in the LRM,
  not textio declarations), no `LINE_VECTOR` (matches our 2008); otherwise identical.
- `std/env`: the same five declarations as our 2008 `env`.
