yavs 0.11.0 lets simulations run side by side share one CPU budget through a token server, fixes elaboration of packages with impure constants and evaluates static integer expressions exactly.

- **Shared CPU budget through a token server:** `--threads=N` takes its extra threads from a test runner's token server named in `YAVS_TOKENS`, on Linux and Windows, and gives every token back when the simulation ends; the `MAKEFLAGS` token pool is gone.
- **Exact static integer expressions:** bounds near the limits of `integer` are evaluated exactly and no longer fail on an intermediate overflow.
- **Packages reached during elaboration:** a package with impure constants first reached through a component or an architecture loaded on demand elaborates, with the same values on every run.
- **Better error locations:** run-time errors in an `elsif` condition or an arithmetic operation point at that condition or operation.
- **Package files:** a file declared with an open clause in a package is opened at elaboration and stays open.
- **Command line:** `yavs elab` and `yavs run` accept `-D NAME=VALUE`, `--ieee-warnings=off` silences the `ieee` package warnings, and a missing work library or wrong top level gets a clear error.
- **Cleaner JSON output:** `--message-format=json` prints only JSON objects.
- **More fixes:** expanded names with the package's own name as prefix, large array-of-records variables in long-running processes, and `--tier` under `--dap`.

# Breaking changes

- `yavs run --threads=N` no longer reads a token pool from `MAKEFLAGS`; the extra threads come from a token server named in `YAVS_TOKENS` instead. (#801)

# Features

- Simulations run side by side can share one CPU budget on Linux and Windows: with `YAVS_TOKENS` naming a test runner's token server, `--threads=N` runs its extra threads only on tokens the server lends, and every token comes back when the simulation ends, even when it is killed. The `vunit-yavs` package's `--yavs-jobserver` uses it and lends the idle `-p` slots to the running tests. (#801)

# Bug fixes

- A file declared with an open clause in a package is opened when the package is elaborated and stays open for the simulation; it was reported as not open. (#834)
- An explicit `--tier` that this yavs was built without is now error `E0120` under `--dap` too, instead of a silent interpreted debugger session. (#835)
- `--ieee-warnings=off` now silences the warnings raised inside the `ieee` packages (for example `NUMERIC_STD.TO_INTEGER: metavalue detected`); before it was accepted and ignored. A value other than `on` or `off` is a usage error. (#836)
- `yavs elab` and `yavs run` accept `-D NAME=VALUE` like `yavs analyze`, so a design that uses conditional analysis identifiers elaborates and runs with the same definitions it was analyzed with. (#837)
- `yavs run` and `yavs elab` treat a missing or empty `--work` directory as an empty library and report the missing top level as error `E0104` naming the directory, instead of "library not found"; a wrong top level, or one written with a library prefix, now gets a message that says so. (#838)
- `--message-format=json` now prints nothing but JSON objects when `analyze` stops at one file of several (the batch note is a note diagnostic; the short format has it on one line), `--threads=0` is a usage error, and `--stop-time=10` says a time needs a unit. (#839)
- The help of `--tier` and the explanation of `E0120` now name the compiled tiers the executable has (Cranelift in the release archives, LLVM when built in), and no option help points at a developer document. (#850)
- Inside a package declaration or body, an expanded name with the package's own name as prefix, such as `p.s`, names a declaration of the package or its body. (#854)
- A process that declares an array-of-records (or array-of-vectors) variable whose bounds depend on a generic, followed by a variable passed by reference to a procedure, no longer sees that variable reset after its 1024th activation. (#856)
- Static integer expressions such as `natural range 0 to 2 ** 31 - 1` or `-2 ** 31` are evaluated exactly up to their final value, so they no longer fail with an overflow of an intermediate result; run-time errors in an `elsif` condition or an arithmetic operation now point at that condition or operation. (#872)
- A package with impure constants (such as handles made from a shared id counter) that is first reached during elaboration, through a component or an architecture loaded on demand, no longer ends elaboration with an internal error: it is initialised after the elaboration-time calls made before it, and every run gives the same values. (#873)

# Miscellaneous

- A construct the semantic analysis does not implement yet is reported with its own code, `E1999`, explained by `yavs --explain E1999`; `E9999` from analysis now always means an internal error. (#842)
