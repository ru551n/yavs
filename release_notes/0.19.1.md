yavs 0.19.1 fixes two wrong results: a stale value driven by compiled code, and strings that lost part of their text after many calls.

- **Bug fix, compiled code:** a zero-delay assignment of a whole vector whose value comes from an address computed in the same run of the process, such as a large constant of an instance driven at initialisation, no longer drives a stale value. (#1131)
- **Bug fix, interpreter and default tier:** a string helper function called many times no longer loses part of its result, so check messages keep their context. (#1133)

# Bug fixes

- Compiled code (`--tier=clift`, and any process the default tier compiles) no longer drives a stale value when a zero-delay assignment of a whole vector takes its value from an address computed in the same run of the process and the fast way to the kernel does not take it, such as a 256-element constant of an instance driven at initialisation. (#1131)
- The interpreter and the default tier no longer drop part of a string returned by a helper function after it has been called often: a string parameter read in only one branch of the function kept the bounds of an earlier call, so check messages could lose their context. (#1133)
