yavs 0.20.0 fixes two bugs and makes compiled code, wide buses and the start of testbenches faster, with a second run that reuses the compiled code of the first.

- **Bug fix, `for generate`:** a process that uses an element, field or slice indexed by the generate parameter no longer sees another lane's element after about a thousand activations.
- **Bug fix, aliases:** an object alias of a generic, of a constant that is not locally static, or of a part of one is accepted in subprograms and processes.
- **Faster compiled code, strings and arrays:** concatenations, slices of run-time length, freeing objects and records with run-time bounds are handled in compiled code itself.
- **Faster compiled code, wide datapaths:** `numeric_std` arithmetic, reductions, `is_x` and logical operators on vectors of up to 128 elements, also with metavalues, are computed in compiled code.
- **Faster compiled code, records and helper functions:** partial record signal assignments, repeated calls of pure functions and fewer overflow and range tests make processor-style designs faster.
- **Faster wide buses:** the kernel commits wide buses in fewer steps.
- **Better `--tier=auto`:** only the subprograms a first run can reach are optimised ahead, more of the subprograms that compiled processes call are compiled, and `--tier-compile=wait` first runs take about the same time every time.
- **Sooner starts:** the optimiser does less repeated work on small subprograms, long functions and very large processes or records.
- **Second runs reuse compiled code:** a second run, also of a testbench that shares its library with others, takes the compiled code of the last run without generating it again.
- **Faster archives:** the release archives are optimised as one whole program, and large designs keep more of their heap on transparent huge pages.

# Bug fixes

- A process of a `for generate` that waits on, reads the attributes of or drives an element, field or slice indexed by the generate parameter no longer sees another lane's element for one activation after about a thousand activations, which gave false assertion failures and "target outside the driver" errors in valid designs (#1137)
- An object alias of a generic, of a constant that is not locally static, or of a part of one (`alias x : integer_vector(0 to t'length - 1) is t;` in a subprogram or a process) is accepted, where it was rejected as not implemented.

# Miscellaneous

- A large design keeps most of its heap on transparent huge pages as the heap grows (Linux with glibc, THP in `madvise` mode), not only the first 64 MiB, which cuts its data-TLB misses; nothing has to be set. Setting the glibc allocator tunables `top_pad`, `trim_threshold`, `mmap_threshold` or `hugetlb` (or their older `MALLOC_*_` variables) now leaves the allocator to you, and `YAVS_HUGE_HEAP=0` still switches it off.
- A testbench that shares its verification library with other testbenches of a suite now takes the compiled code its last run made without generating it again.
- A wide bus copied through a concurrent assignment is committed in fewer steps by the kernel, so designs that pass wide data buses through ports simulate a little faster.
- A wide bus that a process assigns whole is committed in one step by the kernel, so designs with wide data buses simulate a little faster.
- Assignments in compiled code that leave a signal at the value it holds are recognised earlier, so processor designs with many held registers and records simulate faster.
- Compiled code answers a repeated call of a pure function on scalars and short vectors from the memo of pure calls by itself, without calling into the simulator, so designs that call such helper functions often simulate faster.
- Compiled code calls a pure function without a loop directly instead of first looking its arguments up in the memo of pure calls, and a lookup in that memo costs less, so designs that call many small pure helper functions simulate a little faster.
- Compiled code copies slices whose length is known only at run time, such as a slice a small function returns, itself instead of calling into the runtime, so designs with many small index and field helper functions simulate a little faster.
- Compiled code now builds string and array concatenations itself instead of handing each one to the interpreter, so testbenches that format many log messages simulate faster.
- Compiled code now computes `is_x` and the reduction operators (`and`, `or`, `xor` and their negations of a vector) itself for vectors of up to 64 elements, so designs that test buses for metavalues or reduce them every clock simulate faster.
- Compiled code now computes `numeric_std` sums, differences and products, reductions, `is_x` and the logical operators of vectors of 65 to 128 elements, and concatenations of up to 128 elements, itself instead of calling into the interpreter, so designs with 64-bit multipliers and other wide datapaths simulate faster.
- Compiled code now computes the logical operators of vectors that hold metavalues such as `U` itself, so designs with registers that stay uninitialised simulate faster.
- Compiled code now converts real values to integers itself instead of handing each conversion to the interpreter.
- Compiled code now drives a record signal assignment that changes only some of the fields, and an assignment to one element of an array of records, without handing the work to the interpreter, so processor and bus designs with record signals simulate faster.
- Compiled code now frees an object it deallocates without handing the work to the interpreter, so designs that build and free many strings or lists in small functions simulate faster.
- Compiled code now reads the layout of a record or array whose bounds are only known at run time without handing the work to the interpreter, so designs that pass such records to small functions simulate faster.
- Compiled code skips more of the overflow and range tests it can prove never fail, so CPU-style designs simulate slightly faster.
- Long functions with many local composite variables start sooner: the optimiser no longer walks the whole function again for each of them.
- Runs start sooner: the optimiser makes the optimised body of each small subprogram once instead of again for every level of inlining, and long functions full of vector operations are optimised in time that grows with their length.
- Runs that compile with a compilation cache hash each compiled function once instead of twice, so a second run of a design starts its compiled code sooner.
- The optimiser and the lowering work out the layout and the descriptor size of each type once and share the answer, so the first run of a testbench with many large records starts faster.
- The optimiser's frame passes for process variables and temporaries find the blocks, slots and register lists they need by index instead of scanning the whole function, so the first run of a testbench with one very large process starts faster.
- The release archives are optimised as one whole program, so simulations run faster.
- The second run of a design takes the compiled code its first run made without generating it again, so it starts sooner.
- Under `--tier=auto`, a first run optimises ahead only the subprograms its processes can call, not every subprogram of the libraries it uses.
- Under `--tier=auto`, a simulation no longer enters compiled code at a subprogram return that the interpreter runs anyway, so testbenches whose procedures wait inside compiled callers run a little faster.
- Under `--tier=auto`, a subprogram that loops for a long time in one call, such as a test's set-up at time 0, is compiled early in the next run of the test, and the call running then goes on in compiled code.
- Under `--tier=auto`, deciding which subprograms to compile no longer optimises every function of the design first, so most functions that never run are not optimised at all.
- Under `--tier=auto`, subprograms that a compiled process calls through its specialised copies are compiled too instead of staying interpreted for the whole run, so processor models that call many small procedures from one large process simulate faster from the first run.
- With `--tier-compile=wait`, the first run of a testbench whose processes call large trees of procedures no longer sometimes compiles them in its last moments: those compiles move to the following runs, so the first run takes about the same time every time.
