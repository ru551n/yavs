yavs 0.20.0 makes simulations and the start of runs faster, ends runs on Ctrl-C with a proper exit status, lets the test runner compile in parallel, and fixes wrong results with real arrays and signals, resolution functions and generate loops.

- **Faster simulation:** compiled code, wide vectors, buses, ports and timed waits cost less, so most testbenches run faster under `--tier=auto`.
- **Faster starts:** large designs are optimised sooner, and later runs reuse compiled code from the compilation cache.
- **Ctrl-C and SIGTERM:** a `--tier=auto` or `--wave` run ends with exit status 130 and keeps what it compiled and its waveform file.
- **Parallel compiling in vunit-yavs:** compile calls follow the dependency order, share more files per call, and `-j N` runs several at once.
- **Fixed, wrong results:** `=` and `/=` on arrays of reals, `-0.0` as a signal event, resolution functions called once per update, and generate-loop processes seeing another lane's element.
- **Fixed, hangs and errors:** two `yavs analyze` calls into libraries that read each other no longer deadlock, and several valid designs no longer hit `E2001`, `E3006` or "not implemented" errors.


# Features

- A run with the compiled tier (`--tier=auto`) ends on its first Ctrl-C or SIGTERM through yavs itself, with exit status 130, also on a plain terminal, after storing the compilation cache's lists of compiled functions, so an interrupted run does not lose what it compiled.
- vunit-yavs compiles in the project's dependency order with more files per `yavs analyze` call: the files of one library, standard and flags that are ready together share a call, not only consecutive ones. `-j N` (`--jobs N`) runs up to N calls at once, into different libraries; without it, one call at a time. Failures, skipped dependents, `--keep-compiling` and the output stay those of VUnit's own compile loop.

# Bug fixes

- An object alias of a generic, of a constant that is not locally static, or of a part of one (`alias x : integer_vector(0 to t'length - 1) is t;` in a subprogram or a process) is accepted, where it was rejected as not implemented. (#1134)
- The perf map (`YAVS_CLIFT_PERFMAP`, `/tmp/perf-<pid>.map`) now starts empty in each process. A file left by an earlier process with the same pid used to be appended to, so `perf report` could name code of another run and list the runtime stubs twice. (#1135, #1140)
- A subprogram declared with a generic list and a generic map in its header, whose body is missing (for example the package body defines a differently named subprogram), is now reported as a missing body (E1230) instead of an internal error. (#1136)
- A process of a `for generate` that waits on, reads the attributes of or drives an element, field or slice indexed by the generate parameter no longer sees another lane's element for one activation after about a thousand activations, which gave false assertion failures and "target outside the driver" errors in valid designs. (#1137, #1138)
- A resolution function is called once per update of its signal with all the sources, as the language defines it, where it was called once for each driver with a transaction in that cycle: its reports appeared that many times, and a resolved signal with many active drivers was slow. (#1139)
- `--yavs-jobserver` now works with `-p 0` (one simulation per CPU) of the test runner: the token server starts with one slot per CPU and each simulation runs with `--threads=auto`, as with `-p N`. It was silently off. (#1141)
- Runs of one top level with different generics in one work library no longer read each other's cached lowering when the generics select generate branches that use external names, or that instantiate entities with generic types in another order: such a run failed with `E3006 invalid reference: no signal`, an internal error, or printed a wrong value, depending on the order the runs came in. (#1142)
- A generate branch that the generics do not select no longer fails with `E2001` when it holds an alias of a part of an external name (a slice, an element or a record field of `<<signal ...>>`): the branch is not elaborated and its external names are never resolved. (#1143)
- `=`, `/=` and (VHDL-2019) the ordering operators on an array of reals (`real_vector` or any array of a floating-point type) compared the bytes of the elements, so `(-0.0, 1.0) = (0.0, 1.0)` was false and arrays with negative elements ordered wrongly; they now compare the elements as reals, as the scalar and record compares already did. (#1144)
- A REAL signal, or an element of a `real_vector` or of any composite with real fields, going from `0.0` to `-0.0` (or back) is no longer an event: it is still a transaction (`'active`, `'transaction`), but no process waits on it, `'event` stays false, and `'last_value` and the waveform do not change, as `=` already treats the two zeros as equal. Other signal types are unchanged. (#1145)
- Under `--tier=auto`, a subprogram whose compiled code is in the compilation cache but whose entry in the cache's list was lost (a run ended by a crash or a kill) is linked again by a later run instead of staying interpreted in every run until the cache is cleared. (#1148)
- A loop that applies a logical operator to vectors of known length in every iteration no longer keeps each iteration's result: long loops ran in growing memory and could stop with "temporary memory of one statement exceeds 4 GiB". (#1149)
- Two `yavs analyze` calls at once into libraries that read each other (a `library` clause is enough) no longer wait for each other's lock for ever: a parallel compile of such libraries finishes. (#1150)
- A diagnostic on a source with Windows line endings no longer shows the line ending as a stray symbol (U+240D) at the end of the snippet line, which a console in a legacy code page could not print; a stray carriage return inside a line shows as a blank. (#1151)
- A run with `--wave` that is stopped by Ctrl-C or SIGTERM now exits with status 130, like every other run, instead of 1; the waveform file is still finished first. A run with `--exit-on-stdin-close` and `--wave` also finishes its file when standard input closes. (#1155)
- A long run in which processes wait with a long timeout that signal events beat (`wait on s until c for 1 hr` in a loop) keeps its memory flat: the timeouts of waits that ended early are dropped instead of staying queued until their time.

# Documentation

- The documentation of `--tier-compile=wait` no longer says a run keeps no more cores busy than `--threads`: the simulation waits while a function compiles, but a tier-up thread still prepares functions alongside it, so a run can use somewhat more than `--threads` cores for short periods; `--tier=interp` starts no tier-up thread. (#1141)
- The README now shows the yavs shark-fin logo in light and dark themes, with a consistent teal fin and lettering suited to each background. (#1152)
- The yavs logo is shown on the documentation site: in the sidebar header and on the front page. (#1153, #1154)
- The user guide is brought up to date: what a stopped or killed run keeps in the compilation cache, the work-based default of the warm-run gate, the exit status of a run with a waveform that is stopped by Ctrl-C, `-j` and the compile batching of the test runner package, and macOS source builds.

# Miscellaneous

- Compiled code does more of its work itself and skips more checks it can prove never fail, so designs with wide datapaths, record signals, many log messages or many small helper functions simulate faster under `--tier=auto`.
- Ports connected to a signal, an element or a slice of one no longer keep a signal of their own, now also for record ports, `inout` ports and ports connected to elements of an array of records, and elaborating many such instances is much faster; `--no-collapse-ports` keeps every port apart. A large design keeps more of its heap on transparent huge pages (Linux with glibc); setting the glibc allocator tunables `top_pad`, `trim_threshold`, `mmap_threshold` or `hugetlb` leaves the allocator to you, and `YAVS_HUGE_HEAP=0` still switches it off.
- Release archives are optimised as one whole program, and on Windows yavs uses a faster memory allocator than the system heap and measures the CPU time of the simulation, as on Linux, so allocation-heavy simulations are faster and `--tier=auto` decisions depend less on how busy the machine is.
- Runs start sooner: large designs are optimised faster, the first run under `--tier=auto` optimises only what it needs, later runs take compiled code from the compilation cache without generating it again, and a cold run writes far fewer files, which helps most on Windows with real-time antivirus scanning. A run that crashes or is killed loses at most about two seconds of the cache's lists of compiled functions; the next run links or recompiles those functions.
- Under `--tier=auto`, more of what a run spends its time in is compiled, and repeated runs of a testbench settle into their fast state in every fresh cache. The choice of what to compile now follows the work a run did, counted in instructions where the system provides the counter, so a busy machine no longer changes it. Profiles stored by an earlier version are ignored once.
- Wide vectors, arrays of vectors and wide buses are processed in bigger steps, and processes that wait with a timeout, assign a signal several times in one activation or use protected objects and shared variables cost less per activation, so most testbenches simulate faster.
