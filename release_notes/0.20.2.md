yavs 0.20.2 fixes how often and in which order impure function calls in slice targets and aggregates run, guarded composite signals and VHPI values that depend on generics, and makes compiled code faster and `--tier=auto` steadier from run to run.

- **Fixed, wrong results:** an impure function call in the bounds of a slice target or under an aggregate choice runs once per assignment or element, in the order the language defines, and a variable assignment to an element or slice checks its index before it computes the value.
- **Fixed, guarded composite signals:** a signal resolved as a whole stops with `E3011` when one process drives some elements with a null transaction and others with values; a fully disconnected source takes no part in the resolution.
- **Fixed, VHPI:** array sizes, attribute values and constants that depend on a generic through nested arithmetic have their values.
- **Faster compiled code:** `numeric_std` and `std_logic_1164` operations on arrays of vectors work in place, and fewer slice and parameter lengths are checked at run time.
- **Better memo of pure function calls:** it answers more calls from the memo and loses fewer results to collisions.
- **Steadier `--tier=auto`:** repeated runs of a test settle in the same fast state, also on a busy machine and with `--threads` above 1.
- **Renamed setting:** `YAVS_LLVM_ELOOP_HELPER` is now `YAVS_ELOOP_HELPER`; the old name still works for one more release.
- **vunit-yavs:** needs yavs 0.20.2; the workaround for yavs 0.19.1 and older is gone.



# Bug fixes

- A variable assignment to an element or slice whose value is an array or record now checks the target's index before it computes the value, so a run that stops at an index error no longer prints that assignment's warnings or reports first; an impure function call in the bounds of such a slice target now runs once when the value is an aggregate. (#1156)
- An impure function call in the bounds of a slice target now runs once per assignment in every signal assignment (sequential, concurrent, conditional, selected, guarded, with several waveform elements, force) and in variable assignments to slices of arrays of records or arrays, also when the value is an aggregate that takes its bounds from the target. (#1157)
- An impure function call under `others`, a range choice or a choice list of an aggregate of scalar elements (integers, reals, enumeration values, `std_logic` vectors) now runs once for each element, with `others` after the other choices, as it already did for records; before, it ran once per choice and `others` first. (#1158)
- VHPI now sizes arrays and reads user attribute values whose bounds or value depend on a generic through nested arithmetic (`2 * N + 1`, `(N + 1) / 2`, `N * 2 - 1`), and reads a constant whose value is such an expression (`constant c : integer := N + 1`) even when nothing in the design reads it; before, only one operation on the generic gave a size and an attribute value, and these constants had no value. (#1159)
- A guarded signal whose composite subtype is resolved as a whole now stops with error `E3011` when one process drives some of its elements with a null transaction and others with values at the same time, as the language requires; before, the resolution read the last values of the disconnected elements. A source whose driven elements are all disconnected now takes no part in the resolution, also when the process drives only a slice of the signal by a static name. (#1160)

# Miscellaneous

- Compiled code works on an element of an array of vectors in place when it is an operand or the target of a `numeric_std` or `std_logic_1164` operation, and no longer clears the temporary of a vector result it writes itself, so a small function such as one stage of an adder tree runs as fast as the same loop written in the process. (#1122)
- A slice whose bounds the code computes, such as a byte lane `v(8 * i + 7 downto 8 * i)` written from a function result, keeps its known length across the call, and copying an unconstrained parameter into `0 to x'length - 1` or `x'length - 1 downto 0` needs no length check at run time.
- The memo of pure function calls gives every key two places in its table, judges a function on its early calls as a whole, and tries a costly function it gave up on again later in the run, so more calls are answered from the memo.
- Under `--tier=auto`, a run's work counts every simulation thread, functions that compiled code keeps calling out to are compiled and linked from the cache, compile time is planned with its real price, and a function is no longer held back for most of a run or compiled late in a run that gains nothing from it, so repeated runs of a test settle in the same fast state. Profiles stored by an earlier version are read as none once.
- The environment variable `YAVS_LLVM_ELOOP_HELPER` is now `YAVS_ELOOP_HELPER`, since LLVM is no longer a tier. The old name still works for one more release.
