yavs 0.21.2 lets debugger conditions call functions, extends VHPI and VHDL-2019 range records, fixes an occasional internal error at the default tier, and makes runs start faster.

- **Debugger conditions call functions:** breakpoint conditions, Watch expressions and `examine` call functions of the design and of packages, convert types, use the operators a type declares and read attributes of signals and arrays.
- **VHPI:** `vhpiPtrVal` of access variables, `vhpiParent` of sequential statements, the processes that read a signal as its loads, aliases of parts of objects, and configuration declarations in the object model.
- **VHDL-2019 range records:** any expression of a range record type works as a range, also when its value is known only at run time.
- **Fixed, internal error at the default tier:** a subprogram the interpreter runs while the compiled tier is still compiling it no longer stops the run now and then.
- **Fixed:** conditional expressions in constants that elaboration needs are evaluated; a warning made an error by `-Werror` shows as an error and stops `yavs run` before the simulation; runs under `perf` no longer leave a map file each.
- **Faster starts:** a warm run reuses the interpreter's predecoded code and the calls that create verification components in constant declarations, and decodes only the cached analysis it reads; a first run uses the code that testbenches of the other libraries it maps compiled.
- **Parallel test runners:** tests of one design that start together make the cache entries once while the others wait.
- **Multi-clock processes:** a process that tests or waits on edges of several clocks is no longer resumed by the clocks' other edges.
- **Cycle mode (EXPERIMENTAL):** a clock event that is not an edge a region uses no longer wakes the region; the metavalue count of the summary line counts reads.

# Features

- VHPI plugins can read the address an access variable of a process designates with `vhpiPtrVal`. `vhpiParent` of a sequential statement gives the statement or process around it. `vhpiLocalLoads` and `vhpiOptimizedLoads` also list the processes that read a signal. An alias of a record field, an array element or a slice reads, writes and reports value changes as the part of the object it names. Configuration declarations are part of the object model, with their block and component configurations and `vhpiConfigDecl` of the top level and of instantiated configurations. (#143)
- Breakpoint conditions, Watch expressions and `examine` can call functions of the design and of packages such as `numeric_std` (`to_integer(unsigned(d)) > 40`), convert types, use the operators a type declares (`cnt + 1 = 4` on an `unsigned`) and read the attributes `'event`, `'active`, `'last_value`, `'last_event` and `'last_active` of signals and `'length`, `'left`, `'right`, `'high`, `'low` and `'ascending` of arrays. Impure functions are called too when they only read: signals of their architecture, `now`, and functions without parameters by their bare name (`edges > 2`). A called function runs apart from the simulation on copies of what it reads, so a condition cannot change it; a function that may write (a signal, a shared or protected variable, a file, `std.env.stop`) is refused, naming what it does and where. (#364)
- VHDL-2019: any expression of a range record type (`R'RECORD`) now works as a range, also when its value is known only at run time: an object, a function call such as `for i in f(n) loop` or `bit_vector(f(n))`, a qualified expression or an operator, in an index constraint, a range constraint, an array type, a loop, a slice or a for-generate. (#445)

# Bug fixes

- The error for a file parameter of a VHPI foreign subprogram names the file parameter as the problem; it no longer says that signal parameters are not supported. (#143)
- A warning that `-Werror` or `-Werror=CODE` makes an error is now shown as an error, with a note naming the option, and `yavs run` stops before the simulation starts when a warning made an error comes from the design's processes. (#840)
- The IR verifier's check for reads before writes now needs memory in proportion to the size of a function, not blocks times registers: very long and/or chains no longer exhaust memory. (#1168)
- Runs under `perf stat` or `perf record` no longer write a `/tmp/perf-<pid>.map` file each, which could fill the inodes of `/tmp` until yavs failed. The perf map is now written only with `YAVS_CLIFT_PERFMAP=1`, and a map that cannot be written is a warning instead of an error. (#1170)
- A run at the default tier no longer stops now and then with an internal error ("pc ... beyond") in a subprogram the interpreter runs while the compiled tier is still compiling it. (#1171)
- VHDL-2019 conditional expressions (`a when c else b`) in a constant that elaboration needs, such as one that sizes a signal, are now evaluated instead of stopping with E2106. (#1173)

# Miscellaneous

- A later run of a cached design reads the interpreter's predecoded code of the functions earlier runs ran instead of making it again (`YAVS_PDEC=0` turns it off).
- A process made only of clock edge tests on several clocks, or waiting until one of several clock edges, is no longer resumed by the clocks' other edges.
- A testbench that creates its verification components in constant declarations starts faster from its fourth run: the calls those declarations make, and the package state they leave, are taken from the compilation cache when their arguments are the same.
- A warm run decodes only the entries of the cached analysis it reads, not the whole chunk around each, so the start of a run from the compilation cache is cheaper.
- Cycle mode (EXPERIMENTAL): an event of a clock that is not an edge the region uses no longer wakes the region when it also waits on data inputs. The metavalue count of the summary line counts reads, so it can be smaller than before.
- Tests of one design that start together (a parallel test runner's first round) no longer each make the same cache entries: one run makes them while the others wait for it, and a run that is killed lets the others go at once. `YAVS_CACHE_WAIT_MS` limits the wait.
- The first run of a testbench also uses what testbenches of the other libraries it maps compiled: it compiles those subprograms early, and links their code where it is the same, instead of interpreting them for most of the run.
