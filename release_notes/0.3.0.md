Simulation of composites with their own resolution function, more precise overload errors, and fixes to parsing, error codes and the exit status of `yavs run`.

## Features

- Overload errors are more precise: an unknown, repeated or missing parameter association, a procedure used as a function (and the reverse), and an ambiguous argument are reported at the offending association or argument, with the candidates and a qualification to write listed in the help. (#51)
- Signals of a record or array subtype with its own resolution function (a composite resolved as a whole) now simulate: the function sees whole composite values from every source. (#193)

## Bug fixes

- Aggregate and case errors carry the codes and positions the documentation lists: an aggregate in a scalar context, a misplaced `others`, mixed named and positional associations, unknown or surplus record elements, a scalar where a multidimensional aggregate needs a row, and a case on a non-discrete type or with a choice of the wrong length. (#45)
- An index constraint whose range is an attribute of an indexed and selected name, such as
  `unsigned(c(c'low)(i).addr'range)`, now parses instead of being taken for a record constraint. (#59)
- `yavs run` takes its exit status from the VHDL-2019 `std.env` assert counts, so a testbench
  that reports an expected error and then calls `ClearVhdlAssert` exits 0. (#191)
- `open` as the actual of a subprogram parameter with a default, as in `f(a => open, b => 1)`,
  now selects the default instead of failing overload resolution. (#192)
- Building or reading a long line with many textio READ and WRITE calls now takes time proportional to its length instead of growing quadratically. (#196)
