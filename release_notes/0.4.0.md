Adds calls from VHDL into C shared libraries (VHPIDIRECT), FST waveform output, a parallel signal update phase, elaboration of signals of arrays and records, signal aliases and impure package state, and many fixes to error reporting; the Linux release archives now run on glibc 2.17 and later.

## Features

- A VHDL-2008 file in a design elaborated with the VHDL-2019 std/ieee now gets an error when it names a std or ieee declaration that VHDL-2008 does not have (such as `std.env.tool_name` or `std.reflection`), and a warning (`W1008`, escalatable with `-Werror`) where an INTEGER bound such as `integer'high` changes value under the 64-bit VHDL-2019 INTEGER. (#50)
- Expanded names into a process, block, generate statement, loop or subprogram (`p1.v`) now analyze inside the construct, and outside it report that the declaration is not visible there. An undeclared name that a standard package declares gets a help naming the missing use clause, and a name from a package body reports that it is not in the package's visible part. (#54)
- Impure functions that keep state in packages (registries in shared variables, such as logger
  and actor factories) can be called in generic maps, constant and signal declarations: they run
  during elaboration in declaration order, and the simulation starts with their side effects. (#77)
- Files of non-text types (`file of integer`, `real`, enumerations, `character`, `time` and arrays of them) can now be written and read back with `write`, `read` and `endfile`. (#79)
- VHDL can call C functions in a shared library: declare a subprogram with the `foreign` attribute `"VHPIDIRECT symbol"` and run with `yavs run --load=LIB`. Scalars, arrays, records and access values are passed, `out` and `inout` values are copied back and checked. (#95)
- With `--threads` above 1, the signal update phase of each simulation cycle now also runs in parallel for signals that are not connected through ports, so designs with many signals gain more from extra threads. Output stays identical at any thread count. (#103)
- Added `--wave FILE.fst`: records the whole design (hierarchy, records and arrays as scopes, enumeration names, final value per time step) as an FST file, finished on normal end, `--stop-time` and Ctrl-C, with `--wave-include`, `--wave-exclude` and `--wave-max-array` to choose what is recorded. (#129)
- VHDL-2019 signals of an unconstrained array subtype that take their bounds from the initial value
  (`signal s : bit_vector := f(x);`) now elaborate and simulate, in architectures, blocks,
  generates and packages. (#187)
- The Linux release archives now run on glibc 2.17 or newer (RHEL/CentOS 7+, Debian 8+, Ubuntu 14.04+) instead of 2.34, on x86_64 and aarch64; on musl-based systems such as Alpine, install the `gcompat` package.

## Bug fixes

- A selected object part (such as `rec.f`) used where a subprogram or function name is required, for example as a resolution function or a generic subprogram actual, is now a clear error instead of an internal error. (#18)
- Source files analyzed or elaborated honour `--encoding` (`auto`, `latin1`, `utf8`), including units loaded on demand; `--encoding=utf8` rejects a file that is not valid UTF-8. (#20)
- A library clause supplied by a context declaration is now visible to the architecture that references it, including in `architecture a of lib.e`. (#36)
- An alias whose subtype indication names a type other than the aliased object's now points the error at that subtype indication, instead of at the declaration of the type in the standard library. (#46)
- `'range` and `'reverse_range` of a scalar object (`bit_vector(a'range)` with `a : integer`) now report "attribute does not apply to this prefix" at the attribute, like every other predefined attribute, instead of a generic "not an object" error. (#47)
- Type conversions between types that are not closely related, and constants or expressions passed to variable, signal or file parameters, are now rejected at analysis. A condition of type `std_ulogic` works when only the type is imported, two visible `??` operators for one type are reported as ambiguous, and type mismatches between vectors and integers suggest the conversion to write. (#48)
- An external name whose type does not fit its context is reported as a type mismatch instead of
  "not implemented", and a character or string literal that does not belong to its type is reported
  as a character that is not in the type, naming the element type. (#49)
- A non-static or nonexistent dimension argument of an array attribute and an unconstrained constant without a value outside a package are now errors, and a static index or slice outside a static array range now gets a warning at analysis. (#53)
- Every package and architecture constant is evaluated once, at elaboration, including composite
  constants whose bounds are known only at run time: an impure initialiser runs once and every
  use sees the same value. (#73)
- Using `T'reflect` with a type mark that is not fully constrained, followed by a selection such as `.to_array`, now reports that the prefix of `'reflect` must be a fully constrained subtype, instead of "does not denote a value". (#154)
- An external name used as the actual of an `in` port now behaves as an expression actual: the
  port keeps its own initial value and follows the external signal one delta later. (#186)
- A constant, signal, generic, port or constant or signal parameter of an access or file type, or of a composite containing one, is now rejected at analysis with `E1223`, as the LRM requires. Before, a package constant holding an access value analyzed and then stopped the simulation with an internal error. (#198)
- Signals of arrays of records, and records with array fields, now elaborate and simulate: they can be read, assigned whole or through any element, field, bit or slice, used in sensitivity lists and ports, and resolved as a whole. (#200)
- Signal aliases now simulate: an alias of a whole signal, a slice, an element or a record element, with or without a subtype indication, declared in an architecture, process, subprogram or package, reads, drives, waits and takes attributes exactly like the aliased signal, and can be a port or signal actual. (#203)
- A variable or constant declared in a protected type body can now be initialised by calling a method of the same body, for shared variables and for process-local variables of the type; the call acts on the object being created. (#204)
- A procedure declared in a process can assign elements and slices of signals selected by its parameters, or by constants computed from them. (#205)
- A signal assigned in a procedure declared inside a process, also from a nested procedure or as an element or record field, is now driven by that process. Before, such a design stopped with an internal error. (#206)
- 'path_name and 'instance_name of objects declared in processes and subprograms include the process label and the subprogram profile, as the LRM requires. (#207)
- TIME'low is now -9223372036854775808 fs, the full 64-bit range, so arithmetic that reaches that value no longer reports an overflow. (#208)
- A constant of a constrained array subtype initialised by a literal or aggregate now has the bounds of its subtype when it is read as a value, indexed or sliced, for example `constant c : string(5 to 7) := "abc"` passed to an unconstrained parameter has `'left` 5. Before, it had the bounds of the initial value. (#209)
- A subprogram call may associate a formal by its sub-elements, such as `pr(x(0) => s)` for an unconstrained `out` signal formal or `p(r.i => 1, r.b => '0')` for a record: the call now resolves at analysis instead of reporting `E1301`. A non-static index or range in a formal sub-element name, in calls and port maps, is rejected with `E1410` instead of being taken as the whole formal. (#210)
- Methods of a protected type that return or take an access or file type are now rejected in VHDL-2008 with `E1223`, and VHDL-2019 code may use constant parameters of access type. (#212)

## Miscellaneous

- An unbound foreign subprogram symbol is now warning `W0108` before the simulation starts (an error with `-Werror`) and error `E0107` with a VHDL stacktrace only when the subprogram is called, so designs that never call it run. (#95)
