Generic package instances, external names in processes and port actuals, protected-type variable ports, record signals in subprogram parameters and port maps, and many elaboration and simulation fixes across VHDL-2008 and VHDL-2019; `yavs run` gains a time resolution option and the documentation adds a page on where simulators differ.

## Features

- Packages and package bodies can be declared inside packages, package bodies, entities, architectures, blocks, generates, processes and subprograms, generic ones included: their objects belong to the enclosing region, and local generic packages can be instantiated there, in nested regions and through an instance of an enclosing generic package. A signal or shared variable declared in a process or subprogram, directly, in a package there or through a package instance there, is now an error. (#34)
- Record-typed expressions, expressions in the port map of a configuration, and static values
  or qualified expressions for unconstrained ports are accepted as `in` port actuals, and a port
  whose range comes from the instance's generics is range-checked. Type conversions of record
  ports and of arrays of records, such as `pi => pairs(s)`, simulate in the same delta. (#74)
- External names can be used directly in processes, concurrent statements and port actuals, including a process placed before the instance it names; external constants, external shared variables of protected types (with method calls), record signals and aliases of parts of external names now simulate. (#93)
- `'reflect` now works on file and protected objects, on access objects (a mirror of the access value), and on subtypes whose range depends on generics or parameters, also as record elements, array indices and elements. `array_subtype_mirror.index_subtype` reports the type mark of a constrained array definition's index range. (#97)
- Generic package instances now simulate with objects of their own: constants that depend on the generics, signals, shared variables of protected types and package body state, whether the instance is a design unit or is declared in a package, entity, architecture, block, generate, process or subprogram. (#101)
- VHDL-2019 variable ports of a protected type simulate: instances share one protected object through ports of class variable associated with a shared variable or another variable port, through entities, components and blocks. (#188)
- An alias of a method of a shared variable or a variable (`alias push is sv.push [integer];`) is accepted in VHDL-2019, and calls through it run the method on that object. (#237)
- VHDL-2019 conditional procedure returns (`return when c;`) now analyze and simulate. Named return values (`return r of t`) now also work for record types, in generic subprograms and generic packages, and in protected methods; a named return value of a scalar type is reported as an error. (#239)
- `yavs run --resolution=fs|ps|ns|us|ms|sec` sets the time resolution limit (default `fs`): `std.env.resolution_limit` and the TIME values of `std.reflection` mirrors follow it. (#253)
- VHDL-2019 signal parameters with a mode view (`signal b : view v` and `view (v) of arr_t`) now simulate: a call drives only the elements the view makes `out`, `inout` or `buffer`. Subprogram parameters of mode `buffer` or `linkage` are now reported as error `E1236`. (#254)

## Bug fixes

- An `inout` port converted on the actual side only in a port map, such as `q => conv(s)`, is now
  an analysis error instead of passing the other direction unconverted. One converted on the
  formal side only, `conv(q) => s`, is accepted, also for record and array ports: the conversion
  applies to the value going out and the actual passes in unchanged. (#74)
- A call of a generic package instance's subprogram whose parameter type is reached through a formal package of a formal package (`s.r.arr`) with an actual of the instance's own type is now an analysis error (`E1300`), as in most other simulators, instead of being accepted. (#101)
- An external name used as the actual of an `in` port is a signal name actual again: the port
  starts at the external signal's value and follows it in the same delta. (#186)
- A generic subprogram of a component or block used as the actual of an entity's generic subprogram in a generic map is now an analysis error (`E1506`) at the actual. The default binding of a component's generic subprograms by name is unchanged. (#222)
- Concatenation (`&`) of arrays whose elements are arrays or records now works in variables, signals, constants and generic actuals, instead of stopping with a not-lowered error. (#234)
- `'element` attributes (`'length`, `'left`, `'range` and the others) of objects whose element bounds are open, such as an unconstrained port or an alias of an external name, read the bounds of the actual object. Constants computed from a port's bounds, such as `constant w : natural := p'length`, now see them. (#235)
- A type, subprogram or package interface in a port clause is now a coded error at the interface (`E1234`), and so is a generic list or generic map on a formal generic subprogram (`E1235`), instead of an unsupported-feature error. (#236)
- An `inout` port associated with conversions on both sides, `to_bv(b) => to_int(t)`, now
  analyzes and simulates: the actual part converts the actual to the port's type and the formal
  part converts the port back to the actual's type, for scalar and record ports. (#238)
- `'stable`, `'quiet`, `'delayed` and `'transaction` named in a process body, or in a subprogram declared in a process, an architecture or a package body, now elaborate and simulate instead of stopping with an internal error. (#240)
- An array value under `others` in an aggregate, such as `(others => a)` with `a` of the aggregate type, is an analysis error (an `others` association gives an element), as in the other simulators. (#242)
- A range choice in an aggregate assignment target, such as `(5 downto 2 => hi, 1 downto 0 => lo) := v;`, is now an analysis error (`E1333`) at the choice instead of a failure in a later stage. The LRM does not say how such a choice maps the value's elements; positional and element-choice targets are unchanged. (#244)
- A procedure call through a name whose declaration already failed, such as an alias of an undeclared subprogram, no longer adds a second error ("is not a procedure"); only the failed declaration is reported. (#245)
- An access value that a function allocates while initialising a variable of a shared protected object or a package object, at any call depth, stays valid during simulation instead of failing as deallocated. (#246)
- A constant of an array type with a constrained element subtype, such as `constant k : ow(0 to 1)(3 downto 0) := ("0000", "1111")`, keeps the declared element bounds when it is read as a whole, passed to an unconstrained parameter or generic, or asked for `'element'left`; before, it reported the bounds of the literals that initialise it. (#247)
- A shared variable declared in a block or generate statement is now one object per block or generate
  iteration, also for processes in nested blocks and generates. (#249)
- Inside a protected type body, an expanded name with the type as prefix (`pt.n := n;`, `pt.get`)
  now names the body's state or a method of the current object; outside the type it is an error. (#250)
- A constant declared in a process whose initial value calls an impure function with side effects, such as registering a named object in a shared registry, is now evaluated once instead of twice. (#251)
- Processes resumed in the same simulation cycle now run in a fixed order chosen by their shape:
  processes with a sensitivity list or a single wait statement first, in elaboration order, then
  the other processes in reverse elaboration order, those woken by a signal before those woken by a
  timeout. Testbenches that check, in the same cycle, a value reported by a process of an
  instantiated entity now behave as they do in other simulators. (#252)
- A call that no overload accepts, such as a reflection `get` with an `integer` where `index` is expected, is reported as a mismatched call also when its result is selected from (`m.get(i).simple_name`), instead of "not an object, literal or function". (#253)
- 'element'element'left and deeper (`'element'element'element`) of an object whose element subtypes are open at every level, such as an `array of (array of bit_vector)` signal, port, parameter, variable, alias or constant, now report that object's bounds; before, they returned 0 for a signal actual. (#256)
- A subprogram formal with open dimensions and constrained elements, such as `ow(open)(7 downto 0)`, now reports its own element bounds for `'element` whatever the actual's, and a call whose actual has a different element length is a length-mismatch error instead of being accepted. (#257)
- A type mark as the formal part of a port association is now checked: the formal's type and the type mark must be closely related, otherwise the association is rejected with E1350. (#259)
- `inertial` on a part of an individual association (`i(1) => inertial s`) now makes the part an expression actual that follows the signal one delta later, as for a whole port; on a port that is not `in` it is an error. (#261)

## Documentation

- A new documentation page, "Where simulators differ", lists the places where the VHDL standard is open to interpretation, what yavs does at each, and a portable alternative.

## Miscellaneous

- Implicit operations of types whose names look like an operand-shape suffix (`pi`, `ss`, `reduce`) are no longer confused with it; end-to-end tests cover record equality, null concatenation and negative arithmetic shifts. (#163)
- External names as port map actuals are covered end to end for relative, generate-indexed and package paths. (#181)
