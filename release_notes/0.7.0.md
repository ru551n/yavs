Adds VHPI plugin loading and callbacks, external names in subprograms and packages, shared variables of non-protected types and more VHDL-2019 forms, and fixes; three breaking changes make some code that was accepted an analysis error: the most negative literal, static indexes outside their range, and TIME literals finer than `--resolution`.

## Breaking changes

- The literal `-9223372036854775808` (integer and physical) is now an analysis error (`E1402`); write `-9223372036854775807 - 1` for the 64-bit minimum. (#214)
- Selecting a time resolution limit with `--resolution` makes a TIME literal with a finer unit anywhere in the design an error (LRM 5.2.4.2), so a design that ran with a coarse limit before can now fail; `0 fs` and values such as `0.4 ns` under `ns` stay legal. (#253)
- A static index or slice outside the index range of its array is now an analysis error (`E1404`), also in code that never runs; it was warning `W1404`.

## Features

- VHDL-2019 generic array types with anonymous index or element types, such as `type vt is array (type is range <>) of type is private`, or with an index constraint now analyze, instantiate and run; inside the generic they are indexed, sliced and iterated like any array type. (#30)
- The IEEE 1076.4 VITAL packages (`ieee.vital_timing`, `ieee.vital_primitives`, `ieee.vital_memory`) are built in for VHDL-2008 and 2019, so VITAL-style models analyze and simulate (functional, zero-delay use). (#118)
- The analysis corpus runner can measure vendor primitive libraries (`unisim`, `unimacro`) read in place from a local installation named by an environment variable; the manifest is skipped when the variable is unset. A design that only uses the `unisim` component package now analyzes. (#119)
- Signals left out of `yavs run --wave` by `--wave-include`, `--wave-exclude` or `--wave-max-array` are no longer read while simulating, so recording a few signals of a large design stays cheap. The user guide has a Waveforms section on what is recorded and how. (#145)
- Aggregate assignment targets accept range choices, such as `(5 downto 2 => hi, 1 downto 0 => lo) := v;` and the signal form, in any order and mixed with element choices, instead of rejecting them with `E1333`. (#244)
- External names work inside subprograms and packages: procedures and functions of a package, an architecture or a process can read, force, release and wait on signals of the design, read its constants and call methods of its protected shared variables through external names, and package paths (`<<variable @lib.pkg.v : t>>`) name package objects of every class. (#255)
- Group templates, group declarations and disconnection specifications now analyze and run. A group can be decorated with an attribute, and `disconnect s : t after 5 ns;` (also with `others` and `all`) sets how long a guarded `bus` or `register` signal keeps its value after its drivers disconnect. (#260)
- Unconstrained ports can be associated through a type conversion or conversion function whose subtype is constrained, on either side (`i => w4(u)`, `u4(o) => s`), including arrays of records and records with unconstrained elements: the port takes its bounds from the conversion. A conversion that gives no bounds is an error. (#262)
- A 2019 signal parameter or port with a mode view can be associated element by element, for example `send(b.x => s1, b.y => s2)` and `p.x => s1, p.y => s2`: each element has the direction the view gives it, and a call drives only its `out`, `inout` and `buffer` elements. (#265)
- The `yavs` executable now exports the VHPI C interface (`vhpi_*`) on Linux and Windows, so VHPI plugins can bind to it. (#266)
- `yavs run --vhpi=LIB[:ENTRY]` loads VHPI plugins, fires their start and end of simulation callbacks and honours `vhpi_control` stop and finish; a plugin that cannot be loaded is reported before the simulation starts. (#267)
- VHPI plugins can walk the elaborated design: instances, blocks, generate iterations, processes, packages and their generics, ports, signals, constants and variables, down to record fields and array elements, and look objects up by name or index, with names in their original spelling. (#269)
- VHPI plugins can register callbacks for every phase of the simulation cycle (next time step, start of each cycle, last known delta cycle, end of time step, end of initialization) and after a delay, in one-shot and repeating forms, and disable, enable, remove and inspect them; disabled callbacks cost nothing while they wait. VHPI times now count in units of `--resolution`. (#272)
- VHDL-2019 range values work: `x'range'value` and `x'reverse_range'value` (also `t'range(2)'value` and type marks) give the range record of the range, in analysis and simulation. (#282)
- Shared variables of non-protected types (VHDL-93 style, accepted with `--relaxed`) now simulate, in packages as well as in architectures, blocks and generates. The processes that use them, directly or through subprograms, run one at a time, so the output is the same at any `--threads`; `--shuffle` exposes testbenches that depend on process order. (#285)

## Bug fixes

- A signal or shared variable in the body of a generic package instantiated inside a process or subprogram is now reported as an analysis error (`E1237`) instead of failing later in lowering. (#34)
- A condition of type `std_ulogic` now needs the `??` operator to be visible (for example `use ieee.std_logic_1164.all`); making only the type visible is an analysis error (`E1340`). (#48)
- A constant parameter of an access type in your own VHDL-2019 code is now an analysis error (`E1223`), as in VHDL-2008; the `std` library keeps its own such parameters. (#198)
- An access-typed parameter of a protected method is now an analysis error (`E1223`) in VHDL-2019 as well as in VHDL-2008. (#212)
- In a subprogram call, a formal conversion whose overloads differ only in their result type is now an analysis error (`E1302`) instead of being chosen by the actual's type. (#229)
- A named aggregate whose array values sit under `downto` range choices, such as `(3 downto 2 => a, 1 downto 0 => b)` passed to an unconstrained parameter, now takes the direction of those choices, so each value lands where the choice names it; mixing directions among such choices is an analysis error (E1334). (#230)
- Aggregate choices written as range attributes, such as `(hi'range => 1, 1 downto 0 => 2)`, are accepted next to other choices, and a subtype name used as a choice can take an array value, as in `(hr => hi, lr => lo)`. (#244)
- A shared variable of a protected type declared in a package declaration, before the protected body in the package body, is now an error at the variable (E1230), as in the reference simulators. (#258)
- A non-static expression actual of a scalar part in an individual association (`r.f => x + 1`) is now checked against the part's subtype, so an out-of-range value stops the run with a range error instead of entering the port. (#263)
- Aggregate targets with element choices only, such as `(0 => a, 1 => b) := v;`, now give the aggregate's leftmost index the value's leftmost element whatever the value's bounds, the same rule as for range choices, instead of naming the value's own indices. (#264)
- Statement labels can now be named as constituents of a group, and a shared variable in the body of a nested generic package instantiated before its body inside a process or subprogram is reported (`E1237`). (#284)
- A signal attribute such as `s'delayed(0 ns)'last_event` is accepted wherever a time value is expected: `'delayed`, `'stable`, `'quiet` and `'transaction` of a signal are signals themselves. (#286)
- The range of a record element of a signal with a record constraint (`sig.rdata'range`) can be used as a bound in a later declaration of the same region. (#287)
- A record port with unconstrained elements can be associated element by element in a port map, such as `pin.d => sd`: each element takes its bounds from its actual. (#288)
- An aggregate such as `(others => '1')` can be the actual of a generic whose subtype uses an earlier generic (`DEF : bit_vector(W - 1 downto 0)`); its bounds come from that subtype with the earlier generic's actual. (#289)
- An alias of a record element of a port (for example `alias f : id_t is r.fifo;`) can now be read and passed as an actual in a process. A failure while lowering a design that carries no diagnostic is now reported as an internal error instead of ending `yavs run` with exit 2 and no message. (#292)
- Signals of a subtype with your own resolution function on `std_ulogic`, `bit` or `boolean` now simulate, and so do element-wise resolved arrays such as `(resolved_max) std_ulogic_vector`, which used to resolve only their first element. (#293)
- The attributes `'range`, `'length`, `'high` and the like of a signal declared in a package can be used in a port or signal subtype; they take the bounds of the signal's subtype. (#294)
- An alias of an element or slice of a variable (`alias id : std_logic_vector(3 downto 0) is v(7 downto 4);`) can now be read and assigned in a process. (#296)
- A block configuration of an instance that is only default-bound is now an analysis error (`E1704`); bind the instance with a configuration specification or `use entity`.
- A component configuration may repeat the entity aspect of the configuration specification that binds the instance (VHDL-2008, 7.3.2.1); only a different entity aspect is an error.
- An aggregate target whose only choice is not locally static, such as `(i => a) := v;`, works again, and every aggregate target now raises a runtime error when its value has more or fewer elements than the target covers, instead of assigning part of it.

## Documentation

- Test runner recipes: a new user page shows how to drive yavs from an external Python test runner, compile verification libraries from source into named libraries, and use vendor libraries from a local install. (#275)

## Miscellaneous

- CI loads the VHPI test plugin into `yavs.exe` on Windows (MSVC) with an import library built at test time. (#124)
- `tools/suites/pro.py` runs a verification library's own regression from its build scripts on yavs and lists the result per test. (#276)
- A driver under `tools/suites` runs the maintenance testbenches of a verification-library corpus on yavs and reports pass, fail and skip per component. (#277)
