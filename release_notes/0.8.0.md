A Debug Adapter Protocol debugger with a VS Code extension, code coverage (statement, branch and toggle, merged databases, text, Cobertura and HTML reports), PSL assertions at run time, the Synopsys arithmetic packages built in, an LLVM tier, much wider VHPI support (reading and writing values, value-change callbacks, foreign subprograms, iterators, plusargs), waveform recording of variables, and many VHDL-2019 and elaboration fixes; one breaking change: VHPI puts with the non-propagating modes on signals are refused.


## Breaking changes

- VHPI `vhpi_put_value` refuses the non-propagating modes `vhpiDeposit` and `vhpiForce` on signals (warning W0903, return 1); use `vhpiDepositPropagate` and `vhpiForcePropagate`.

## Features

- `force` and `release` now apply to composite signals and their parts (whole arrays and records, slices, fields and elements, also through aliases of external names), in the simple, conditional and selected forms; forcing a member of a composite signal resolved as a whole is reported as an error. (#68)
- The Synopsys packages `std_logic_arith`, `std_logic_unsigned`, `std_logic_signed` and `std_logic_misc` are built into library `ieee` as the original files and are visible without a flag, so existing designs and vendor primitive models that use them analyze and simulate. (#117)
- `yavs run --tier=llvm` runs a design with every function compiled by the LLVM tier, with the same output as the interpreter, in a yavs built with the `llvm` feature. `--verbose` lists what the tier leaves to the interpreter. (#125)
- `yavs run --dap=PORT` (or `--dap=stdio`) runs the design under a Debug Adapter Protocol debugger: line breakpoints with hit counts, pause, step over, into and out of subprograms within a process, call stacks with source positions, process variables, signals and generics, and reading any signal by name or path, with the simulation time and delta at every stop. (#130)
- Code coverage: `yavs run --cov[=FILE]` counts statements and branches (`if`/`elsif`/`else`, `case` alternatives, conditional and selected assignments, loop bodies) per instance and writes a coverage database; `yavs cov merge` adds databases of several runs together, and `yavs cov report` prints a text summary with every uncovered line and writes a Cobertura XML report with `--cobertura FILE`. (#131)
- PSL assertions run: `default clock`, `assert`/`assume` with `always`, `never`, `->` and `next[n]` on VHDL conditions, `cover` of a condition, `@` clocks and `report`/`severity` clauses are checked during simulation, written as VHDL-2008 statements or in `-- psl` comments (with `--psl`). Other PSL is still skipped with warning W0004. (#226)
- VHPI plugins can read the values of signals, ports, generics and constants and of their record fields and array elements with `vhpi_get_value`, in every standard format, including the object's own format and the buffer-size protocol. They can also inspect types: base types, subtypes, range constraints, enumeration literals, record elements and physical units. (#270)
- VHPI plugins can write signals, ports and their elements with `vhpi_put_value` (deposit, force and release), so a testbench can clock and drive a design entirely from VHPI. (#271)
- VHPI plugins can register value-change callbacks on signals, ports and their elements; each runs once in every cycle in which the object changed and receives its value in the format it asks for. (#272)
- A VHPI plugin can implement VHDL functions and procedures: register them with `vhpi_register_foreignf` and mark the subprogram `attribute foreign of f : function is "VHPI library model"`; the plugin reads the parameters with `vhpi_get_value` and returns values with `vhpi_put_value`. (#274)
- VHDL-2019 generic constants, ports and subprogram parameters declared with an anonymous type, such as `c : type is range <>`, now analyze and run: the type is the type of the actual, checked against the written class. (#283)
- `yavs run` accepts `+NAME` and `+NAME=VALUE` plusargs after the top level and passes them to VHPI plugins as the tool's arguments. (#298)
- Passive concurrent assertions and passive processes in an entity declaration (entity statements) are elaborated and run for every instance of the entity. (#301)
- A record value can be assigned to an aggregate variable target, as in `(x, y, z) := f;`. (#302)
- Shared variables of non-protected types holding access values (accepted with `--relaxed`), such as coverage packages with linked lists or records with `line` fields, now simulate. Objects that become unreachable are reclaimed between simulation cycles, so long runs of logging code no longer grow without bound. (#303)
- `yavs run --wave-variables` also records the scalar variables of processes in the waveform, sampled at the end of each time step and selected by `--wave-include` and `--wave-exclude`. (#305)
- Waveforms record an integer with the name of its subtype and the width its range needs (`natural range 0 to 255` is 8 bits, negative ranges are signed), and the chosen alternative of an if or case generate keeps its label in the scope name (`g.alt1`). (#306)
- VHDL-2019 parameters with an anonymous type (`x : type is ...`) now also work in formal generic subprograms, in subprograms that have a generic list, and in user operators called with operator syntax. (#308)
- VHPI plugins can read and deposit process variables and shared variables, including their record fields and array elements, with `vhpi_get_value` and `vhpi_put_value`. (#309)
- VHPI `vhpi_iterator` lists the child blocks (`vhpiBlockStmts`), component instances (`vhpiCompInstStmts`) and all concurrent statements (`vhpiStmts`) of a region. (#316)
- VHPI plugins can register `vhpiCbStartOfProcesses`, `vhpiCbEndOfProcesses` and `vhpiCbStartOfPostponed` callbacks (and their repeating forms). (#317)
- VHPI `vhpi_get_value` reads an integer object in the `vhpiEnumVal` format too. (#318)
- A VHPI plugin can write an integer into a logic vector, and a value put from an after-delay or start-of-cycle callback now takes effect in a new delta cycle. (#319)
- A condition of a type whose `??` operator is declared beside the type now uses that operator even when only the type is made visible, as in `use ieee.std_logic_1164.std_ulogic` followed by `if s then`. (#320)
- A configuration may now give a block configuration for a component instance that is bound by default (no binding indication): the default binding supplies the entity. (#320)
- In VHDL-2019 files, protected type methods may take parameters of an access type (or of a composite holding one); VHDL-2008 files still reject them. (#320)
- A subprogram parameter whose type is reached through a formal package of a formal package (`s.r.arr`) accepts an actual of the actual instance's type in a package instance. (#320)
- `yavs run --wave-variables` also records array and record variables (as scopes, like signals) and non-protected shared variables of architectures and packages, and sizes an integer variable whose range depends on a generic after its elaborated range. (#321)
- The debugger (`yavs run --dap`) stops when a signal changes or takes a given value: "Break on Value Change" on a signal in VS Code's Variables view, the extension's "Break when a signal equals..." command, or a signal named by path. (#322)
- The debugger (`yavs run --dap`) forces, deposits and releases signals and sets variables: "Set Value" in VS Code's Variables view, the extension's force, deposit and release commands, or the `yavs/force`, `yavs/deposit` and `yavs/release` requests, with values written as VHDL literals such as `x"A5"` or `(a => 1, others => '0')`. (#323)
- The debugger (`yavs run --dap`) runs for a time or until a time, steps to the next delta and to the next time step, and reports the simulation time and delta at each stop; the VS Code extension adds commands for them. (#324)
- The debugger (`yavs run --dap`) takes conditions on line and signal breakpoints, written as VHDL expressions such as `count = 3 and state = IDLE`, expands records and arrays in the Variables view, and shows the design hierarchy with its processes and signals in a Hierarchy scope and through the `yavs/hierarchy` request. (#326)
- VHDL-2019 named return values now work for scalar types too: in `function f return r of integer`, `r` takes the range of the call's target, also for enumeration, physical and floating point types, generic subprograms whose generic type is scalar, and protected methods. (#327)
- A VHPI foreign function can return an array: the plugin sets an unconstrained result's length with `vhpi_put_value` in `vhpiSizeConstraint` mode, then puts the value. Foreign subprograms can also take records, access values and signals; an `out` signal parameter is driven with `vhpi_schedule_transaction` on its driver. A plugin can implement a whole architecture (`attribute foreign of arch : architecture is "VHPI library model"`): it creates a process and drivers with `vhpi_create` and drives the ports with `vhpi_schedule_transaction`. (#330)
- Signals whose record fields or array elements have a subtype resolved as a whole (a record of resolved records, an array of resolved records or bit vectors) simulate, each such element resolved with its own drivers, and a resolved field inside a resolved record no longer stops elaboration. (#333)
- `yavs run --cov` also counts toggle coverage: how often every `std_logic` and `bit` signal, port, vector element and record field went 0 to 1 and 1 to 0, shown in the text report and in the `--uncovered` exclusion rows. `--cov-kind` picks which kinds of coverage to count. (#343)
- `yavs cov report --html DIR` writes a self-contained HTML coverage report: totals, a row per instance and file, and per source file the hit count of each line, missed statements, branch arms and toggles with copyable exclusion rows, excluded items greyed with their reason, and the tests that hit each item. A "missed only" page per source file (`src-N-missed.html`, linked from the index and the file page) lists just the lines with a missed or excluded item, so large designs stay usable without scripts. (#344)
- Aggregate assignment targets can name record fields in any order, be nested aggregates (records of records, arrays of arrays) and be multi-dimensional arrays written as an aggregate of aggregates, for variables and signals alike. (#350)
- Coverage exclusions: `-- coverage off` / `-- coverage on` / `-- coverage off-line` comments leave code out of the coverage database, `yavs cov report --uncovered` prints every miss as a row you can paste into an exclusion file, and `yavs cov report --exclude FILE` leaves those items out of the totals and Cobertura report, listing them with their reasons. Rows match by the statement's text, so edits that move a statement do not break them; stale rows, moved lines and excluded items that ran are warnings. (#351)
- Coverage databases record which tests hit each item: `yavs run --cov-test NAME` names the run (by default from the test case or the top level and its generics), `yavs cov merge` keeps the attribution, `yavs cov rank` finds a small set of tests that reaches the same coverage and what each test alone covers, and `yavs cov report --tests` lists the tests behind every item. (#353)
- A VS Code extension in `editors/vscode` debugs VHDL testbenches with yavs: it analyzes the listed files, starts the simulation under the debugger and supports breakpoints in VHDL files, configured in `launch.json`.
- The new option `--psl` (`parse`, `analyze`, `elab`, `run`) makes yavs read `-- psl` comments as PSL pragmas; without it they are comments, as in the reference simulators. PSL statements written in VHDL-2008 syntax are always read.

## Bug fixes

- A pure function whose result type is or contains an access type is rejected (E1830, warning with `--relaxed`), as the language requires; only the vendored VITAL packages are exempt. The VITAL exemption from the purity check is now limited to calls of `NOW`. (#118)
- A conversion on an unconstrained formal of a subprogram call, such as `setv(b4(x) => v)` with a constrained subtype `b4`, is accepted and gives the formal the conversion's bounds, as for ports; only a conversion that defines no bounds is an error. (#229)
- Concurrent procedure calls that loop on a wait now run before the other multi-wait processes in a simulation cycle, so a protocol checker written that way sees a testbench process's report of the same edge after its own, as in the reference simulators. (#281)
- A source file can be analyzed into several libraries and a design can use the units of all of them; each library keeps its own copy of the units. (#290)
- A component declared in a package of another library is bound by default to the entity of that name in the package's library instead of being left unbound. (#291)
- A constant declared without a value in a package and given its value in the package body can now be used during elaboration, for example as a generic default, a signal range or a generate bound. (#295)
- FILE_OPEN with APPEND_MODE, WRITE_MODE and READ_WRITE_MODE opens the file in the requested mode under `--std=2019` (APPEND_MODE of a missing file used to fail), and `VHDL_VERSION` and the INTEGER range of text reads follow the selected standard. (#297)
- A `report` (or assertion) in a function called while the design is elaborated, such as one in a signal initial value, prints its message at elaboration instead of failing the run. (#299)
- An alias of a constant with a static value declared in a subprogram works; it no longer fails with "not lowered to IR yet". (#300)
- Attributes such as `'length` and `'range` of an element of a record port (`p.data'length`, also of nested records and arrays of records) can be used in constants, signal subtypes and generate ranges of the instance; they take the bounds the actual gives the port. (#304)
- An aggregate assignment target that names the same variable or signal twice, or gives one association several choices, is rejected at analysis (E1335). (#307)
- A signal that a VHPI plugin deposited, then forced and released, returns to the value of its drivers. (#310)
- An aggregate whose choice is the range of an unconstrained port, such as `(tid'range => '0')`, can be used in the initial value of a signal or constant of the instance. (#311)
- A constant built from an entity's `'PATH_NAME` or `'INSTANCE_NAME`, directly or through an impure function, can be used as a generic actual: it is evaluated during elaboration instead of failing with E2106. (#314)
- An alias of a record element of a variable (`alias a : v.rd'subtype is v.rd`) keeps the element bounds of the variable, also when the variable is declared as `port'subtype`; signals and constants declared with the `'subtype` of a port element take the bounds the actual gives the port. (#315)
- A static index or slice outside the index range of its array is a warning (`W1404`) again, so a design with such code in a branch that never runs analyzes; it is still an error when the code runs. (#320)
- Reading an element of an element of a constant array of arrays of an unconstrained array type (for example `r(i)(0)` with `type uvecvec is array (natural range <>) of uvec` and `uvec` an array of `unsigned`) works, also for an aggregate passed to a subprogram, instead of stopping with an internal error. (#329)
- `vhpi_handle_by_name` accepts `.` between the levels of the hierarchy (`:TOP.CHILD.SIG`) as well as `:`, with or without a scope handle. (#331)
- VHPI range handles report `vhpiIsUnconstrainedP` 0 (and unconstrained array types 1) instead of undefined, and `vhpiStrValP` of an enumeration literal returns the literal text. (#332)
- VHPI plugins can read and deposit a process variable before its process first runs (from the start of simulation on) and a shared variable no process uses. (#342)
- VHPI `vhpi_put_value` with `vhpiStrVal` accepts text shorter or longer than the array: it fills from the left, pads with NUL and cuts what does not fit. (#345)
- A VHPI value-change callback registered while a cycle's value changes are dispatched, such as one re-armed from inside its own callback, now first fires in the next cycle instead of again for the same change. (#346)
- VHPI read-write (last known delta) and read-only (end of time step) callbacks now also run at time 0 when the design has no delta cycle there, so a value written from them at time 0 takes effect at time 0. (#347)
- VHPI reads and deposits array and record variables of processes that use shared variables, which failed before. (#348)
- A `report` or assertion of severity error during elaboration, such as one in a signal initial value, is now counted like a run-time one: the run still goes on and ends with exit status 1. (#349)
- A process that loops without a wait, writing textio lines or deallocating objects, no longer keeps the memory of every deallocated object until it waits: freed heap slots are reused inside the loop. (#355)
- Coverage exclusion `file` rows match source paths written with either `/` or `\`, so exclusion files work the same on Windows. (#358)
- VHPI `vhpiCbEndOfProcesses` callbacks also fire once after initialization's process run (before end of initialization), as most reference simulators do.
