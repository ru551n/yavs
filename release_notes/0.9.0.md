yavs 0.9.0 brings compiled code to every release archive, a broad round of speed work, VHDL-1993 support, and better coverage, debugging and diagnostics.

- **Compiled code built in:** each platform (Linux x86_64, Linux aarch64, Windows x86_64) has one archive with a Cranelift compiled tier and the graphical debugger; `--tier=auto`, the default, compiles hot code during the run and nothing else needs to be installed.
- **Faster everywhere:** the interpreter, the kernel and compiled code all do less work per cycle, and analysis, elaboration and start-up reuse cached work between runs and test cases.
- **VHDL-1993:** `--std=93` analyzes and simulates 1993 code against the 1993 `std` and `ieee` packages and checks the 1993 rules that later revisions relaxed.
- **More VHDL-2019 and PSL:** generic protected types, `'IMAGE` and `'VALUE` of composites, generic-mapped subprogram calls, PSL sequences, properties and built-in functions.
- **Coverage:** condition and expression coverage, YAML exclusion files, an interactive HTML report, and much cheaper coverage runs.
- **Debugging:** the graphical debugger `yavs-gui` (`yavs run --gui`), live waves over the debug protocol, `--profile`, `--time-report` and hang reports that explain a stuck simulation.
- **VHPI additions:** foreign library and application models, user attributes, `vhpi_format_value`, `vhpi_get_next_time` and more properties and callback reasons.
- **Readable diagnostics:** many internal errors are now clear errors that name the problem and the rule, and analysis warns only for the files you name.
- **New user guide:** getting started, libraries, waveforms, coverage, debugging, VHPI, running faster, a command-line reference and troubleshooting.
- **Breaking:** the library format changed; delete libraries made by an earlier version and analyze their files again.

## Breaking changes

- A library is now an index (`yavs-lib.toml`) plus a record per source file (`yavs-lib.d/`), so `yavs analyze` reads and writes only what its file needs instead of the whole library, which makes analysing a library file by file faster. Libraries written by an earlier version are refused with a message naming the directory; delete it and analyze its files again. (#599)

## Features

- Every platform has one release archive, `yavs-<version>-<target>`, with a compiled tier built in: `--tier=auto` (the default) compiles the hot code during the run and nothing else needs to be installed. `yavs --version` says `compiled tier: cranelift`. (#780)
- `--tier=auto`, the default, compiles the functions and processes that become hot on a background thread while the simulation keeps running in the interpreter, with the same output. It picks what to compile by sampling the run against a compile budget, checks after swapping compiled code in whether the run progresses faster and takes the code back where it does not, and keeps a small profile of each run so the next run of the same design compiles what was hot at once (`YAVS_AUTO_PROFILE=off` turns that off). `--tier=interp` runs the interpreter alone. (#125, #336, #596, #754)
- A yavs built with the `clift` feature compiles with Cranelift and needs nothing else installed: `--tier=clift` translates every function before time 0, `--tier=clift-auto` translates the functions that become hot, and without the `llvm` feature `--tier=auto` is `--tier=clift-auto`. `yavs --version` says `compiled tier: cranelift`. (#481)
- Compiled code runs more of a simulation without handing it back to the interpreter: variables, arrays and their layouts, signal reads and drives, clock-edge tests, waits, reports, natives, protected-object calls, and calls between compiled subprograms on native frames with their arguments in machine registers, which covers most functions of large verification libraries. Error messages and call stacks are unchanged. (#334, #335, #336, #338, #339)
- Compiled code is kept in the compilation cache of the work library, so a later run of the same design, or another test case of it, links the code instead of compiling it again; `--no-cache` and `yavs cache clean` cover it. (#505, #785)
- `yavs run --tier-max-size=N` sets the size above which the compiled tier leaves a function to the interpreter, so a very large process does not hold up the run while it compiles. (#126)
- The LLVM tier (`--tier=llvm`, and `--tier=auto3` with both code generators) stays available in a yavs built from source with the `llvm` feature; it loads LLVM only when a run first needs it. (#127, #426)
- VHDL-2019 generic protected types can be instantiated with `type t is new pkg.prot generic map (...)` and used for variables and shared variables; each instance gets its own generics in the methods and the body. (#29)
- A block configuration can select the iterations of a for-generate with a subtype indication (`for g(natural range 1 to 2)`), and a range or subtype indication as the actual of a port or generic is reported as an error instead of an internal one. (#35)
- Files of records and of arrays of composites can be written and read back with `write` and `read` (the stored form is the value's image, readable by yavs only, into an object with the same bounds). (#79)
- VHPI plugins can read user attributes of declarations (`vhpiAttrSpecs`), convert values between formats with `vhpi_format_value`, use the time-out and sensitivity callback reasons, and query more tool and region properties (capabilities, port and generic counts, labels, generate indexes). (#143)
- `yavs run --dap` now works together with `--wave` and `--vhpi`, and streams live waves: a client subscribes to signals and variables with `yavs/waveSubscribe` and receives their changes per time step as `yavs/waves` events, without ever slowing the simulation down. Values are compact: base64 of the same value bytes the waveform file gets, and the subscribe response gives each signal's `encoding` so a client can decode them. (#325)
- A sequential signal assignment may contain `null` waveform elements for guarded (`bus` and `register`) signals: the driver is disconnected at the element's time, as the standard describes. (#352)
- VHPI library and application foreign models now run: a `vhpiLibF` model's elaboration function when a foreign model of its library is bound and its execution function at the start of the simulation, a `vhpiAppF` model's both at the start of the simulation whatever the design. (#357)
- VHDL-2019 `T'IMAGE(X)`, the object form `X'IMAGE` and `TO_STRING` now work for arrays and records, including nested composites and signals, instead of stopping with an internal error. (#360)
- VHDL-2019 arrays, records and access types whose elements are protected types now work: each element is its own protected object, and its methods can be called through indexing, record selection and `.all`. (#361)
- VHDL-2019 calls of uninstantiated subprograms with a generic map, such as `ident generic map (t => integer) (4)`, now work for functions, procedures and concurrent procedure calls. (#362)
- VHDL-2019 signatures in the formal part of a generic map, such as `generic map (f [integer return integer] => inc)`, now select the formal subprogram, also among overloaded formals. (#363)
- The debugger forces, deposits and releases a part of a signal (a record field, an array element or a slice) without touching the rest, and "Set Value" on a field or element of a signal deposits only that part. (#364)
- `yavs run --time-report` prints the wall and CPU time of each phase (analyze, elaborate, init, simulate) to standard error, to see where the time of a run goes. (#387)
- `yavs run --gui` opens a run in the new graphical debugger `yavs-gui` (also started as `yavs-gui -- <run arguments>` or `yavs-gui --attach HOST:PORT`): run, pause and stop the simulation and read its reports in a console, in a window of dockable panels. Release archives now include `yavs-gui`. (#388)
- The common `std_logic_1164`, `numeric_std`, `math_real` and Synopsys `std_logic_arith` functions (logic gates on vectors, `+`, `-`, `*`, comparisons, `resize`, conversions, shifts, `rising_edge`, `sqrt`, `exp`, `log`, `sin`, `cos`, `floor`, `**`) run natively and are much faster than their VHDL bodies, with the same bounds, warnings and error reports; set `YAVS_NO_NATIVE_IEEE=1` to run the library bodies instead (`math_real` results may differ in the last digits). (#395)
- `yavs-gui` can debug: a source view with a breakpoint gutter (click to toggle, right click for a condition and hit count), the current line highlighted at a stop, a call stack for every process, locals and signals with lazily expanded records and paged arrays (double click to change a local), watch expressions, hover values, step over, in and out, step to the next delta or time step, run for a time, and the time and delta of the stop in the status bar. (#399)
- `yavs elab` and `yavs run` keep the analyzed design in a cache next to the work library, so the next run of the same design starts without analyzing its files again; results are identical, `--no-cache` turns it off and `yavs cache clean` empties it. (#407)
- Recording waves (`--wave`) costs much less run time and the files are much smaller: names with the same value (a port and the signal it is connected to, at every level of the hierarchy) are written once as FST aliases, value chains are LZ4-compressed, and values are converted and written with far fewer copies. (#410)
- An `in` port whose actual is a signal, or an element or slice of one, now shares the actual's storage instead of being a separate signal copied every delta cycle, so hierarchical designs elaborate and simulate with less work and memory; `--no-collapse-ports` keeps every port its own signal. (#413)
- More `ieee` functions run natively with the same results, bounds and warnings as their VHDL bodies: the `numeric_bit` arithmetic, comparison, conversion and shift functions, `shift_left`/`shift_right`/`rotate_left`/`rotate_right`, `to_hstring`/`to_ostring` and `math_real.uniform`; `YAVS_NO_NATIVE_IEEE=1` still runs the library bodies instead. (#414)
- With `--dap` and `--wave`, the waveform file is flushed at every debugger stop, so a waveform viewer open next to the debug session shows every change up to the stop.
  A run started with `--dap=PORT` says on stderr that it waits for a debugger and holds the simulation until a client attaches, so an editor can attach to a run started by a test runner; the VS Code extension has an "Attach to yavs" snippet and the usage guide a recipe for debugging one test. (#423)
- Lowered code is simplified before it runs (constant folding, shared address and descriptor computations, store-to-load forwarding, dead definitions), each function the first time it is called, and large arrays are allocated without a temporary copy, so simulations execute fewer instructions. `YAVS_NO_IROPT=1` turns the simplification off for comparison. (#427)
- `yavs run` writes report and `OUTPUT` text in blocks when standard output is a pipe or a file, which cuts the cost of testbenches that log heavily; a terminal, plugins and foreign code keep line-by-line output, and the order against error messages is unchanged. (#428)
- Interpreted code runs faster: more instructions and common instruction pairs are executed directly by the interpreter loop, and a subprogram call enters its callee with fewer lookups and a smaller frame. (#443)
- Files declared in an architecture work: the declaration opens them, processes of the instance share them, and each instance has its own. (#466)
- A VHDL-2019 type conversion between record types with the same element names runs. (#476)
- A design that runs again starts faster: the lowered design and the optimised code of the functions earlier runs called are kept with the compilation cache and read back instead of being made again. Release builds check the generated code of a function when it is first called instead of all of it at start (`YAVS_VERIFY_IR` checks everything at start). (#479)
- An `out` or `buffer` port that is the only source of its actual now shares the actual's storage too, so the processes inside drive the actual directly instead of through a separate signal copied up every delta cycle; `--no-collapse-ports` keeps every port its own signal. (#528)
- `yavs analyze` keeps the analysis of every design unit in its library and reads it back for the files
  that depend on it, so analysing a library one file per call, analysing a file again and the first
  `elab` or `run` of a testbench no longer parse and analyse unchanged dependencies; `analyze --no-cache`
  turns it off and `yavs cache clean` removes it. (#537)
- `yavs analyze` no longer waits for the disk to sync the library manifest: it is renamed into place, so a crash leaves the old or the new manifest, and a recording that changes nothing writes nothing. (#561)
- The analysed `std` and `ieee` packages are kept once per user (in the user's cache directory) instead of once per library, so analysing into a new library no longer analyses them again. `--std-cache=DIR|off` (or `YAVS_STD_CACHE`) chooses the directory or turns the sharing off, and `yavs cache clean` clears it too. (#564)
- `yavs run --profile[=FILE]` samples a simulation and reports which processes, instances and subprograms (with source file and line) it spends its time in, as a table on standard error and optionally as JSON. (#580)
- A simulation that is stuck or hung now says why: the delta cycle limit error names the processes and signals of the loop and how to raise the limit (`--max-deltas`), `--hang-report` (and `kill -USR1` on a running simulation, on Unix) lists what every waiting process waits for, which signals have no driver and which clock stopped, a process with no wait statement is warned about before time 0, and a shuffled run prints its seed and how to replay it. (#582)
- `yavs analyze` prints warnings and notes only for the files named in the call: a file that uses a library unit with a warning no longer repeats it, and `-Werror` counts the named files' warnings only. Errors are always shown. (#584)
- `yavs run --profile` now prints (and writes) the profile of the time run so far when the run is stopped with Ctrl-C or SIGTERM, and `--profile` with `--dap` is the user error `E0125` instead of an internal-style `E9999`. (#587)
- A package declaration with a generic map aspect (`package p is generic (g : integer := 1); generic map (g => 2); ...`) is accepted in a library and in a declarative part and used like an instance. (#598)
- Implemented VHDL-2019 `T'VALUE` for records and arrays, including constrained and unconstrained arrays, nested composites, multidimensional arrays, and logic vectors. (#609)
- yavs now analyzes and simulates VHDL-93 code: `--std=93` (or `1993`) selects the 1993 language and the 1993 `std` and `ieee` packages, where `std_logic_vector` is a type of its own, shared variables can have any type, and names that 2008 reserved or predefined are free. A design of 93 files runs against the 1993 packages; a 93 file in a 2008 design is checked as 93. (#629)
- Designs whose processes pass a wide record signal to many functions, such as a processor's register record, simulate much faster: a process with a sensitivity list reads such a signal once per activation instead of once per use, and a one-bit field of a record signal is read in place. (#630)
- Processes of parametrised designs that run for a long time switch to code specialised to the generics and constants of their instance, so such simulations run faster; the specialised code is kept in the compilation cache and is not used under a debugger, with coverage, or with VHPI access to variables. (#651)
- A `--wave` file now depends only on the recorded changes: blocks end by size alone, so two runs of the same design write the same bytes however fast they were. Set `YAVS_WAVE_FLUSH=5s` (or `500ms`) to also end a block after that much run time, which leaves more of the file if a run is killed. (#666)
- Records whose fields are logic values are stored and updated together, so reading, driving and updating a register record of many single-bit and vector fields is faster. (#686)
- Coverage exclusion files can be written in YAML (`--exclude exclusions.yaml`) with a reason per entry, and `yavs cov report --uncovered=yaml` prints the missed items in that form. A toggle exclusion can name one direction (`rise` or `fall`). (#687)
- Coverage can now measure conditions and logic expressions: `--cov-kind=condition,expression` counts, for every `if`, `elsif`, conditional assignment, loop and `exit`/`next` condition and every boolean assignment with two or more inputs, whether each input at each value decided the result alone (focused expression coverage). Missed rows are listed by `yavs cov report --uncovered`, shown as a table per condition in the HTML report, and can be excluded per row in text or YAML exclusion files. Inputs that are constant after elaboration (generics, constants, literals) get no rows. (#688)
- The coverage HTML report shows each line's items in a popup that opens only on a click (or Enter or Space on a focused line; Escape or a click outside closes it), with per-instance counts and tests, marks lines that ran in only some instances, shows source paths relative to the current directory (or `--root`), and has copy buttons for each missed item's exclusion row and YAML entry. (#689)
- Coverage runs keep the edge triggers: a process that only reacts to a clock edge is resumed at that edge, as without `--cov`, and the toggle observer is much cheaper, so coverage of clocked designs costs a fraction of what it did. The statement of a pure edge test (`if rising_edge(clk) then`) now counts the runs at initialisation and at its edge, and its false arm only the initialisation. (#707)
- Calls of pure functions of one character, enumeration or small integer argument that choose their result with a `case` or an `if` chain (hex digit to value, character to nibble, state to code) are answered from a result table made when the function is lowered, so parsers that call them for every character of a large input start up faster. Values whose evaluation reports or fails still call the function, so output and reports are unchanged; `YAVS_NO_CASETAB=1` turns the tables off. (#722)
- A file analysed with `--std=93` is now checked against the VHDL-1993 rules that VHDL-2008 relaxed: aliases of multidimensional arrays, unconstrained element types, `buffer` port associations with `out` or `inout` ports, packages inside declarative parts and array values as parts of aggregates are errors that name the 1993 rule. 2008 and 2019 files are unchanged. (#814)
- VHPI plugins can ask for the time of the next scheduled activity with `vhpi_get_next_time` in the read-only (end of time step) phase. (#828)
- A VHDL-1993 file that reads an `out` port or an `out` parameter (including `'event`, `'stable` and the other attributes that read the value) is now rejected with `E1360`, as the 1993 rules require; VHDL-2008 and 2019 files may still read them.
- A VHDL-2019 configuration declaration may configure an entity of another library; earlier revisions report an error as the LRM requires.
- A VHDL-2019 constant of a range record type (`X'range'record`, `X'range'value`) can be used as a range: in an index constraint, a range constraint, an array type definition and a loop.
- A `yavs analyze` of many files no longer waits for the disk after every file: it keeps the library manifest in memory and syncs it once at the end, so a batch of files costs a fraction of the same files one call each.
- A run of a design that uses packages with signals, shared variables or computed values now also reuses the lowered form of those packages from the compilation cache, so that part of the start-up work is skipped; results are unchanged.
- Added `yavs run --gc-threshold SIZE` to choose how much access-value memory is allocated before the heap is collected (bytes or a k, m, g suffix); the output does not depend on it.
- PSL `restrict`, `restrict_guarantee`, `assume_guarantee`, `fairness`, `strong fairness` and directives that call `nondet` or `nondet_vector` are for formal tools only and are now skipped without the `W0004` warning.
- PSL properties may now use `abort` and `async_abort`; both are checked at the clock tick like `sync_abort`, not between ticks as the PSL standard defines the asynchronous abort.
- PSL properties with `next_a`, `next_e`, `next_event`, `until`, `until_`, `before`, `before_`, `sync_abort`, `<->`, nested `next` and `always`, and a property after `|->` or `|=>` are checked at the clock like the simpler directives (weak forms only).
- PSL sequences and properties can be declared with `sequence` and `property`, with `boolean`, `const`, `sequence` and `property` formals, and used in covers, suffix implications and as the property of an assertion.
- PSL sequences run: `cover {a; b[*2]}`, `assert never {..}`, `assert always {..} |-> ..` and `|=> ..` with concatenation, fusion, alternation, `&&`, `&`, `within`, repetition counts and ranges, `[=n]` and `[->n]` are checked at the clock like the simple directives.
- PSL: `default clock` may stand among the concurrent statements, `[*n]` starts a sequence as `true[*n]`, a boolean may stand before `|->` and `|=>` and, with a repetition, after `never` or `cover`, without braces.
- Test cases of one library that start with the same packages share the analysis of them: the first run of a new test case analyzes only its own files.
- Test cases that start with the same library packages share more than their analysis: the first run of a new test case reuses the library's lowered code, the initial state of its packages and the optimised code of the library functions earlier test cases called, instead of making them again. A package body in a file of its own is now analyzed right after its package where it can be.
- The PSL checker subset evaluates the built-in functions `prev`, `stable`, `rose`, `fell`, `isunknown`, `countones`, `onehot` and `onehot0` inside `assert`, `assume` and `cover`.
- The analysis image of a design is made on its second run instead of its first, so a design that runs once (a test case of a suite) no longer pays for an image nobody reads.
- With `--relaxed`, an aggregate with an `others` choice assigned to a port, signal or variable parameter of unconstrained type takes the bounds of the object at run time (warning `W1325`) instead of being rejected.
- `T'length` of a discrete type or subtype (VHDL-2019) gives the number of its values, also for enumeration types and subtypes whose bounds are known at elaboration.

## Bug fixes

- An allocator now picks its access type from the type it allocates when several overloads fit (new integer = new integer), instead of being ambiguous. (#27)
- A block configuration for a for-generate whose index or range uses a generic of the configured design (`for g(n)`) selects the right iteration, and an error evaluating it is reported instead of leaving the default binding. (#41)
- A range attribute with `'record` (`T'range'record`) in a VHDL-2008 design is the error "not available in VHDL-2008" instead of an internal error. (#359)
- Writing a string to a `TEXT` file with the implicit `WRITE` stores just its characters, so `READLINE` reads it back, and `WRITE (OUTPUT, s)` prints the string. (#365)
- A `wait for` or a signal assignment whose time would fall after `TIME'HIGH` no longer stops the simulation with a time overflow: it never happens, and the simulation ends at `TIME'HIGH`. (#366)
- A resolution function receives the driving values as an array indexed from the left bound of its parameter's index subtype, so functions that index from `1` (a `positive` index) work. (#367)
- An array generic of a constrained subtype takes the bounds of its subtype rather than those of the actual, so slices and indices written against the declared range work. (#368)
- VHDL-2019 records that mix protected-type elements with other elements are now rejected with `E1905` at the offending element, as the LRM requires; records of only protected elements still work. (#371)
- A report made by a resolution function or a port conversion function during the run prints the time and delta of the cycle that called it, counts toward the exit status, and a failure report in one ends the run like any other failure. (#372)
- A guarded concurrent assignment no longer assigns in the delta cycle where its block's guard condition becomes false; the condition is tested on the current values of its signals. (#373)
- A concurrent signal assignment now also reacts to signals read only in the choices of an aggregate, such as `(1 to i => '1', others => '0')`. (#374)
- A file declared in a subprogram is closed, and its data written out, when the subprogram returns. (#375)
- The `'path_name` and `'instance_name` of a block or generate label now name that statement (`:top:g:`) instead of repeating the label (`:top:g:g`). (#376)
- A positional aggregate with more (or, without `others`, fewer) elements than the non-static constrained subtype it initialises or is assigned to is now a run-time length error instead of an internal error. (#378)
- Run-time checks the language requires are now made: a range or index constraint outside its type mark, the bounds of an array converted to an unconstrained array type outside the target's index subtype, and a `wait` in a procedure called by a process with a sensitivity list are reported as errors instead of running on. (#379)
- An aggregate whose array elements have different lengths, with an unconstrained element type, is a run-time length error also when every element is a literal; it used to be folded silently into a constant of mixed lengths. (#380)
- A textio READ that fails without a GOOD argument reports an error (for example `integer read failed`) and the simulation goes on, instead of stopping at once. (#381)
- A second force of a signal in the same cycle that takes it back to its current value wakes the processes sensitive to it, as an event. (#382)
- A VHPI plugin's output (`vhpi_printf`, C `printf`) no longer corrupts the debugger protocol under `--dap=stdio`: it goes to standard error. (#389)
- A report in a function with package state called during elaboration is printed once, not again for every later elaboration-time function and once more when the simulation starts. (#390)
- A force through an external name of a child entity's output port now changes the connected net, as a force out does. (#391)
- A resolution function may now read and write shared variables, call protected methods or use files; it used to end the run with an internal error. (#392)
- File objects declared in a protected type body now work: each object of the type has its own file, opened by the methods or by the declaration. (#393)
- Running a suite of testbenches of one library a second or third time no longer costs more than the first run: the runs keep sharing what the library gives them instead of each writing a copy of its own, and the run that prepares the shared library hands its working memory back before it simulates. (#407)
- A testbench whose main process allocates objects without ever waiting no longer keeps every dropped object until the end of the run: its memory use stays bounded. (#409)
- `p'delayed(T)` of an `in` port whose default differs from its actual's initial value now starts at the actual's initial value, the port's value at time 0, instead of the port's default. (#413)
- The native `numeric_std` and `math_real` functions use the INTEGER range of the selected standard revision (64-bit under VHDL-2019), so `to_integer` of wide vectors, large `to_unsigned`/`to_signed` arguments and `floor`/`ceil` of large values work again. (#416)
- Processes with several waits that resume on the same event after running before now run in declaration order, so a testbench whose process reads state a monitor changes on the same clock edge sees the same values, and ends at the same time, in every run. (#417)
- The garbage collector finds the live access values of a running process precisely, also in the middle of a long activation: a value that merely looks like an access value no longer keeps an object alive, and processes suspend with less overhead. (#422)
- `yavs run` and `yavs elab` now report that a source file changed since it was analyzed (`L0034`), instead of an unrelated message that the top level is an unknown configuration.
  A diagnostic whose source file changed since it was analysed, or cannot be read, is now shown without its source snippet (with its code, message, location, labels and a note saying why) instead of stopping with an internal error. (#426)
- A run on a pipe or file that is ended by Ctrl-C or SIGTERM now writes out the reports it made before it ends, instead of losing up to the last 100 ms of output. (#428)
- `--tier=auto` compiles a long compute loop inside one process that never suspends again: it ran interpreted to the end of the run before, and now switches to compiled code soon after it starts. (#432)
- `--wave` records a signal of an enumeration type whose literals are all logic characters (such as `'X' '0' '1' 'Z'`) instead of failing with E0801. (#433)
- A process making many reports in one time step no longer slows down quadratically. (#439)
- The debugger answers a `pause` request before the stop it causes, so a client no longer sees the stopped event ahead of the response and waits for it forever. (#441)
- 'instance_name and 'path_name of an item of a package or package instance name the package (`:work:pkg:f[return integer]:`, or the declaring region and the instance label) instead of the caller's context. (#445)
- A case generate over an array value now takes the alternative whose choice has the same elements, whatever the bounds and direction of the choice. (#447)
- A qualified expression or type conversion of a static value outside its subtype (`natural'(-1)`, `natural(-1.5)`) is analysed with a warning and fails when it runs, instead of passing silently. (#448)
- A constant with a failing initial value in an architecture or entity without processes now stops the run instead of being ignored. (#449)
- 'active of an element of a signal behind an out port is true only for the elements driven in that cycle. (#450)
- 'last_value of a composite signal is the value of the whole signal before its last event; elements that did not change in it keep their current value. (#451)
- A use clause naming a type or subtype also makes the type's user-declared operations of the same declarative region visible. (#452)
- A constant whose initial value reads a signal or an in port now takes the signal's initial value during elaboration instead of stopping the simulation with an error. (#453)
- An aggregate whose elements are arrays of an unconstrained subtype now fails when the elements differ in length instead of silently truncating or padding them. (#455)
- `T'image` and `T'value` can now be used in declarations and generic maps that are evaluated during elaboration, for example `signal t : time := time'value("123 ns")`. (#458)
- `use work.all;` (or another library) in front of a design unit no longer reports every ordinary name as a missing design unit. (#459)
- The `'path_name` and `'instance_name` of a parameter or local of a subprogram in a library package no longer read garbage when the subprogram is called from several entities, and name the package (`:lib:pkg:sub[types]:item`) as the LRM says. (#460)
- A slice of a locally static constant with a locally static range is accepted as a case choice and folded to its value. (#461)
- A protocol checker written as a concurrent procedure call, or declared in an instance after the testbench process, again reports on a clock edge before the testbench process that reads its log on that edge. (#462)
- An integer literal outside the range of INTEGER (integer'image(3000000000), f(2147483648)) now fails when it is evaluated. (#463)
- A case over an array whose value has another length than the choices now fails with a length error instead of falling through to the others branch. (#463)
- A record aggregate whose element does not fit a field with generic-dependent bounds or range now fails when it is evaluated, instead of storing the element unchecked. (#463)
- An external name whose type or array lengths differ from the object it names is an error (E2121) when it is bound. (#463)

(#465)

(#611)

Using the name is now `E1102`. (#628)
- An array index constraint is now checked against the index subtype whatever form its range has and wherever it appears: an attribute range (`variable s : string(x'range);`), the constraint of a record element or of an array's element subtype, and a signal's constraint whose bound comes from a generic (`signal s : string(g to 3);` with `g = 0`). A bound outside the index subtype (`0` for `string`, whose index subtype is `POSITIVE`) fails at the declaration instead of being accepted. (#637)

(#646)

(#673)

## Miscellaneous

- Interpreted code runs faster: each subprogram and process is converted once into a compact form the interpreter dispatches on directly, with common instruction sequences combined; calls and returns are cheaper and frames smaller; constants, array layouts and index arithmetic are computed once per call, per instance or outside the loop; variables, loop bounds and pointers stay in registers; checks that cannot fail are removed; small functions and protected-method calls are inlined (`YAVS_NO_INLINE=1` turns inlining off); and a check builds its message only when it fails. Run-time errors and their messages are unchanged. (#386, #412, #431, #438, #443, #444, #478, #493, #509, #520, #526, #531, #541, #588, #730, #778, #791)
- Logic vectors and the `numeric_std` and `std_logic_1164` operators work on whole words: resolution, copies, comparisons, slices, concatenations, shifts, resizes and reductions (also a user `or_reduce`-style loop), and loops that copy or fill vector elements run as one step. Arrays of 32-bit integer types take less memory. (#199, #415, #518, #519, #520, #534, #697, #778)
- The simulation kernel does less work for clocked designs: every spelling of a clock edge gets the same fast path, a clocked process is not woken on the edge it ignores and stays suspended when nothing it reads changed, clock generators run inside the kernel, assignments of an unchanged value are not queued, a process waiting on the same signals is not registered again each cycle, wide buses are tracked per block of elements, and registers, state machines and records take direct update paths. Results are unchanged. (#385, #420, #440, #521, #632, #667, #720, #734, #767, #795)
- Concurrent assignments that copy or convert a signal, or combine signals with logical operators, comparisons and conditions, run inside the kernel instead of as process code, which speeds up glue logic, multiplexers and address decoders. (#529, #530, #713, #779, #786, #788)
- Processes of parametrised designs switch to code specialised to their instance's generics and package constants, and pure functions called with repeating arguments, user resolution functions and elaboration-time table builders remember their results. (#651, #661, #678, #701, #708, #721)
- Compiled code is smaller and faster: fewer runtime calls, registers kept across blocks, heap and protected objects reached directly, `numeric_std` on short vectors and `math_real.uniform` computed inline, cheaper activations of clocked processes, and `--tier=auto` compiles sooner and only what pays for itself. (#480, #554, #565, #626, #634, #648, #676, #679, #684, #698, #711, #726, #757, #766)
- Analysis, elaboration and start-up are faster: a faster lexer and parser, analysed-unit cache entries decoded only when used, analysis images and package state shared between test cases of a library, faster elaboration-time function calls, unchanged source files no longer read again, and a quicker start of short runs. (#383, #407, #424, #425, #426, #442, #539, #549, #551, #552, #555, #562, #581, #603, #665, #691, #695, #742, #747)
- Memory use is lower: smaller signal, driver and process records, compact storage of large constants of one repeated value, zeroed allocation of large default arrays, and analysis results freed before the simulation starts. (#409, #421, #446)
- Recording variables with `--wave-variables` and coverage runs (`--cov`) cost much less, with unchanged waveforms and coverage databases. (#410, #418, #568, #692, #699, #707)
- Text conversions, `textio` reads and writes including `hread`, and string searches run faster. (#428, #578, #744, #770, #771)
- On Linux with transparent huge pages in `madvise` mode, yavs asks the system for huge pages on its heap at start, so a cold `analyze`, `elab` or `run` of a library testbench uses noticeably less CPU time for a few MiB more memory. `YAVS_HUGE_HEAP=0` switches it off. (#556)
- Release executables no longer carry line tables, so the downloads are much smaller; function names stay. (#600)
- A variable port of a composite of protected types gets a clear error (`E1907`), and an unassociated formal package with a generic map gets a hint that an interface package has no default. (#370, #622)
- The VHDL-1993 `numeric_std` and `numeric_bit` are now derived from the Apache-2.0 IEEE sources. The 1995 IEEE 1076.3 texts, whose notice forbids sale or distribution for profit, are no longer shipped. (#650)
