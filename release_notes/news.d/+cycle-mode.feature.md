Cycle mode, experimental: `yavs run --cycle` runs the clocked and combinational RTL of a design as compiled code evaluated once per clock edge and leaves the testbench in the ordinary event simulation, an opt-in mode for long runs of synchronous designs. It trades detail for speed: values are two-state (a metavalue reaching the region reads as `0`; `--cycle-exact-meta` keeps the exact rules), the reports and assertions of cycle-based processes below the top-level unit are not produced (a warning at the start of the run names those of severity error and failure, which then no longer stop the run), and waves, coverage, VHPI and the debugger cannot be combined with it. A process it cannot take stays in the event simulation; `--cycle-strict` makes each such process an error that says why and how to fix it, and `--cycle-report[=FILE]` shows what would run cycle-based without simulating. Only the logic that a clock edge or a changed input reaches runs, and the compiled region is kept in the compilation cache, so the other test cases of a design compile it once. Its options, error codes and what it accepts may change in a later release; the user guide page "Cycle mode" lists everything it changes.
