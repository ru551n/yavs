Cycle mode keeps metavalues by default now: plain `--cycle` and `--cycle-strict` run with the rules `--cycle-exact-meta` gave in 0.21, so processes that would hide a metavalue from the testbench stay in the event kernel again. The new flag `--two-state` (vunit-yavs sim option `yavs.two_state`) selects the two-state values plain `--cycle` gave in 0.21, and `--cycle-exact-meta` is removed. To get two-state values as plain `--cycle` gave them in 0.21, add `--two-state` to `--cycle` (the design below the testbench now also starts at `0` from time 0 and is two-state in the event kernel, so some results differ slightly from 0.21); drop `--cycle-exact-meta`. `--cycle-strict` only changes which processes must join, not the values. `--two-state` also works without cycle mode, as a diagnostic mode that tells differences caused by values from those caused by scheduling: the design below the testbench then holds only `0` and `1` in the event kernel, metavalues it reads counting as `0`, the metavalue literals it assigns taking `--init-x` (a `'Z'` driven onto a resolved signal stays `'Z'`), and a comparison with a metavalue literal never matching. It is slower than the default today.
