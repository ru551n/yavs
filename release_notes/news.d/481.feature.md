Warm runs start faster: the compilation cache maps its entries into memory instead of reading and copying them, and the generated code of a function is decoded when the function first runs. A short test of a verification library takes up to 15% less CPU time on its warm runs.

A yavs built with the `clift` feature can run compiled code without an LLVM install: `--tier=clift` translates every function before time 0 and `--tier=clift-auto` translates the functions that become hot while the simulation runs; the output is the interpreter's. `--tier=auto3` (both features) translates warm functions with Cranelift and compiles those that stay hot again with LLVM. Calls between small compiled functions run without an interpreter frame and are inlined by Cranelift, which makes call-heavy code several times faster; the output is unchanged. Without LLVM, `--tier=auto` is `--tier=clift-auto`, which decides what to translate and when by the same rules as `--tier=auto` (compile budget, payback, clocked-process bands, measured take-back), and in a build with both generators the code of each calls the other's directly; the output is unchanged.
