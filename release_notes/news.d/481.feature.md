Warm runs start faster: the compilation cache maps its entries into memory instead of reading and copying them, and the generated code of a function is decoded when the function first runs. A short test of a verification library takes up to 15% less CPU time on its warm runs.

A yavs built with the `clift` feature can run compiled code without an LLVM install: `--tier=clift` translates every function before time 0 and `--tier=clift-auto` translates the functions that become hot while the simulation runs; the output is the interpreter's. `--tier=auto3` (both features) translates warm functions with Cranelift and compiles those that stay hot again with LLVM. Calls between small compiled functions run without an interpreter frame and are inlined by Cranelift, which makes call-heavy code several times faster; the output is unchanged. Without LLVM, `--tier=auto` is `--tier=clift-auto`, which decides what to translate and when by the same rules as `--tier=auto` (compile budget, payback, clocked-process bands, measured take-back), and in a build with both generators the code of each calls the other's directly; the output is unchanged. The code Cranelift generates for small functions keeps their registers, frame slots and heap objects in processor registers, so call-heavy testbenches run noticeably faster under `--tier=clift` and the Cranelift levels of `--tier=auto`. Clocked processes of designs with few instances of each are translated when they have run long enough, and translating a hot function no longer translates the library functions it never calls.

Code Cranelift translated is kept in the compilation cache of the work library, so warm runs under `--tier=clift`, `--tier=clift-auto` and `--tier=auto3` link it instead of translating it again (`--no-cache` turns it off).

Under `--tier=clift` and `--tier=clift-auto`, a process without a wait statement keeps running in compiled code, loops that copy or fill logic vector elements run as one operation, and the scalar signal assignments of an activation are handed to the kernel together, as under the LLVM tiers.

`--tier=clift-auto` no longer reserves the layout slots of the LLVM tiers in the frames of processes, which its code does not use.

The code Cranelift generates is shorter where it reaches heap objects, array elements and the arguments of called functions: an object found once stays at hand for the accesses after it, bounds tests are one comparison and jump each, and the queue and pointer-table accessors of verification libraries run noticeably faster under `--tier=clift` and `--tier=clift-auto`.

A yavs built with `clift` and without `llvm` runs `--tier=auto` by default, and `yavs --version` says `compiled tier: cranelift` (`llvm, cranelift` with both).
