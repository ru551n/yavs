Compiled code (`--tier=llvm`, `--tier=auto`) now lives in one block of memory backed by huge pages where the kernel allows it, and its entry dispatch and hot-path branches are laid out to cost fewer instruction fetches. `YAVS_LLVM_ARENA=0` returns to the linker's own placement. The compiled code of large processes is smaller and faster: calls into the runtime are short, blocks are laid out in execution order and the low half of a 64-bit load is a 4-byte load. `YAVS_LLVM_CODEMODEL=large` returns to the previous addressing. A process whose shared code is compiled now moves to its specialised copy under `--tier=auto`, and the compiled copy is smaller and faster than the compiled shared code; field-wise copies of record variables with constant offsets are shorter in compiled code. Large processes compiled under `--tier=auto` call into the runtime far less often: record field offsets come from the layout memo in one call, constants and the objects a process uses are found once instead of at every activation, and scalar assignments of unchanged values no longer reach the kernel. Compiled processes of designs with many instances no longer find their objects again after another process ran: each process keeps its own entries in the compiled tier's object table, so short activations of large compiled processes cost less.
