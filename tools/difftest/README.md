# difftest

Differential tests for yavs. Every `tests/corpus/**/*.vhd` testbench is run on a
candidate simulator, its output is normalised, and the result is compared with a
checked-in reference (`<name>.expected`, generated by the reference simulator). CI needs no the reference simulator.
Python 3 stdlib only.

    tools/difftest/difftest.py                      # the reference simulator against its own .expected (must be green)
    tools/difftest/difftest.py --candidate sim2     # report where the second reference simulator differs
    tools/difftest/difftest.py --candidate yavs     # the real thing, with the default tier of the build
    tools/difftest/difftest.py --candidate yavs-interp  # yavs with `--tier=interp`
    tools/difftest/difftest.py --candidate yavs-llvm  # yavs with `--tier=llvm` (a yavs built with `--features llvm`)
    tools/difftest/difftest.py --candidate yavs-auto  # yavs with `--tier=auto` (the same build)
    tools/difftest/difftest.py --candidate yavs-clift       # `--tier=clift` (a yavs built with `--features clift`)
    tools/difftest/difftest.py --candidate yavs-clift-auto  # `--tier=clift-auto` (the same build)
    tools/difftest/difftest.py --candidate yavs-auto3        # `--tier=auto3` (a yavs built with `--features llvm,clift`)
    tools/difftest/difftest.py --candidate yavs-auto3-eager  # the same with `--tier-heat=0,0,0`
    tools/difftest/difftest.py --candidate yavs-mixed        # LLVM and Cranelift compile half of the functions each and call each other
    YAVS_LLVM_PREKEY_CHECK=1 tools/difftest/difftest.py --candidate yavs-auto-warm  # a second `--tier=auto` run, linking what the first compiled (the check generates it anyway and compares, #785)
    tools/difftest/difftest.py --bless              # regenerate .expected from the reference simulator
    tools/difftest/difftest.py --filter 'report/|env/' --jobs 4 -v

Every simulator run is `timeout 300 systemd-run --user --scope -p MemoryMax=2G bash -c ...`,
at most 8 at a time (`--jobs` is clamped). Work libraries and raw `stdout.txt`/`stderr.txt`
go to `~/.cache/yavs-difftest/run-<pid>/<candidate>/<test>/t<threads>/` (one directory per
process, so parallel runs do not collide; set `DIFFTEST_CACHE` to choose the directory yourself;
old `run-*` directories are not removed). `--no-sandbox` skips
systemd-run for debugging.

## Test header

One line in the first 15 lines of each `.vhd`:

    -- difftest: top=NAME [std=2008|2019|1993|2002] [stop=55ns] [res=ps] [relaxed] [psl] [exit=N] [ref=hand] [ignore=a,b] [spin=N]

- `top`: top-level entity (required). All design units in the file are analysed into one library.
- `std`: default 2008. `stop`: passed as `--stop-time` (needed for free-running clocks).
- `res`: time resolution limit, passed to yavs as `--resolution` (the reference simulators
  ignore it, so use it only with `ref=hand`).
- `relaxed`: analyse, elaborate and run with each candidate's switch that relaxes LRM checks
  (`--relaxed` for yavs and the reference simulator, `-frelaxed` for the second one; `{relaxed}`
  in a template), e.g. for VHDL-93 style shared variables of non-protected types.
- `psl`: yavs gets `--psl` (read `-- psl` comment pragmas); the references read them anyway.
- `exit`: expected process exit status of the reference (default 0). `--bless` refuses to write
  an `.expected` whose exit status differs, so a broken test cannot be blessed by accident.
- `spin`: the bound on the jumps back of a process that never suspends, as `YAVS_SPIN_LIMIT` for yavs (default 10^9, minutes
  in a debug build); lower it so a test that runs into it ends in seconds. The references ignore it.
- `ignore`: fields added to the ignore set for this test only (below), e.g. `ignore=order` for a
  test whose processes report in the same cycle. Say why in a comment.
- PSL: the reference simulator templates read `-- psl` comments (`--psl`, `-fpsl`). A PSL failure
  carries the directive's label or source line instead of a process path, so PSL tests set
  `ignore=path`; the reference simulator's `Label L at file:line` line is dropped like a snippet.
- `ref=hand`: the reference simulator is known to give a wrong result for this test. The `.expected` is edited by
  hand to the LRM result; `--bless` and the reference simulator candidate skip it. Say why in a comment.

Tests must be self-checking (`assert ... severity failure`) and deterministic. Avoid output that
the LRM leaves implementation-defined (`real'image` text outside `scalar/real_image.vhd`,
non-ASCII characters, multi-line reports mixed with other stdout).

## Canonical form

`.expected` is tab separated text, one event per line:

    exit    <status>
    diag    <severity> <time_fs> <delta> <process path | -> <message, \n \t \\ escaped>
    out     <program stdout line>        # textio output
    err     <unclassified stderr line>

`diag` covers report/assert output, `finish`/`stop` calls (severity `finish` or `stop`, message
= status) and fatal runtime errors. Normalisation: severity lowercased; time converted to
femtoseconds from whatever unit the simulator printed; the reference simulator source snippets, "Process/Procedure"
traces and the second reference simulator `instance:`/`from:` lines dropped (the first process trace gives `path`);
the reference simulator's trailing full stop on "Assertion violation." removed and the path of that default assert
message dropped (the reference simulator prints a source snippet instead of the process; yavs keeps the `Process`
line of its CLI format); a fatal runtime error has a `path` only when it happens inside a subprogram, the
reference simulator's trace then names the process (yavs: the note "in process P" of a diagnostic with a "called from here" label); `FINISH called`/`simulation finished`
unified; `sim2:info:` lines dropped. Streams are kept in separate sections (report text goes
to stderr in the reference simulator and stdout in the second reference simulator, so cross-stream order is not compared).

## Ignore set

`--ignore a,b` masks fields on both sides before comparing. Defaults: none for `sim1` and
`yavs` (strict); `delta,path,fatalmsg,order,errexit` for `sim2`.

- `delta`, `path`: the second reference simulator prints neither the delta cycle nor the process path.
- `fatalmsg`: runtime error text and time of `fatal` events (the reference simulators word them differently).
- `order`: sort events that share the same time (and delta) by process path, keeping each
  process's own order (by text when `path` is ignored too); process order inside a cycle is
  unspecified by the LRM. Keep this off for yavs and compare strictly first; a test can opt in
  with `ignore=order` (the reference simulator's order there is an artefact of its event heap, see
  `docs/decisions.md`).
- `errexit`: the reference simulator exits 1 after any `error` severity report, the second reference simulator exits 0. Exit 1 is treated as 0
  when there is no `failure` or `fatal` event.
- `wallclock`: ISO timestamps (`2026-10-23T08:16:29`) in the output are replaced by a placeholder, for tests that print the time of day and would differ when two runs straddle a second. Always on in `external.py` (#567); off elsewhere. Nothing else is masked.
- `time`, `stderr`: extra, off by default.

## Plugging yavs in

`--candidate` takes a reference label (`sim1`, `sim2`: key `difftest` of its section in the untracked `tools/sims.local.conf`, with keys `difftest_relaxed` and `difftest_ignore`), `yavs` or any bash command template. The built-in `yavs`
template (`YAVS` in `difftest.py`) analyzes the file with `yavs analyze` into the work library,
then `yavs run`s the top; `YAVS_BIN` selects the binary (default `yavs` on `PATH`),
`YAVS_RUN_FLAGS` adds flags to `yavs run` (e.g. `--no-collapse-ports` for the uncollapsed design),
`DIFFTEST_CACHE` the output directory (default: unique per process). A failing `yavs elab` (run first, so that `stop(2)` in `yavs run` can exit 2)
is reported as an elaboration failure. `tools/difftest/report.sh` runs the corpus at 1 thread,
4 threads and 4 threads shuffled and writes `tests/corpus/RESULTS.md`; `--json FILE` writes the
raw per-test results it summarises.

Placeholders: `{file}` `{top}` `{std}` (2008) `{std2}` (08) `{stop}` `{stop_flag}`
(`--stop-time=X` or empty) `{relaxed}` (the `relaxed` switch or empty) `{work}` (does not exist yet; sim2 needs `mkdir -p`) `{threads}`
`{shuffle}` (seed) `{shuffle_flag}` (`--shuffle=SEED` or empty) `{shuffle_on}` (`--shuffle` or empty). The template runs in a fresh
working directory, so textio files land there. Exit codes 97 (analysis) and 98 (elaboration) are
reserved for the harness: make a multi-step template `|| exit 97` / `|| exit 98` as `sim1` does, so
that a compile failure is reported as such. yavs must print reports in the reference simulator's format
(`** Note: 5ns+0: text` plus an optional indented `Process ...` line) or the parser in
`normalise()` gets a branch for its format; the canonical form is what matters. yavs runtime
errors are diagnostics on stderr (`error[E3xxx]` with a `= note: at T, delta D`
line); `yavs_fatal()` turns each into a `fatal` event.

Thread-count invariance: if the template contains `{threads}`, `--threads 4` runs every test with
1 and 4 threads and requires both outputs to be identical (unmasked) as well as equal to
`.expected`. `--shuffle SEED` is passed through for yavs's randomised evaluation order.

## Corpus

Grouped by directory: `scalar arith process delta sigassign postponed report env resolution
force composite access protected textio generics hierarchy reflect implicit ieee psl`. Written from scratch (no
the reference simulators test files). A few use `std=2019`. See `git log` and the file list (`--list`).

## External regression tests (`external.py`)

`external.py` runs the reference simulators' own self-checking regression tests (pass or fail
through assertions and the exit status) in place from the corpus cache (`tools/fetch-corpus.sh`,
`YAVS_CORPUS`, default `~/.cache/rsim-corpus`); they are never copied into the repository. Suites:
`sim1` (the test list of its regression directory: one VHDL file per test, options such as the
standard, `fail`, `gold`, `stop=`, generics) and `sim2` (the per-directory `testsuite.sh` scripts
whose lines are only `analyze`, `elab_simulate`, `elab_simulate_failure`, `clean` and the standard
flags; anything else, such as `if`, loops or tool options, is skipped). Tests of other languages,
VHPI, coverage, waves dumps compared to files, Tcl and shell scripts are skipped. yavs runs tests
written for an earlier standard as 2008 with `--relaxed` (VHDL-93 shared variables).

    tools/difftest/external.py sim1                      # yavs against the reference simulator, classified
    tools/difftest/external.py sim2 --filter 'issue1'   # a subset
    tools/difftest/external.py sim1 --threads 4          # also 1 against 4 threads
    tools/difftest/external.py sim1 --oracle --check tools/difftest/external-sim1.pass   # CI

Default mode runs each test on the reference simulator and on yavs (one simulator at a time per
test, `--jobs` tests at once, default 2) and puts it in one class:

- `pass`: the normalised output (`normalise()`, yavs analysis warnings dropped) is equal per run;
  `order`, `fatalmsg`, `delta-path`: equal only with that much ignored (same-cycle order; the
  wording, process path and exit status of a run-time error when both fail); `output`: other
  differences; `outcome`: one passes a run the other fails;
- `early`: yavs rejects the design when it analyses or elaborates it, with an error the LRM
  states (`EARLY_OK` in `external.py`), where the reference simulator fails the run and the
  test expects a failing run; it meets the suite's verdict and counts as passing;
- `analysis`, `elab`, `timeout`, `threads`: yavs fails there or differs between thread counts;
- `ref-bad`: the reference simulator does not meet the test's own expectation here (environment,
  version), so the test is not compared; `skip`: not modelled by the harness.

`--oracle` needs no reference simulator: a test passes when every run passes or fails as the
suite expects (its exit status; the gold lines of the first suite are checked on the reference
only, they carry its time format). A run of the
second suite that exits 1 after `error` reports only counts as passing (the `errexit` rule).
`external-sim1.pass` and `external-sim2.pass` list the tests that pass both ways; CI (`corpus`
job) runs `--oracle --check` on them, so a regression fails the build. Regenerate them with
`--oracle --write-pass FILE` on a release build (the suite's own verdict; a differential run shows which of the tests also match the reference output, a few do not).
