# difftest

Differential tests for yavs. Every `tests/corpus/**/*.vhd` testbench is run on a
candidate simulator, its output is normalised, and the result is compared with a
checked-in reference (`<name>.expected`, generated by the reference simulator). CI needs no the reference simulator.
Python 3 stdlib only.

    tools/difftest/difftest.py                      # the reference simulator against its own .expected (must be green)
    tools/difftest/difftest.py --candidate sim2     # report where the second reference simulator differs
    tools/difftest/difftest.py --candidate yavs     # the real thing, with the default tier of the build
    tools/difftest/difftest.py --candidate yavs-interp  # yavs with `--tier=interp`
    tools/difftest/difftest.py --candidate yavs-auto  # yavs with `--tier=auto` (the same build)
    tools/difftest/difftest.py --candidate yavs-clift       # `--tier=clift` (a yavs built with `--features clift`)
    tools/difftest/difftest.py --candidate yavs-clift-auto  # `--tier=clift-auto` (the same build)
    tools/difftest/difftest.py --candidate yavs-clift-check # every process a copy, every skip of a drive in generated code or against a record image checked (the same build)
    tools/difftest/difftest.py --candidate yavs-clift-count1 # the count rule of --tier=auto at a count of 1: every function asked for at its first call, the run waiting for the compile (the same build)
    tools/difftest/difftest.py --candidate yavs-clift-cheap   # `--tier=clift` with every block lowered as code that never ran (the interpreter runs it, a native frame leaves); `yavs-clift-cheapalt` every second block (the same build)
    YAVS_CLIFT_PREKEY_CHECK=1 tools/difftest/difftest.py --candidate yavs-auto-warm  # a second `elab` and `--tier=auto` run, both compared, linking what the first compiled (the check generates it anyway and compares, #785; on by default in a debug `clift` build)
    tools/difftest/difftest.py --bless              # regenerate .expected from the reference simulator
    tools/difftest/difftest.py --filter 'report/|env/' --jobs 4 -v
    tools/difftest/difftest.py --exclude '^composite/aggregate_fill'  # a gc-stress build: 70001 allocations, over 300 s there (#852)

Every simulator run is `timeout 300 systemd-run --user --scope -p MemoryMax=2G bash -c ...`,
at most 8 at a time (`--jobs` is clamped). Work libraries and raw `stdout.txt`/`stderr.txt`
go to `~/.cache/yavs-difftest/run-<pid>/<candidate>/<test>/t<threads>/` (one directory per
process, so parallel runs do not collide; set `DIFFTEST_CACHE` to choose the directory yourself).
A passing case's directory is removed at once and the whole run directory when the run ends
(also on interrupt or SIGTERM); only failing cases stay, and the path is printed on stderr.
A run killed with SIGKILL leaves its directory, and old `run-*` directories are never swept.
`tools/difftest/test_cleanup.py` checks this. `--no-sandbox` skips
systemd-run for debugging, and is what runs on Windows (from Git Bash, whose `timeout` and `bash` it finds through `PATH`); the release workflow runs the corpus so on the binary of each archive.

## Test header

One line in the first 15 lines of each `.vhd`:

    -- difftest: top=NAME [std=2008|2019|1993|2002] [stop=55ns] [res=ps] [relaxed] [psl] [exit=N] [ref=hand] [ignore=a,b] [spin=N]

- `top`: top-level entity (required). All design units in the file are analysed into one library.
- `std`: default 2008. `stop`: passed as `--stop-time` (needed for free-running clocks).
- `res`: time resolution limit, passed to yavs as `--resolution` (the reference simulators
  ignore it, so use it only with `ref=hand`).
- `relaxed`: analyse, elaborate and run with each candidate's switch that relaxes LRM checks
  (`--relaxed` for yavs and the reference simulator, `-frelaxed` for the second one; `{relaxed}`
  in a template), e.g. for VHDL-93 style shared variables of non-protected types.
- `psl`: yavs gets `--psl` (read `-- psl` comment pragmas); the references read them anyway.
- `exit`: expected process exit status of the reference (default 0). `--bless` refuses to write
  an `.expected` whose exit status differs, so a broken test cannot be blessed by accident.
- `spin`: the bound on the jumps back of a process that never suspends, as `YAVS_SPIN_LIMIT` for yavs (default 10^9, minutes
  in a debug build); lower it so a test that runs into it ends in seconds. The references ignore it.
- `ignore`: fields added to the ignore set for this test only (below), e.g. `ignore=order` for a
  test whose processes report in the same cycle. Say why in a comment.
- PSL: the reference simulator templates read `-- psl` comments (`--psl`, `-fpsl`). A PSL failure
  carries the directive's label or source line instead of a process path, so PSL tests set
  `ignore=path`; the reference simulator's `Label L at file:line` line is dropped like a snippet.
- `ref=hand`: the reference simulator is known to give a wrong result for this test. The `.expected` is edited by
  hand to the LRM result; `--bless` and the reference simulator candidate skip it. Say why in a comment.

Tests must be self-checking (`assert ... severity failure`) and deterministic. Avoid output that
the LRM leaves implementation-defined (`real'image` text outside `scalar/real_image.vhd`,
non-ASCII characters, multi-line reports mixed with other stdout).

## Canonical form

`.expected` is tab separated text, one event per line:

    exit    <status>
    diag    <severity> <time_fs> <delta> <process path | -> <message, \n \t \\ escaped>
    out     <program stdout line>        # textio output
    err     <unclassified stderr line>

`diag` covers report/assert output, `finish`/`stop` calls (severity `finish` or `stop`, message
= status) and fatal runtime errors. Normalisation: severity lowercased; time converted to
femtoseconds from whatever unit the simulator printed; the reference simulator source snippets, its `Type T at file:line` line, "Process/Procedure"
traces and the second reference simulator `instance:`/`from:` lines dropped (the first process trace gives `path`);
a yavs process path turned into the reference form (`tb.g(1).p` is `:tb:g(1):p`, `lrm_path`; message text untouched);
the reference simulator's trailing full stop on "Assertion violation." removed and the path of that default assert
message dropped (the reference simulator prints a source snippet instead of the process; yavs keeps the `Process`
line of its CLI format); a fatal runtime error has a `path` only when it happens inside a subprogram, the
reference simulator's trace then names the process (yavs: the note "in process P" of a diagnostic with a "called from here" label); `FINISH called`/`simulation finished`
unified; `sim2:info:` lines dropped. Streams are kept in separate sections (report text goes
to stderr in the reference simulator and stdout in the second reference simulator, so cross-stream order is not compared).

## Ignore set

`--ignore a,b` masks fields on both sides before comparing. Defaults: none for `sim1` and
`yavs` (strict); `delta,path,fatalmsg,order,errexit` for `sim2`.

- `delta`, `path`: the second reference simulator prints neither the delta cycle nor the process path.
- `fatalmsg`: runtime error text and time of `fatal` events (the reference simulators word them differently).
- `order`: sort events that share the same time (and delta) by process path, keeping each
  process's own order (by text when `path` is ignored too); process order inside a cycle is
  unspecified by the LRM. Keep this off for yavs and compare strictly first; a test can opt in
  with `ignore=order` (the reference simulator's order there is an artefact of its event heap, see
  `docs/decisions.md`).
- `errexit`: the reference simulator exits 1 after any `error` severity report, the second reference simulator exits 0. Exit 1 is treated as 0
  when there is no `failure` or `fatal` event.
- `wallclock`: ISO timestamps (`2026-10-23T08:16:29`) in the output are replaced by a placeholder, for tests that print the time of day and would differ when two runs straddle a second. Always on in `external.py` (#567); off elsewhere. Nothing else is masked.
- `time`, `stderr`: extra, off by default.

## Cycle mode gate

`cyclegate.py` runs the corpus, the designs of `crates/yavs/tests/cycle` and the bench designs of
`tools/bench/designs` twice with the same binary (`YAVS_BIN`, flags of `YAVS_RUN_FLAGS` for both), normal and
`--cycle`, and compares exit status and console output in the canonical form (the summary line of cycle mode is
taken out of stderr). A third run with `--cycle-report` (analysis only) gives the members of each test and which
of them hold asserts and reports. Buckets: identical; documented (only the delta of report stamps, reports and asserts of member
processes that cycle mode does not evaluate, or delta cycles a monitor no longer sees, shown by the lines
themselves; a vanished report counts as a member's when its process path is one of a member with dropped asserts,
or `-` for an unlabelled process while such a member exists); known (differs, and `cyclegate.expected` lists the
test with the checksum of its diff and the reviewed cause: a changed diff is not known any more); differs
otherwise (a wrong result in cycle mode: exit status 1, and the line to paste into the list after a review);
refused (`E41xx`); skipped (the normal mode does not run it). A lost failure of a member ends the normal run
early: such a test is reported as not compared after that point. Every test shows how many processes joined
the region, and the summary counts the tests with at least one member. `--only corpus|cycle|bench`, `--filter`,
`--jobs`, `-v`, `--json FILE`, `--selftest`. `--warm` runs every cycle run first in a library of its own, then the compared run on a copy of
that library, with the region's machine code from the compilation cache, compares the two (a difference fails the test)
and counts the tests that ran with region code in the cache; with
`YAVS_CYCLE_CACHE_CHECK=1` every hit is made again (the analysis, the region and each function's code) and the
run stops when it differs:

    YAVS_BIN=target/release/yavs python3 -I tools/difftest/cyclegate.py [--warm]

The gate has no large design. `cyclebig.py` is its companion for the big ones, required before every push that
changes which processes join the region: it runs realbench worlds (made by
`tools/realbench/run.py --prepare` under `YAVS_REALBENCH_CACHE`, named `<test>-<label>`, `--label` default `yavs`)
normal and `--cycle` with one binary to one stop time (the table `GATE` in the script), each mode in a copy of the
world, and compares exit status, the console (standard output without report records) and every text file the run
wrote in its working directory (on NEORV32 the CPU's instruction traces and the UART logs). A `?` in the normal
mode's file matches any character (a metavalue digit, read as 0 in cycle mode). Reports are counted, not compared:
NEORV32 prints about 80 000 library metavalue warnings and configuration notes from processes that join the region,
and cycle mode evaluates none of them. The region's member count must be the one `GATE` holds, and the normal
console must hold the test's `expect` lines. A run that compared nothing (no member, or no output) fails, and so
does a test without a world (the command that makes it is printed). Default tests `neorv32_dual_full` and
`microwatt_coremark_short`, both to completion in about a minute (6 s and 56 s on 2026-11-16): Microwatt runs to
1369 us in both modes, past "Execution completed."; the normal mode ends with its RTL's `end of test` failure (exit
status 1), which cycle mode drops by decision (exit status 0), and `GATE` expects each. `--selftest` checks the
comparison:

    YAVS_REALBENCH_CACHE=<cache> python3 -I tools/difftest/cyclebig.py target/release/yavs

`seeddiff.py` is the safety net of the run-count rule, which console equality is too weak for (Microwatt's
`dcache_request` gave a stale `req_nc` from 0.3 us on, and the console lost one line at the very end). It asks
`--cycle-report` with `YAVS_CYCLE_SEEDS` for the signals driven by the processes outside the region whose result
may depend on the delta cycles their inputs change in, runs both modes with `YAVS_TRACE` (each listed signal at
the end of every time step where it changed), and compares the traces time step by time step. A difference only
where the normal mode holds a metavalue is counted apart; any other fails (exit status 1). `--seeds LIST` traces the list of another binary
(the one before a change that lets processes join). With `YAVS_CYCLE_RUNCOUNT=off` it finds the Microwatt
divergence at 0.345 us:

    python3 -I tools/difftest/seeddiff.py --bin target/release/yavs --cwd WORLD -- run --work=work:WORLD/work ... top

A recorded command file extends the gate to runs it does not contain, the benches of a test runner.
`cyclereplay.py` takes recorded `yavs run` command lines (one run per entry, with its working
directory) and runs each normal and with `--cycle` with one binary (`--bin` or `YAVS_BIN`), each mode in its own
copy of the run's output directory (its path is replaced in every argument, so the files a test
writes land in the copy). The libraries the runs name (`--work=` and `--map=` outside the output directory) are
copied once per replay, without their `yavs-cache/`, and the runs use the copies: the caches a run writes land
there, so a recorded or shared library is never written. A `--std-cache=DIR` of a run is replaced by the replay's own. It compares the exit status, the simulation end time (the times of the `stop` and
`finish` events, else the last report), the console in the canonical form and every file the run wrote
(a `?` in the normal mode's file matches any character). From the console it takes out the delta of report
stamps, the cycle summary line and the reports and asserts of cycle-based processes, found through a
`--cycle-report` run as `cyclegate.py` does; a `stop` or `finish` event is never taken out. The buckets are
identical, documented (a lost failure of a cycle-based process may end the normal run, the rest is then not
compared), differs (any other difference, with the first differing line and both end times; exit status 1),
timeout (the cycle run does not finish in `--timeout` while the normal one does: not compared, listed) and
skipped (the normal run does not finish). Each test shows `[members/processes in the region]` and the summary
counts the tests with a member, so a pass is not vacuous. `--jobs` (default 2), `--filter`, `--budget SECONDS` (start no further test after that), `--mask REGEX` (text that differs between runs by itself, such as the name of a temporary directory a test makes), `--env K=V`,
`--subst OLD=NEW`, `--prefix` (a command before every run, such as `tools/claim core --`), `--timeout`, `--memory`,
`--json FILE`, `-v`, `--selftest`. A command file is JSON lines, `{"name", "cwd", "dir", "argv", "env"}`;
`--record OUT_DIR...` writes it from the output directories of a VUnit run with yavs (`test_output/*/*/args.rsp`,
the response file of each run), run in the directory the test runner ran in (`--cwd`):

    python3 -I tools/difftest/cyclereplay.py --record <vunit out dir> --env K=V > cmds.jsonl
    YAVS_BIN=target/release/yavs python3 -I tools/difftest/cyclereplay.py cmds.jsonl --jobs 2 -v

A test runner that has run the tests already needs no second run to record them: any simulator wrapper that
exits at `run` still leaves each test's response file. The files are copied before each run; files written
outside the output directory, or relative to the working directory, are not isolated or compared.

## Cycle mode fuzzer

`cyclefuzz.py` generates random synchronous designs in the subset of cycle mode, each with a testbench
that drives seeded random stimulus and prints every output of the design twice a clock, between clock
edges, and runs each design normal and `--cycle` with one binary (`--bin`, default `YAVS_BIN`). A design
is deterministic from its seed (and the version of the generator, whose hash each JSON line records).

    python3 -I tools/difftest/cyclefuzz.py gen 7                      # the design of seed 7
    python3 -I tools/difftest/cyclefuzz.py run --seeds 0:400 --warm --checks 5 --bin target/release/yavs
    python3 -I tools/difftest/cyclefuzz.py shrink 7 --bin ...          # a failing seed reduced to a small reproducer
    python3 -I tools/difftest/cyclefuzz.py shrink 7 --reason "did not count" --bin ...  # reduced while the report holds the text
    python3 -I tools/difftest/cyclefuzz.py check DIR --bin ...         # a reproducer `DIR/d.vhd` edited by hand

The designs hold what cycle mode must give the normal result for: `std_ulogic`, vectors, `unsigned`,
`signed`, integer subtypes, enumerations, records and arrays of all of these (constants, generics, both
directions, bounds not at 0, widths around 1, 63, 64, 65 and 128), `numeric_std` arithmetic, shifts,
`resize`, comparisons, slices, concatenations, aggregates (`others`, named and range choices), `if`,
`case`, `for` loops with `exit` and `next`, package functions and procedures, clocked processes (both
edges, both edge forms, `wait until`, `q <= d when rising_edge(c)`, synchronous and asynchronous resets,
enables, memories written at run-time indices), combinational processes, concurrent assignments of
all three kinds, `for generate`, hierarchy with generics, expression actuals and partial associations
of ports, two clocks (made by two concurrent assignments or by one process), and processes cycle mode
must leave in the event kernel (latches, variables keeping state, waits in time, and a process that
waits on a register and reads logic following it: the run-count class). They hold no asserts or reports in the region, every signal and variable is initialised and
the inputs are `'0'` and `'1'`, so any difference is a bug; the metavalue warnings of time 0 (an
expression actual is `'U'` until its equivalent process runs) are not compared. The generator also
avoids the `numeric_std` "vector truncated" warnings: cycle mode gives them at other deltas or, for a
call folded during elaboration, once at time 0.

Each seed runs, per tier of `--tiers` (default `interp,clift`), the normal mode and `--cycle` cold (no
region code in the cache); `--warm` runs it again with the region from the cache (a cold run that left
no code in the cache fails); `--checks N` runs every Nth seed once more with `YAVS_CYCLE_CHECKS=all`,
`YAVS_CYCLE_SKIP_CHECK=1`, `YAVS_CYCLE_IMPORT_CHECK=1` and `YAVS_CYCLE_GUARD=all`. Compared: exit status,
standard output and standard error without the summary line. A `--cycle-report` run gives the members; the
summary prints how many of the design's processes joined the region and the most common reasons of the
others, so a pass is not vacuous (a seed with no member is `vacuous`). The exit status is 1 when a
seed differs or does not compare (analysis or elaboration fails, the normal run fails or times out:
a valid design, so a bug of the generator or of yavs) and when fewer than `--min-share` percent
(default 60) of the designs' processes joined the region. Simulations run under
`systemd-run --user --scope -p MemoryMax=2G`, at most 2 at a time, and wait while less than 20 GB of
memory is available. Passing seeds' directories are removed (`--keep` keeps them); `--json FILE` appends
a line per seed. `shrink` deletes processes, statements, signals, ports, constants and subprograms,
replaces expressions by a constant or an operand, halves the widths of vectors and shortens the run,
keeping each step that still differs in the same run (or, with `--reason`, still shows the reason);
`shrink` regenerates the seed from the current generator, so shrink a seed with the version that found it.

## Plugging yavs in

`--candidate` takes a reference label (`sim1`, `sim2`: key `difftest` of its section in the untracked `tools/sims.local.conf`, with keys `difftest_relaxed` and `difftest_ignore`), `yavs` or any bash command template. The built-in `yavs`
template (`YAVS` in `difftest.py`) analyzes the file with `yavs analyze` into the work library,
then `yavs run`s the top; `YAVS_BIN` selects the binary (default `yavs` on `PATH`),
`YAVS_RUN_FLAGS` adds flags to `yavs run` (e.g. `--no-collapse-ports` for the uncollapsed design),
`DIFFTEST_CACHE` the output directory (default: unique per process). A failing `yavs elab` (run first, so that `stop(2)` in `yavs run` can exit 2)
is reported as an elaboration failure. `tools/difftest/report.sh` runs the corpus at 1 thread,
4 threads and 4 threads shuffled and writes `tests/corpus/RESULTS.md`; `--json FILE` writes the
raw per-test results it summarises.

Placeholders: `{file}` `{top}` `{std}` (2008) `{std2}` (08) `{stop}` `{stop_flag}`
(`--stop-time=X` or empty) `{relaxed}` (the `relaxed` switch or empty) `{work}` (does not exist yet; sim2 needs `mkdir -p`) `{threads}`
`{shuffle}` (seed) `{shuffle_flag}` (`--shuffle=SEED` or empty) `{shuffle_on}` (`--shuffle` or empty). The template runs in a fresh
working directory, so textio files land there. Exit codes 97 (analysis) and 98 (elaboration) are
reserved for the harness: make a multi-step template `|| exit 97` / `|| exit 98` as `sim1` does, so
that a compile failure is reported as such. yavs must print reports in the reference simulator's format
(`** Note: 5ns+0: text` plus an optional indented `Process ...` line) or the parser in
`normalise()` gets a branch for its format; the canonical form is what matters. yavs runtime
errors are diagnostics on stderr (`error[E3xxx]` with a `= note: at T, delta D`
line); `yavs_fatal()` turns each into a `fatal` event.

Thread-count invariance: if the template contains `{threads}`, `--threads 4` runs every test with
1 and 4 threads and requires both outputs to be identical (unmasked) as well as equal to
`.expected`. `--shuffle SEED` is passed through for yavs's randomised evaluation order.

## Corpus

Grouped by directory: `scalar arith process delta sigassign postponed report env resolution
force composite access protected textio generics hierarchy reflect implicit ieee psl`. Written from scratch (no
the reference simulators test files). A few use `std=2019`. See `git log` and the file list (`--list`).

## External regression tests (`external.py`)

`external.py` runs the reference simulators' own self-checking regression tests (pass or fail
through assertions and the exit status) in place from the corpus cache (`tools/fetch-corpus.sh`,
`YAVS_CORPUS`, default `~/.cache/rsim-corpus`); they are never copied into the repository. Suites:
`sim1` (the test list of its regression directory: one VHDL file per test, options such as the
standard, `fail`, `gold`, `stop=`, generics) and `sim2` (the per-directory `testsuite.sh` scripts
whose lines are only `analyze`, `elab_simulate`, `elab_simulate_failure`, `clean` and the standard
flags; anything else, such as `if`, loops or tool options, is skipped). Tests of other languages,
VHPI, coverage, waves dumps compared to files, Tcl and shell scripts are skipped. yavs runs tests
written for an earlier standard as 2008 with `--relaxed` (VHDL-93 shared variables).

    tools/difftest/external.py sim1                      # yavs against the reference simulator, classified
    tools/difftest/external.py sim2 --filter 'issue1'   # a subset
    tools/difftest/external.py sim1 --threads 4          # also 1 against 4 threads
    tools/difftest/external.py sim1 --oracle --check tools/difftest/external-sim1.pass   # CI

Default mode runs each test on the reference simulator and on yavs (one simulator at a time per
test, `--jobs` tests at once, default 2) and puts it in one class:

- `pass`: the normalised output (`normalise()`, yavs analysis warnings dropped) is equal per run;
  `order`, `fatalmsg`, `delta-path`: equal only with that much ignored (same-cycle order; the
  wording, process path and exit status of a run-time error when both fail); `output`: other
  differences; `outcome`: one passes a run the other fails;
- `early`: yavs rejects the design when it analyses or elaborates it, with an error the LRM
  states (`EARLY_OK` in `external.py`), where the reference simulator fails the run and the
  test expects a failing run; it meets the suite's verdict and counts as passing;
- `analysis`, `elab`, `timeout`, `threads`: yavs fails there or differs between thread counts;
- `ref-bad`: the reference simulator does not meet the test's own expectation here (environment,
  version), so the test is not compared; `skip`: not modelled by the harness.

`--oracle` needs no reference simulator: a test passes when every run passes or fails as the
suite expects (its exit status; the gold lines of the first suite are checked on the reference
only, they carry its time format). A run of the
second suite that exits 1 after `error` reports only counts as passing (the `errexit` rule).
`external-sim1.pass` and `external-sim2.pass` list the tests that pass both ways; CI (`corpus`
job) runs `--oracle --check` on them, so a regression fails the build. Regenerate them with
`--oracle --write-pass FILE` on a release build (the suite's own verdict; a differential run shows which of the tests also match the reference output, a few do not).
