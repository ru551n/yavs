# AGENTS.md: tools/verilog/ (Verilog test tools)

Read the root `AGENTS.md` and `tools/AGENTS.md` first. This file is for an agent about to change or run the tools that check
`yavs analyze` on Verilog (plan: issue #776, milestone M0). Python, stdlib only, run with `python3 -I`.

## 1. Purpose and boundaries

- `fixtures.py`: runs the hand-written fixtures of `tests/verilog/ci` against the manifest `fixtures.expected`; `--static` checks
  manifest against files with no analyzer.
- `corpus.py vendor|cells`: the analysis corpus gate. `vendor` reads the FPGA vendor's 2026.1 install in place (local only: it
  skips with a notice when the install is absent, decision D3 of #776); `cells` reads the yosys techlibs simulation models that
  `tools/fetch-corpus.sh` puts in the corpus cache (ISC, CI-visible once the analyzer exists).
- `vendor.expected`, `cells.expected`: the manifests, generated by `corpus.py ... gen` and then blessed from a real run. Paths
  and outcomes only: vendor sources are never copied or committed (root rule 7).
- `fake_yavs.py`, `selftest.py`: a stand-in for the analyzer's preprocessor-stage diagnostics (E4001 to E4005, W4006) and a test
  of the tools against it, including deliberately wrong runs that must fail. Delete `fake_yavs.py` and the stand-in half of
  `selftest.py` when `yavs analyze *.v` exists; keep the selftest of the skip and failure paths.
- `vcommon.py`: finding `yavs`, one `analyze` call, parsing `--message-format json` lines.
- Not here: the VHDL analysis corpora (`tools/corpus`), simulation tests, the analyzer itself (`crates/yavs-verilog`).

## 2. Map

| Command | What |
|---|---|
| `corpus.py vendor list` | Count and classify the install, print findings (include fragments, unresolved includes, macros defined nowhere in sight, SystemVerilog syntax in `.v`, plaintext files that include an encrypted one); writes nothing |
| `corpus.py vendor gen` | Write `vendor.expected` from the classification (what the plan expects) |
| `corpus.py vendor [check]` | Run `yavs analyze` and compare every file with the manifest; exit 0 as expected, 1 differences, 2 usage |
| `corpus.py vendor bless` | Write the manifest from a complete run, then read the diff |
| `fixtures.py [--static]` | The CI fixtures |
| `selftest.py` | The tools against `fake_yavs.py`, no install needed |

Categories of `vendor`: `unisims`, `retarget`, `unimacro`, `unifast`, `glbl` (each file in both views: no define, and `-D XIL_TIMING`;
one `yavs analyze` call per library and view), `unisims-sv` (E4002), `ip-plain`, `ip-includes-encrypted` and `ip-encrypted`
(one call per `ip/**/*.v`), `protected` (`*.vp` in `verilog/src`, `secureip` and `ip`). Libraries: `unisims_ver` (unisims and
retarget), `unimacro_ver`, `unifast_ver` (separate: five module names are in both unisims and unifast), `work` (glbl).

## 3. Design decisions that bind this module

| Decision | Why | Source |
|---|---|---|
| The install is found by `--root`, `$YAVS_VENDOR_DATA`, then `~/Xilinx`, `/opt/Xilinx`, `/tools/Xilinx` under `2026.1/data`, and must hold `verilog/src/glbl.v` there; the first hit wins, two installs need `--root` | The install holds other `glbl.v` copies (IP testbenches), so no search by file name; one version only | #776 D3 |
| Outcome per file in the manifest, not per category | The plan expects SystemVerilog syntax in some `.v` IP files (E4003) and encrypted files (E4001); a category cannot say so | #776 section 1.2, 5 |
| Outcome is `PASS` or the sorted error codes; `xN` only on E4001 | "Exactly one E4001 per encrypted file" is the M0 claim; other counts depend on error recovery | #776 M0 |
| Warnings are counted, not compared | Warning codes are not all registered yet | |
| Include directories are part of the manifest, per file: the file's own directory, plus the directory of every plain-name include found by name elsewhere in `ip/` (transitively, nearest first) | The gate must not depend on how the analyzer resolves relative include paths; paths such as `../x.vh` that resolve nowhere are listed as unresolved, not guessed | |
| No `-I` for `unisims_dr`; the `*_dr.v` includes sit under `` `ifdef XIL_DR `` | A correct preprocessor never opens them, so the gate catches one that does | plan section 1.2 |
| A call over a library stops at its first failing file (as `yavs analyze` does), so a failed call is repeated file by file; a session-only failure is a DIFF | Same as `tools/corpus/run.py` | `tools/corpus/AGENTS.md` |
| In a one-file call every diagnostic belongs to that file, including those in files it includes | The including file fails because of its include | |
| `*.svp`, IP `*.sv`, `*.svh`, xeclib, `unisims_dr`, `hybrid` and the other `verilog/src` directories are counted, not gated | Out of M0's list; D1 (XPM and SystemVerilog) is open | #776 D1 |
| `cells` = the 36 files `techlibs/**/*sim*.v` of yosys at the commit pinned in `fetch-corpus.sh` | ISC; the quicklogic `qlf_k6n10f` files carry an Apache-2.0 header (F4PGA); `bram_types_sim.v` is generated at build time and not in the checkout | |
| `fake_yavs.py` is a test double, not a parser | It lets the tools be tested, and fail on purpose, before the analyzer exists | |

## 4. Pitfalls

- Predictions in a generated manifest are textual (regex, includes followed without evaluating `` `ifdef ``): `E4003` marks
  unambiguous SystemVerilog syntax (`typedef`, `enum`, `struct`, `package`, `always_ff`, `int x`, ...), `E4001` an envelope
  anywhere in the file or in a file it includes. `bless` after the first real run replaces them; review the diff per category.
- The vendor `.vp` files come in other tools' forms. Six use `//pragma protect begin_protected` inside a comment, which the
  plan's detector (directive forms only) does not catch; they are expected to give E4001 here, and the gate shows the gap.
- A change of the install version changes the file lists: `check` reports a stale manifest (`gen`, review the diff, commit).
- Scratch space is a `tempfile` directory; nothing is written into the install or the repository.
- The gate runs each call under `timeout 300 systemd-run --user --scope -q -p MemoryMax=2G` (root rule 15); `--no-wrap` drops
  that. `-j` defaults to 4 parallel calls.

## 5. Commands

```sh
python3 -I tools/verilog/selftest.py
python3 -I tools/verilog/corpus.py vendor list
python3 -I tools/verilog/corpus.py vendor gen                      # then review git diff
python3 -I tools/verilog/corpus.py vendor --yavs target/release/yavs -j 4
python3 -I tools/verilog/corpus.py vendor bless --yavs target/release/yavs
tools/fetch-corpus.sh && python3 -I tools/verilog/corpus.py cells --yavs target/release/yavs
```
